# [2] 공통 레이아웃 및 내비게이션 기획 명세서

본 문서는 와이앤아처 통합 Works 플랫폼의 최상위 화면 프레임인 공통 쉘(AppShell), 상단바(Topbar), 좌측 사이드바(Sidebar)의 UI/UX 구성 요소 및 사용자의 이동 흐름을 통제하는 내비게이션 규칙을 정의합니다.

---

## 1. 레이아웃 그리드 및 프레임 개요
플랫폼의 전체 레이아웃은 사용자가 데스크톱, 태블릿, 모바일 등 다양한 기기에서 일관된 경험을 유지할 수 있도록 3분할(사이드바 + 상단바 + 본문 콘텐츠) 구조를 기본으로 설계하며, 화면 공간을 좁게 고정하지 않고 넓게 활용할 수 있도록 유연한 풀-와이드(Full-Width) 컨테이너 및 1열/2열 가변 그리드 시스템을 적용합니다.

```
+---------------------------------------------------------+
| [CI LOGO] | 상단바 (높이: 64px)                          |
|           | [현재 위치]  [통합 검색]     [AI][캘린더][알림] |
+-----------+---------------------------------------------+
| 좌측      | 본문 콘텐츠 영역                             |
| 사이드바  | (1열형: Full-Width 테이블/차트 화면)          |
|           | (2열형: 좌측 기본 카드 + 우측 연관 패널)     |
| (240px)   |                                             |
|           |                                             |
+-----------+---------------------------------------------+
```

* **좌측 사이드바 (Sidebar)**: 데스크톱 화면에서 가로 `240px` 고정 폭으로 화면 좌측에 고정되며, 현재 워크스페이스의 세부 메뉴 목록을 표시합니다.
* **상단바 (Topbar)**: 세로 `64px` 높이로 상단에 고정되며, 사이드바 접기 토글·현재 위치·통합 검색과 전역 슬라이드오버 진입점(AI·전사 캘린더·알림)을 배치합니다. 워크스페이스 전환은 사이드바가, 계정 조작은 OFFICE 환영 카드가 담당합니다(§2.2).
* **본문 콘텐츠 영역 (Content)**: 상단바와 사이드바를 제외한 나머지 화면 영역으로, 좌우 여백을 균형 있게 주는 동시에 데이터 밀도가 높은 화면에서는 넓게 쓰며 컨텍스트에 따라 아래의 **1열/2열 분할 규칙**을 적용합니다.

### 1.1 콘텐츠 그리드 분할 규칙 (1열 & 2열 구성)

#### ① 1열형 레이아웃 (Full-Width Layout)
* **적용 대상**: 대시보드 리포트(차트 나열형), 통합 검색 결과 목록, 대량의 행이 존재하는 리스트/테이블 화면(예: 스타트업 DB 리스트, 감사 로그 등).
* **특징**: 화면 폭을 최대 가용 영역까지 넓게 사용하여, 가로 스크롤을 최소화하고 대형 테이블의 다중 컬럼 데이터를 한눈에 시원하게 판독할 수 있게 합니다.

#### ② 2열형 레이아웃 (Two-Column Layout)
* **적용 대상**: 스타트업/전문가 상세 프로필 조회 화면, 보육 프로그램 매칭 캘린더, M&A 딜 검토 상세 및 전자결재 문서 상세 화면.
* **특징**: 화면을 크게 **주 콘텐츠(Primary)**와 **보조 정보(Secondary)**로 분할하여 정보의 다각적 탐색을 유기적으로 돕습니다.
  * **주 콘텐츠 열 (좌측, 65% ~ 70% 비율)**: 주요 핵심 인적 정보 카드, 기본 업무 폼, 메인 기안 문서 등 사용자 집중이 필요한 핵심 내용을 표출합니다.
  * **보조 정보 열 (우측, 30% ~ 35% 비율 또는 고정 360px~400px)**: 연관 파일 첨부 패널, 히스토리 로그 타임라인, 정성 피드백 의견 카드(아코디언 형태), 혹은 결재선 지정 박스 등을 함께 배치합니다.
* **반응형 흐름(Responsive Behavior)**:
  * 화면 가로 폭이 충분한 데스크톱에서는 2열로 나란히 배치하여 화면을 넓고 입체적으로 씁니다.
  * 가로 폭이 부족한 태블릿 및 모바일 환경(1024px 미만)에서는 **우측 보조 열이 좌측 주 콘텐츠 열 아래로 흐르는(Stack) 1열 형태로 자동 적응**하여 모바일 스크롤만으로 모든 정보를 유기적으로 조회할 수 있도록 대응합니다.

## 2. 상단바 (Topbar) 상세 요건

### 2.1 서비스 전환 드롭다운 (Workspace Switcher)
상단바 좌측 영역에 배치되어 사용자가 다른 워크스페이스로 매끄럽게 이동할 수 있도록 지원하는 핵심 컴포넌트입니다.

* **동작 및 비주얼**:
  * 클릭 전에는 현재 진입한 워크스페이스명(예: `OFFICE`, `STARTUP`, `AC`, `FUND` 등)과 드롭다운 화살표(`▾`) 아이콘이 표시됩니다.
  * 클릭 시 하단으로 드롭다운 형태의 레이어가 부드럽게 펼쳐집니다.
* **권한 기반 노출 제어**:
  * 사용자의 권한 정보(`PermissionMap`)를 읽어와, 해당 워크스페이스(도메인)에 **최소 '읽기(Read)' 권한**이 부여된 공간만 목록에 노출합니다.
  * 권한이 아예 없는 워크스페이스(예: 일반 직원이 볼 수 없는 `ADMIN`이나 타 부서에 잠긴 `M&A`)는 드롭다운 메뉴 목록에서 완전히 숨김(Hidden) 처리하여 무분별한 링크 노출을 방지합니다.
  * `GUEST`는 권한 도메인에는 포함되지만 WORKS 내부 워크스페이스가 아니므로, 서비스 전환 드롭다운에는 노출하지 않고 별도 서브도메인 앱에서 운영합니다.
* **현재 위치 표시**:
  * 드롭다운 목록 중에서 현재 사용자가 머물고 있는 워크스페이스 항목에는 브랜드 포인트 컬러(`text-brand`) 및 우측에 '현재' 텍스트/체크 배지를 노출하여 직관성을 확보합니다.

### 2.2 사용자 프로필 및 계정 관리 메뉴
계정 조작(내 계정 관리·로그아웃)은 셸(상단바·사이드바)이 아니라 **OFFICE 대시보드 우측 첫 칸의 환영 카드**가 소유합니다.

* **자리 이동 배경**: 계정 영역은 상단바 우측 → 사이드바 하단을 거쳐 2026-08-03에 환영 카드로 모았습니다. 사진·이름·소속·근속을 이미 보여 주는 카드가 "지금 로그인한 사람"을 말하는 유일한 자리이므로, 그 정보를 셸에서 중복해 이고 다닐 이유가 없다는 판단입니다.
* **버튼 구성**: 카드 우측 끝에 글자 버튼 두 칸('내 메뉴' → 마이페이지, '로그아웃')을 둡니다. 로그아웃은 되돌리기 어려운 동작이지만 대시보드에 상시 놓이므로, 빨간 버튼(`danger`) 대신 호버에서만 위험색을 드러내는 `outline-danger`를 쓰고 실행 전 확인 창을 한 번 띄웁니다.
* **셸에 남지 않는 것**: 상단바 우측은 전역 슬라이드오버 진입점(AI·전사 캘린더·알림)만, 사이드바는 현재 워크스페이스의 이동 수단만 담습니다.

## 3. 좌측 사이드바 (Sidebar) 상세 요건

### 3.1 워크스페이스별 동적 메뉴 스위칭 규칙 (Contextual Sidebar Menu)
상단바 드롭다운에서 선택된 워크스페이스(컨텍스트)에 종속된 하위 메뉴군만 좌측 사이드바에 동적으로 노출합니다. 사용자는 하나의 플랫폼 안에서 불필요한 노이즈 없이 현재 업무에만 집중할 수 있습니다.

#### ① OFFICE (전사 업무 허브) 선택 시
* **기본 업무 영역**: 대시보드, AI 에이전트, 임직원 정보, 전사 캘린더, 회의실 예약, 전자결재, 거래처 정보.
* **게시판 영역**: 고정 게시판(공지사항, 공용자료실 등)과 일반 게시판(인사이트 및 신규 생성 게시판)을 런타임 게시판 레지스트리에서 동적으로 주입합니다.

#### ② STARTUP (스타트업 풀) 선택 시
* **현황 영역**: 대시보드.
* **내 업로드 DB**: 구분과 무관하게 담당자(`startup_managers`) 또는 등록자(`created_by`)가 로그인 사용자인 기업을 모아 봅니다. 담당자는 투자기업 전용 개념이므로 등록자 축을 함께 보아야 발굴·보육·기타 기업도 포착됩니다.
* **스타트업 DB**: 구분·담당 무관으로 볼 수 있는 기업 전부를 봅니다. 위 '내 업로드 DB'와 같은 목록 화면을 범위만 넓혀 그대로 씁니다. 두 항목은 같은 원장을 범위만 달리해 보는 한 쌍이므로 사이에 구분선을 두지 않으며, 아이콘도 이모지가 아닌 선 아이콘으로 통일합니다(2026-08-20 명칭·표기 정리).
* **구분은 메뉴가 아니라 필터**: 투자·보육·발굴·기타 네 구분은 2026-08-20에 사이드바 항목에서 내리고 두 목록의 **구분 필터(다중선택)** 로 옮겼습니다. 분류를 메뉴로 두면 그것이 '어디에 있는가'가 되어 소재지·단계 같은 다른 축과 함께 걸 수 없고(보육기업 중 시드 단계만, 같은 질문에 답할 수 없습니다), 분류를 하나 늘릴 때마다 사이드바가 길어집니다. 옛 링크(`?tab=invested` 등)로 들어오면 `스타트업 DB`로 주소까지 바로잡습니다 — AC 사업구분이 2026-08-03에 밟은 경로와 같습니다.
* **운영 도구**: 회의록, 아처스캔, 대용량 업로드.

#### ③ NETWORKS (네트워크 원장) 선택 시
메뉴는 **`네트워크 DB` 한 줄**입니다(`/networks`, 탭 키 없음). 2026-09-04 원장 통합으로 국내/글로벌 쌍이 사라졌고(지역은 목록의 필터 축입니다), 같은 날 '미분류 데이터베이스'도 구분 필터의 선택지로 내려갔으며, 2026-09-05에 마지막으로 남아 있던 범위 두 줄도 목록 상단의 **범위 토글**로 합쳤습니다.

* **내 관리**(기본, `/networks`): 로그인 사용자가 **생성자(`created_by`)이거나 기여자(`entity_contributions`)인** 네트워크를 구분·지역 무관 단일 목록으로 봅니다. NETWORKS는 담당자 축이 없는 공동 관리 모델이므로 기여 이력이 담당자 축을 대신합니다. 조회는 `public.my_network_entities()` RPC가 담당하며, 호출자 판정을 함수 내부에서 하고 `SECURITY INVOKER`로 동작해 원장 RLS를 그대로 따릅니다.
* **전체 관리**(`/networks?scope=all`): 볼 수 있는 원장 전부를 같은 목록으로 봅니다(`public.all_network_entities()`). 열·필터·검색·상세 진입이 모두 같고 범위만 다릅니다.

> [!NOTE]
> 2026-09-05에 `내 업로드 DB`·`전체 네트워크` 두 메뉴를 한 줄로 합치고, 범위는 목록 상단 액션 줄 왼쪽의 세그먼트 토글(`내 관리` / `전체 관리`)이 답하게 했습니다. 두 메뉴는 같은 원장을 같은 열·같은 필터로 보며 범위만 달랐는데, 범위를 메뉴로 두면 그것이 '어디에 있는가'가 되어 지역·구분과 같은 축으로 함께 걸 수 없고 메뉴를 옮길 때마다 걸어 둔 검색어와 필터가 사라집니다 — 구분(2026-08-20)·지역(2026-09-04)이 먼저 밟은 경로와 같습니다. 토글은 검색어·필터를 유지하고 페이지 번호만 첫 장으로 되돌립니다(넓힌 목록의 3페이지는 방금 보던 그 3페이지가 아닙니다). 범위는 주소(`?scope=all`)에 실려 링크가 범위까지 실어 나르며, 기본 범위는 주소에 적지 않아 같은 화면을 가리키는 주소가 둘이 되지 않습니다. 민감정보 정책 키는 범위별로 그대로 둡니다(`networks.mine`/`networks.all`) — 내 것만 볼 때와 전부 볼 때의 노출 범위가 같을 이유는 없습니다.

> [!NOTE]
> 2026-09-04에 '미분류 데이터베이스' 메뉴를 내리고 구분이 비어 있는 행은 목록 **구분 필터의 `미지정` 선택지**가 답하게 했습니다. 분류를 메뉴로 두면 그것이 '어디에 있는가'가 되어 지역·영역 같은 다른 축과 함께 걸 수 없습니다(*해외의 미지정*, 같은 질문에 답할 수 없습니다) — AC 사업구분(2026-08-03)·STARTUP/FUND 구분(2026-08-20)이 먼저 밟은 경로와 같습니다. 대신 구분이 정해지는 자리를 앞으로 당겨, 대용량 업로드는 빈 구분이 남아 있으면 업로드가 막히고 회의록 간이 등록도 구분을 필수로 받습니다(신규 등록 폼만 2026-09-05에 필수를 풀고 기본값을 '미지정'으로 두었습니다 — [3_3_4 §3.1](../docs_planning/3_3_4_networks_unified_ledger.md)). 옛 링크(`?tab=others`·`?tab=experts`·`?tab=all` 등)로 들어오면 `?scope=all`(전체 관리)로 주소까지 바로잡습니다.

> [!NOTE]
> 모든 워크스페이스의 '내 ~' 탭은 **생성자이거나 담당자(NETWORKS는 기여자)** 라는 동일한 정의를 따릅니다. 생성자 축을 항상 함께 보는 이유는, 담당자·기여자 레코드가 없는 건이 어느 사용자의 목록에도 잡히지 않는 사각지대를 막기 위함입니다.

* **원장 종류는 메뉴가 아니라 필터**: 전문가·투자사·BAN·EXP·기업·기관·대학·기타 여덟 메뉴는 2026-08-20에 사이드바에서 내리고 국내 통합 목록의 **구분 필터(다중선택)** 로 옮겼습니다. 분류를 메뉴로 두면 그것이 '어디에 있는가'가 되어 영역·활동 같은 다른 축과 함께 걸 수 없고(전문가 중 영역이 핀테크인 사람, 같은 질문에 답할 수 없습니다), 원장을 하나 늘릴 때마다 사이드바가 길어집니다 — AC 사업구분(2026-08-03)·STARTUP 구분(2026-08-20)이 먼저 밟은 경로와 같습니다. 원장별 목록이 갖고 있던 **영역·매칭·활동·만족도 필터도 통합 목록으로 함께 옮겼으므로** 거를 수 있는 축은 줄지 않습니다. 옛 링크(`?tab=experts` 등)로 들어오면 `?scope=all`(전체 관리)로 주소까지 바로잡습니다.
* **열은 원장별로 가르지 않습니다**: 통합 목록은 프로필 공용 컬럼 한 벌(이름·소속·직책/직급·이메일·연락처·구분·영역·활동·만족도·매칭)을 세웁니다. 조직형(기업·기관·대학·기타)은 영역·활동·만족도·매칭을 채우지 않으므로 그 칸이 `-`로 남습니다 — 열을 원장별로 갈면 통합 목록이 성립하지 않으므로, 열은 세우고 값을 비웁니다.
* **등록은 구분을 되묻지 않습니다**: 원장이 하나가 된 뒤(2026-09-04 통합) 구분은 어디에 저장할지가 아니라 폼 안의 한 칸이므로, `신규 등록` 버튼은 곧장 작성 화면(`/networks/record/new`)으로 갑니다. 구분은 그 폼이 묻고 기본값은 `미지정`입니다.
* **대용량 업로드**: 사이드바 항목이 아니라 목록 상단의 `대용량 업로드` 버튼으로 들어갑니다(`/networks/bulk`).

#### ④ AC (사업 관리) 선택 시
* **AC 메인**: 대시보드.
* **사업 목록**: `내 프로젝트`, `전체 프로젝트` 두 항목입니다. 같은 원장을 범위만 달리해 보는 한 쌍이므로 사이에 구분선을 두지 않습니다(STARTUP·NETWORKS와 같은 규칙). 프로그램 상세 내부에서 운영 모듈 카드 클릭으로 모집, 평가, OT, 멘토링, 매칭, 데모데이, 타임라인, 성과, 글쓰기 화면으로 진입하고, URL첨부·파일첨부는 보드 위에서 모달로 엽니다.

> [!NOTE]
> M&A와 PROJECT도 동일한 사업 워크스페이스 사이드바 구성을 공유합니다(`config/navigation.ts`의 `programSubnav()`). 2026-08-20부터 **라벨까지 같습니다** — 워크스페이스마다 달랐던 `내 사업 관리`/`전체 사업`, `내 딜 관리`/`전체 딜`을 세 곳 모두 `내 프로젝트`/`전체 프로젝트`로 통일했습니다. 같은 원장 구조와 같은 화면을 쓰는 세 워크스페이스라 메뉴 이름까지 같아야 워크스페이스를 옮겨도 손이 같은 자리를 찾습니다. 라벨은 `PROGRAM_MINE_LABEL`·`PROGRAM_ALL_LABEL` 상수가 단일 원천이며 페이지 제목도 같은 값을 읽습니다(사이드바와 제목이 어긋나면 눌러 들어간 메뉴와 도착한 화면의 이름이 달라집니다). 도메인 명칭(사업·딜)은 목록 안쪽 문구(`entityNoun`)가 계속 답합니다.

> [!NOTE]
> 2026-08-03 이전에는 세 워크스페이스 모두 사업구분별 세분화 항목(AC 공공·민간·매출·기타 등)을 사이드바에 나열했습니다. 분류를 메뉴로 두면 그것이 '어디에 있는가'가 되어 상태·부서 같은 다른 축과 함께 걸 수 없고(공공 사업 중 진행중만 같은 질문에 답할 수 없습니다), 분류를 하나 늘릴 때마다 사이드바가 길어집니다. 사업구분은 목록 필터의 축 하나로 옮겼으며, 미분류 건은 그 필터의 `미지정` 선택지가 답합니다. 옛 링크(`?tab=sell` 등)로 들어오면 `전체 ~`로 주소까지 바로잡습니다.

#### ⑤ FUND (투자 관리) 선택 시
* **펀드 목록**: `내 운용펀드`, `전체 운용펀드` 두 항목입니다. 두 목록은 같은 화면을 범위만 달리해 쓰므로 사이에 구분선을 두지 않으며, 출자자·캐피탈 콜·포트폴리오·목적달성은 사이드바가 아니라 펀드 상세 안에서 다룹니다.

> [!NOTE]
> 2026-08-20에 펀드 종류별 항목(`AC 펀드`·`VC 펀드`·`PE 펀드`)을 내리고 구분(`strategy_type`)을 목록 필터의 축으로 옮겼습니다. 분류를 메뉴로 두면 그것이 '어디에 있는가'가 되어 재원·성격·상태 같은 다른 축과 함께 걸 수 없고(VC 펀드 중 모태 재원만, 같은 질문에 답할 수 없습니다), 구분이 비어 있는 펀드는 세 메뉴 어디에도 나타나지 않아 아예 보이지 않았습니다 — AC 사업구분(2026-08-03)·STARTUP 구분·NETWORKS 원장(2026-08-20)이 먼저 밟은 경로와 같습니다. 미분류 건은 구분 필터의 `미지정` 선택지가 답하며, 옛 링크(`?tab=ac_fund` 등)로 들어오면 `전체 운용펀드`로 주소까지 바로잡습니다.

### 3.2 내비게이션 활성화 및 하이라이트 규칙
* 현재 접속 중인 브라우저의 URL 경로(`pathname`)와 사이드바 메뉴 항목의 `href` 경로를 비교하여 일치하거나 하위 경로인 경우 활성화(`active`)로 판정합니다.
* 사이드바 배경은 브랜드 인디고 한 단계(`brand.700`, `#204181`) **단색**을 표준으로 합니다(2026-08-20 확정). 한때 `brand.600`→`700`→`800` 세로 그라디언트로 깊이를 주었으나, 화면 왼쪽 끝에서 위아래로 밝기가 변하는 면이 생기면서 그 위에 얹히는 흰 pill과 구분선의 명도 대비가 자리마다 달라졌습니다 — 같은 규격의 메뉴 항목이 상단에서는 또렷하고 하단에서는 묻힙니다. 배경은 균일한 바탕으로 두고 위계는 항목 쪽(흰 pill·인디케이터 바)이 만듭니다. 메뉴 텍스트는 불투명 흰색(`text-white`)을 사용하며, 반투명 흰색은 배경과 섞여 메뉴 전체가 뿌옇게 보이므로 사용하지 않습니다. 구분선은 `border-white/15`, 아코디언 화살표 등 보조 요소만 `text-white/75`까지 낮춥니다.
* 메뉴 아이콘은 **lucide 선 아이콘 한 종류**로 통일합니다(2026-08-20 확정). 한때 `내 ~` 항목만 ⭐ 이모지를 아이콘 자리에 놓아 '내 것' 층을 강조했으나, 색 있는 글리프는 그 줄을 다른 층의 메뉴로 보이게 합니다 — `내 ~`와 `전체 ~`는 같은 원장을 범위만 달리해 보는 한 쌍이므로 같은 규격의 글리프를 씁니다. `SubNavItem`에서 `emoji` 필드 자체를 제거했고, `내 ~` 항목의 아이콘은 탭 매핑(`mine` = `User`)이 답합니다.
* 활성화된 메뉴는 **흰색 pill 배경(`bg-white`)에 브랜드 인디고 글씨(`text-brand`)**로 반전시키고, 좌측에 `4px` 두께의 브랜드 컬러 세로 인디케이터 바를 노출하여 사용자의 현재 위치 인지력을 향상시킵니다. 호버 상태는 `bg-white/15`입니다.

## 4. 반응형 모바일 뷰포트 인터랙션

* **데스크톱 해상도 (`1024px` 이상)**:
  * 좌측 사이드바가 고정 형태로 항상 유지됩니다. 본문 영역은 사이드바 너비를 제외한 영역을 가득 채웁니다.
* **모바일 및 태블릿 해상도 (`1024px` 미만)**:
  * 좌측 사이드바는 화면에서 완전히 숨겨집니다.
  * 상단바 좌측에 **햄버거 메뉴 아이콘(Menu Bar Icon)**이 노출됩니다.
  * 사용자가 햄버거 메뉴 아이콘을 터치하면, 화면 좌측에서 사이드바가 슬라이딩 아웃(Drawer) 형식으로 부드럽게 미끄러지며 펼쳐집니다. 사이드바 바깥 영역은 `rgba(0,0,0,0.4)` 배율의 어두운 오버레이 딤(Dim) 처리를 적용하여 본문 영역을 터치하면 다시 닫히도록 유도합니다.
