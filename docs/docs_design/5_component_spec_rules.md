# [5] 공통 컴포넌트 규격 및 표준 디자인 시스템 정의서

본 문서는 와이앤아처 통합 Works 플랫폼의 시각적 일관성과 설계 효율성을 보장하기 위해, 컴포넌트 제작 시 적용해야 하는 **표준 글로벌 토큰(Radius, Shadow, Density)**과 **공통 UI 컴포넌트의 물리적 규격 명세**를 정의합니다.

> [!IMPORTANT]
> 본 문서의 수치는 코드가 원천입니다. 값 자체는 `tailwind-preset.mjs`가, "어느 맥락에 어느 값을 쓰는가"라는 매핑은 `packages/ui/src/densityScale.ts`가 소유합니다. 규격을 조정할 때는 그 두 파일을 고치고 본 문서를 뒤따라 갱신합니다. 문서에 수치를 다시 적어두고 코드와 어긋나게 두지 않습니다.

## 1. 글로벌 디자인 토큰 (Global Design Tokens)

### 1.1 모서리 둥글기 (Border Radius)

라운드는 "아주 약간"만 적용해 카드·버튼·테이블 모두 각진 인상을 유지합니다. 업무용 원장 화면이 주된 무대이므로, 둥근 모서리로 부드러움을 주기보다 정보 밀도와 격자감을 우선합니다.

| 토큰 | 값 | 사용처 |
| :--- | :--- | :--- |
| `radius-sm` | `4px` | 페이지네이션 버튼 |
| `radius-md` | `6px` | 버튼, 입력 필드, 셀렉트, 드롭다운 팝오버 패널, 테이블 래퍼 |
| `radius-lg` | `10px` | 카드(`Card`·`CardShell`·`PanelCard`), 모달 다이얼로그 |
| `rounded-full` | — | 배지(`Badge`), 태그 칩(`TagChip`), 토글 스위치, 아바타, 배지 내 상태 점(dot) |

### 1.2 그림자 효과 (Box Shadow)

**쉬고 있는 표면에는 그림자를 쓰지 않습니다(2026-08-20).** 화면의 구획은 헤어라인 테두리와 면의 색차가 만들며([4_color_system_rules.md](./4_color_system_rules.md) §2.1), 그림자는 화면 위에 **떠 있는** 요소(팝오버·모달)에만 남깁니다.

* **`shadow-soft`**: `0 0 #0000`(투명) — 카드·입력 필드·테이블 래퍼가 쓰던 단계이며, 값을 비워 사실상 폐지했습니다.
  * `none`이 아니라 **투명한 그림자**를 쓰는 이유: Tailwind의 shadow 유틸은 여러 그림자를 쉼표로 잇는 형태(`box-shadow: <ring>, <ring>, var(--tw-shadow)`)라, 여기에 `none`이 들어가면 목록 전체가 문법 오류가 되어 선언이 통째로 버려집니다. 결과는 같아 보여도 "의도해서 껐다"가 아니라 "망가져서 안 나온다"가 되고, 나중에 그림자를 하나라도 되살리면 예측할 수 없게 깨집니다.
* **`shadow-popover`**: `0 8px 20px rgba(0, 0, 0, 0.06)` — 드롭다운 메뉴, 입력 포커스 상태.
* **`shadow-dialog`**: `0 12px 32px rgba(0, 0, 0, 0.08)` — 모달·드로어·슬라이드오버.
* **`shadow-pinned`**: `10px 0 14px -4px rgba(17, 24, 39, 0.16)` — 가로 스크롤 표의 고정(sticky) 선두 열 seam(2026-08-25 토큰화). 쉬고 있는 표면이 아니라 스크롤되는 셀 **위에 떠 있는** 열의 그림자이며, 우측으로만 번지는 방향성 때문에 별도 토큰입니다. `DataTable` 밖에서 쓰지 않습니다.

> [!IMPORTANT]
> **그림자는 반드시 이 토큰들로만 지정합니다(2026-08-20 후속 정비).** 정책을 확정하면서 `shadow-soft`를 투명으로 비웠지만, 정작 버튼·체크박스·라디오·스위치·페이지네이션·세그먼트 토글은 그 토큰이 아니라 Tailwind 기본 `shadow-sm`을 직접 쓰고 있어 정책이 닿지 않았습니다. 그래서 카드와 표는 평평해졌는데 그 위의 버튼만 예전 그림자를 달고 떠 있는, 한 화면 안에 표면 규칙이 두 개인 상태가 남았습니다. **토큰을 바꾸는 것만으로는 정책이 반영되지 않습니다** — 기본 스케일(`shadow-sm`/`md`/`lg`/`xl`/`2xl`/`inner`)을 직접 쓴 곳이 있으면 그곳은 정책 밖에 있습니다.
>
> * **쉬고 있는 표면 = 그림자 없음**: 카드·표·입력에 더해 **버튼과 폼 컨트롤도 여기 속합니다.** 눌리는 것임은 면색과 테두리가 이미 말합니다.
> * **떠 있는 요소 = 토큰**: 모달·드로어·슬라이드오버는 `shadow-dialog`, 드롭다운·멘션 패널·툴팁·이미지 위 오버레이 컨트롤은 `shadow-popover`. 토큰 위에 색 틴트(`shadow-gray-900/15` 등)를 겹치지 않습니다 — 토큰 값이 무의미해집니다.
> * **유일한 예외는 스위치의 손잡이**입니다. 트랙 위에 얹혀 좌우로 움직이는 부분이라 떠 있음이 곧 조작 가능함의 표시이고, 패널용 크기인 두 토큰은 8px짜리 손잡이에 쓸 수 없습니다.
> * **`shadow-none`을 쓰지 않습니다**: 걷어낼 그림자가 이미 없으므로, 남아 있으면 "여기엔 그림자가 있었다"는 잘못된 신호만 남습니다.

### 1.3 밀도 맥락 (Density Context)

> [!IMPORTANT]
> **크기를 가르는 축은 중요도가 아니라 놓이는 자리입니다.** 같은 '수정' 버튼이라도 페이지 툴바에 있으면 40px, 카드 안이면 32px, 표 셀 안이면 24px입니다. 버튼에 `size` prop을 두어 호출부가 매번 크기를 고르는 방식은 쓰지 않습니다 — 같은 자리의 컨트롤이 화면마다 달라지는 원인이 그것이었습니다.

맥락은 3종이며, `DensityProvider`가 React 컨텍스트로 하위 트리에 전달합니다.

| 맥락 | 무대 | 컨트롤 | 아이콘 버튼 | 배지 | 글자 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `page` | 페이지 툴바 · 상세 헤더 · 독립 폼 | `40px` | `36px` | `22px` | `14px` |
| `card` | 카드섹션 내부 | `32px` | `28px` | `20px` | `13px` |
| `table` | 데이터 테이블 셀 내부 | `24px` | `24px` | `18px` | `12px` |

* **맥락은 자동으로 상속됩니다**: `Card`·`CardShell`·`PanelCard`는 `card`를 하위에 내려줍니다. 그래서 카드 안에 놓인 `<Button>`은 아무것도 지정하지 않아도 32px이 됩니다.
* **`DataTable`은 자기가 놓인 자리를 보고 한 단 내려 줍니다(2026-08-20)**: 카드 안에 든 표는 셀 안에 `table`(24px)을, 페이지에 바로 놓인 표는 `card`(32px)를 내려줍니다. 표는 언제나 `table`이라고 고정하던 것을 바꾼 것으로, 페이지 전체를 차지하는 목록이 카드 안 보조 표와 같은 크기로 서서 **화면의 주인공이 화면에서 가장 작은 글자가 되던** 문제를 없앱니다. 셀 글자·행 높이·열 폭이 이 맥락과 한 벌로 움직입니다([3_typography_rules.md](./3_typography_rules.md) §4.2).
* **수동 지정은 예외 경로입니다**: 카드 안이지만 페이지급 강조가 필요한 경우에만 `density="page"`처럼 명시합니다. 기본값과 같은 값을 다시 적지 않습니다.
* **오버레이는 맥락을 되돌립니다**: 포털은 DOM만 `body`로 옮길 뿐 React 컨텍스트는 부모를 그대로 따릅니다. 따라서 `Modal`·`Drawer`는 `page`로, `Dropdown`·`Toast`는 `card`로 맥락을 재설정합니다. 이 처리가 없으면 표 셀에서 연 모달의 입력 필드가 24px로 렌더됩니다.
* **아이콘 버튼이 한 단계 작은 이유**: 라벨이 없어 같은 높이면 시각적으로 더 커 보이기 때문입니다. 컨트롤과의 단차는 4~8px을 유지합니다.

### 1.4 타이포그래피 스케일

| 토큰 | 크기 | 용도 |
| :--- | :--- | :--- |
| `title-lg` / `title-md` / `title-sm` | `30` / `24` / `20px` | 페이지 제목 계열 |
| `body-lg` | `16px` | 강조 본문 |
| `body` | `14px` | 본문 표준, `page` 맥락 컨트롤 라벨 |
| `body-sm` | `13px` | `card` 맥락 컨트롤 라벨 |
| `caption` | `12px` | 보조 설명, `table` 맥락 컨트롤 라벨 |
| `tag-page` / `tag-card` / `tag-table` | `12` / `11` / `10px` | 배지·태그 전용 |

* **컨트롤 라벨을 본문보다 한 단계 누르는 이유**: 조작 요소가 읽을거리보다 앞으로 튀어나오지 않게 하기 위함입니다.
* **`tag-*`는 배지 전용입니다**: `line-height`를 `1`로 고정해 부모의 행간을 상속하지 않게 했습니다. 상속하면 같은 배지가 화면마다 다른 높이로 보입니다.
* **임의값 금지**: `text-[13px]`처럼 클래스에 수치를 직접 적지 않습니다. ESLint가 차단합니다.

### 1.5 아이콘 스타일 규칙

* **표준 패밀리**: `Lucide Icons`. `stroke-width: 2px`를 유지해 시각적 무게를 통일합니다.
* **글리프 크기**: 맥락을 따릅니다 — `page` `18px` / `card` `16px` / `table` `14px`.

## 2. 기본 조작 컴포넌트 명세 (Control Components)

### 2.1 버튼 (Button & IconButton)

* **크기**: `size` prop이 없습니다. 높이·글자·좌우 여백·간격을 모두 밀도 맥락(§1.3)에서 가져옵니다.
* **위계는 색이 만듭니다**: `primary`(브랜드 채움) → `secondary`(회색 채움) → `outline`(테두리) → `ghost`(배경 없음) 순으로 무게가 낮아집니다.
* **파괴적 액션 2종**:
  * **`danger`**: 적색 채움. 단독으로 서는 결정적 삭제에 사용합니다.
  * **`outline-danger`**: 평소에는 중립이고 호버에서만 위험색이 드러납니다. 표의 '비활성화'처럼 **행마다 반복되는** 파괴적 액션용으로, 빨간 버튼이 목록에 깔리는 것을 피합니다.
* **IconButton**: 정사각 아이콘 버튼(`outline`·`ghost`·`selected` 3종 + `danger` 플래그). `label`이 필수 prop이므로 `aria-label`이 구조적으로 강제됩니다.
* **상태색은 여기서 정하지 않습니다**: 기본·호버·클릭의 실제 색은 [4_color_system_rules.md](./4_color_system_rules.md) §5.1이 단일 원천이며, `Button`의 `buttonVariantClass`가 그 표를 그대로 옮겨 담습니다. 라우팅이 필요해 `Button`을 쓸 수 없는 자리(`BackButton`처럼 `as={Link}`가 되는 것)도 색을 다시 적지 않고 그 표를 가져다 씁니다 — 옮겨 적는 순간 정본이 두 벌이 됩니다.
* **직접 만들지 않습니다**: `<button>`에 `h-* rounded border px-*`를 조합해 버튼 모양을 새로 만들지 않습니다. 상자를 가진 아이콘 액션은 전부 `IconButton`을 씁니다.
* **크기를 바꿔야 하면 `density`를 씁니다**: `className="h-ctl-page"`처럼 높이만 덮어쓰면 글자·좌우 여백은 상속한 맥락 그대로 남아, 40px 상자 안에 카드 규격 글자가 들어갑니다. 규격은 한 벌로 움직여야 하므로 `density="page"`를 명시합니다.

> [!IMPORTANT]
> **ESLint 가드는 클래스 문자열이 나타나는 네 자리를 모두 봅니다(2026-08-21 보강).** 이전에는 JSX 속성에 **평범한 문자열로** 적힌 경우만 검사했고, 그래서 우회가 두 줄이면 끝났습니다 — 조건부 클래스를 템플릿 문자열로 쓰거나(`` className={`h-10 ...`} ``), 클래스를 상수로 한 번 빼면(`const topbarButtonBase = cn('h-10 …')`) 규칙이 닿지 않았습니다. 실제로 상단바 40px 버튼과 GUEST 버튼 전량이 그 경로로 규격 밖에 살아남았고, 전 코드베이스에서 걸리는 위반이 **1건**뿐이었습니다.
>
> 지금은 ① JSX 속성 문자열 ② JSX 속성 템플릿 문자열 ③ 변수 선언 ④ `cn()` 인자를 모두 검사하며, 임의 폰트값·컨트롤 높이·비토큰 모서리·기본 그림자 스케일·수제 카드/배지·원시 색·버튼의 `gray-25` 호버를 막습니다.
>
> **가드는 클래스만이 아니라 요소도 봅니다(2026-08-21 보강).** 어떤 이탈은 클래스가 아니라 태그에 있습니다 — 원시 `<input type="checkbox">`는 **클래스를 아예 안 달았을 때가 가장 나쁜데**(브라우저 기본 파랑으로 렌더됩니다) 그때 클래스 기반 규칙은 볼 것이 없어 통과시킵니다. 실제로 GUEST 신청서의 개인정보 동의 체크박스가 그 상태였습니다. 이제 원시 선택 컨트롤(`input[type=checkbox|radio]`)과 수제 토글(`role="switch"`)을 요소 단위로 막습니다.
>
> **수제 카드 규칙은 조합으로 판정합니다(2026-08-21).** 이전에는 정본 클래스 문자열과 **정확히 일치**할 때만 걸려서 한 글자만 달라도 통과했고, 하필 정본에서 가장 먼 형태(GUEST의 `rounded-lg border border-gray-200 bg-white p-4` — 토큰 밖 모서리에 컨테이너가 아닌 divider 색)가 그 틈으로 살아남았습니다. 이제 카드 모서리 + 테두리 + 흰 면의 **조합**으로 봅니다.
>
> **`packages/ui`도 검사 대상입니다(2026-08-21).** 이전에는 `apps/**`만 봤는데, 그러면 디자인 시스템의 본체가 정책 밖에 놓입니다. 실제로 `MultiSelectFilter`가 **같은 패키지 안의 `Checkbox`를 두고** 원시 input을 쓰고 있었고, 앱이었다면 즉시 걸렸을 코드가 여기서는 아무 신호 없이 살았습니다. 규격을 만드는 쪽이 규격에서 면제되면 규격이 두 벌이 됩니다. 규격의 **원본**(`CardShell`·`Modal`·`Checkbox`·`Radio`·`Switch`)에는 사유를 적은 `eslint-disable-next-line`을 답니다 — 그 한 줄이 곧 규격이므로 가드의 대상이 아니라 대상의 근거입니다.
>
> **가드가 잡지 못하는 것도 분명히 해 둡니다.** 린트는 클래스 문자열과 요소만 볼 뿐, "이 `Button` 두 개가 배타 쌍이다" 같은 **의미**는 보지 못합니다. §2.3의 컨트롤 선택 표가 그 자리를 대신하며, 이 항목은 리뷰에서 잡습니다.
>
> **컨트롤인지 판별하는 표지는 상태 접두사**(`hover:`·`active:`·`focus-visible:`·`disabled:`)입니다. 요소를 볼 수 없는 상수 자리에서 "모서리 토큰"을 표지로 쓰면 썸네일·이모지 타일(`h-12 rounded-radius-md`)이 전부 걸립니다. 누를 수 없는 것에는 상태 접두사를 붙일 이유가 없다는 점이 더 정확한 신호입니다. 같은 이유로 `gray-25` 호버는 **높이 토큰이 함께 있을 때만** 막습니다 — 클릭 가능한 행은 gray-25가 맞고(§3.1), 행은 내용이 높이를 정하므로 높이 토큰을 달지 않습니다.

> [!NOTE]
> **GUEST 앱만 최소 높이가 다릅니다.** 밀도 격자(40/32/24)는 마우스를 전제한 값이고, GUEST는 모바일 우선이라 터치 영역 **최소 48px**을 따로 규정합니다([3_9_workspace_guest.md](../docs_planning/3_9_workspace_guest.md) §2). 그렇다고 버튼을 손수 만들지는 않습니다 — 같은 `Button`에 `min-h`만 얹는 `GuestButton` 래퍼 하나가 이 규칙을 대신 지키고, 색·모서리·포커스 링은 전 플랫폼 공통을 그대로 따릅니다.

### 2.2 입력 필드 (Input / Select / TextArea)

* **크기**: 버튼과 같은 밀도 맥락을 따르므로, 한 줄에 나란히 놓인 입력과 버튼의 높이는 자동으로 일치합니다.
* **4상태 공통 외형**: 기본 · 호버(`border-gray-400`) · 포커스(`border-brand/50` + `shadow-popover`) · 비활성(`bg-gray-50`). 오류 상태는 `aria-invalid`와 함께 `border-danger-700`로 덮어씁니다.
* **아이콘 슬롯**: 좌측(검색 입력) 또는 우측(셀렉트 화살표)에 놓이며, 아이콘 위치와 반대편 여백이 짝을 이루도록 `controlIconPad`가 함께 관리합니다.
* **TextArea**: 높이는 `rows`가 정하므로 글자·여백만 맥락에 반응합니다. 최소 높이 `120px`를 보장하고 세로 리사이즈만 허용합니다(`resize-y`) — 가로 리사이즈는 레이아웃을 깨뜨립니다.
* **웹 접근성**: 플레이스홀더를 항목 명칭 대용으로 쓰지 않고, 좌측 또는 상단에 영구 텍스트 라벨을 노출합니다.


#### 라벨은 `Field`가 소유합니다 (2026-08-20 신설)

입력 위 라벨·도움말·오류는 화면이 직접 쓰지 않고 `Field` 컴포넌트에 맡깁니다. 카드의 라벨:값을 `InfoField`가, 표의 머리글을 `DataTable`이 소유하는 것과 같은 자리이며, 값 자체는 `packages/ui/src/densityScale.ts`의 `formText`가 갖습니다.

* **소유자가 없던 동안 규격이 넷으로 갈렸습니다**: `text-body font-medium text-gray-800`(36곳) · `text-caption font-semibold text-gray-600`(11곳) · `text-caption font-medium text-gray-700`(7곳) · `text-caption text-gray-600`(5곳). 같은 모달 안에서도 위 필드와 아래 필드의 라벨 크기가 달랐습니다.
* **라벨은 본문(14px)·`gray.900`**입니다. [3_typography_rules.md](./3_typography_rules.md) §4가 폼 레이블을 페이지 타이틀·표 본문과 같은 Primary Text 단계로 규정합니다. 라벨은 값을 읽기 전에 무엇을 묻는지 알려주는 자리이므로, 카드의 라벨(`gray.500` — 값이 주인공이고 라벨은 이름표)과 달리 물러나지 않습니다.
* **가로 라벨형(라벨이 입력 왼쪽)도 같은 규격을 씁니다**: 라벨이 입력과 한 줄에 서면 캡션(12px) 라벨은 본문(14px) 입력과 한 줄 안에서 크기를 가르게 되어 §1.4의 관통 원칙을 깨뜨립니다.
* **도움말·오류만 캡션(12px)으로 내려갑니다**: 라벨·컨트롤과 다른 줄에 서기 때문입니다. 도움말 색은 정본이 '폼 필드 입력 힌트 안내문'에 지정한 `gray.600`이고, 오류는 같은 크기에서 색만 `danger`로 갈립니다. 오류가 있으면 도움말 자리를 오류가 대신합니다 — 같은 자리를 두 줄이 다투지 않게 합니다.
* **`as="div"`**: 안에 컨트롤이 둘 이상 들어가면(시작·종료 시각 등) `<label>`이 어느 것을 가리키는지 모호해지므로 `div`로 바꿉니다.

### 2.3 선택 컨트롤 (Checkbox / Radio)

* **박스 크기**: `page` `20px` / `card` `16px` / `table` `14px`.
* **둥글기**: 체크박스는 `rounded`, 라디오는 완전 원형.
* **세로 정렬**: `align-middle`을 기본 적용합니다. 인라인 요소라 그냥 두면 글자 베이스라인에 걸려 위로 떠 보입니다. 표 셀에서는 셀 자체를 flex 중앙 정렬로 두어 확실히 고정합니다.
* **라벨은 컴포넌트가 소유합니다(2026-08-21, `Checkbox`에 신설)**: `label`을 넘기면 `<label>`로 감싸 클릭 영역을 라벨까지 넓히고, 간격·글자·커서를 밀도 맥락(`toggleScale`)에서 가져옵니다. **화면이 `<label>`을 직접 감싸지 않습니다.** `Radio`에는 처음부터 이 슬롯이 있었고 `Checkbox`에는 없었는데, 그 차이가 그대로 결과로 나타났습니다 — 라디오는 규격이 하나였고, 체크박스는 아홉 개 호출부가 **간격 다섯 가지**(`gap-1`·`gap-1.5`·`gap-2`·`gap-x-2`·`gap-3`)**, 글자 다섯 가지**로 갈렸으며 커서는 절반만 붙어 있었습니다. §2.2의 라벨 4종 난립과 원인이 같습니다.
* **`title`은 라벨 래퍼가 받습니다**: 비활성 input은 브라우저가 마우스 이벤트를 삼켜 툴팁이 뜨지 않습니다. 두 컴포넌트 모두 `label`이 있으면 래퍼에 붙입니다(2026-08-21 이전 `Radio`는 주석만 그렇게 적혀 있고 실제로는 툴팁이 사라지고 있었습니다).
* **선택 카드는 `boxed`입니다**: 선택지가 길거나 여러 줄이면 체크박스 하나로는 어디까지가 한 항목인지 눈이 끊지 못합니다. 테두리 상자에 담는 이 형태를 화면이 손으로 만들지 않습니다 — 그렇게 만든 두 자리는 테두리 색(`brand` / `brand/40`)도, 꺼짐 면(`bg-white` / `bg-gray-25`)도, 여백(`py-1.5` / `py-2`)도 서로 달랐습니다. 글자 크기는 상자가 아니라 밀도 맥락이 정합니다.

#### 무엇으로 만들지는 '몇 개를 고르는가'가 정합니다 (2026-08-21 신설)

같은 질문에 답하는 컨트롤이 화면마다 다른 모양이면 같은 것으로 읽히지 않습니다. 실제로 배타 선택 하나가 works에서 **네 가지 방식**으로 구현되어 있었습니다 — `Radio`, `SegmentedToggle`, `Button`의 variant 토글, 그리고 수제 선택 카드.

| 고르는 수 | 선택지 수 | 씁니다 |
| :--- | :--- | :--- |
| 하나 (배타) | 2~4개 | `SegmentedToggle` — 한 테두리 안에 칸을 나눠 **반드시 하나만 켜진다**는 사실을 형태가 말합니다 |
| 하나 (배타) | 5개 이상, 또는 설명이 붙는 선택지 | `Radio`(`label` 동봉) |
| 여럿 | 짧은 라벨 | `TagChip` |
| 여럿 | 설명이 붙거나 여러 줄 | `Checkbox boxed` |

* **`Button`을 켜짐/꺼짐 토글로 쓰지 않습니다**: variant를 바꿔 선택 상태를 표현하면 누르는 것(액션)과 고른 것(상태)이 같은 무게로 보이고, `aria-pressed`를 빠뜨리기도 쉽습니다.
* **'아무것도 안 고른 상태'에도 이름을 줍니다**: 태그 관리의 정렬이 그랬습니다 — 버튼 둘 중 같은 것을 다시 누르면 정렬이 풀렸는데, 그 상태에는 화면에 이름이 없어 두 버튼이 모두 꺼진 것이 무슨 뜻인지 알 수 없었습니다. 세 칸 세그먼트(`노출순위` · `이름 오름차순` · `이름 내림차순`)로 바꾸면 그 상태가 이름을 갖습니다.
* **고정 폭 격자가 필요한 다중 선택은 예외입니다**: 요일 일곱 칸은 알약이 글자 수만큼 늘어나면 한 주가 가지런히 보이지 않습니다. 이런 자리는 전용 컴포넌트(`WeekdayPicker`)를 두되, **화면마다 다시 만들지 않습니다.**

### 2.4 토글 스위치 (Switch)

트랙과 썸이 함께 움직여야 하므로 별도 규격표를 둡니다. 썸 이동 거리는 `트랙 너비 − 썸 크기 − 좌우 여백`과 일치시킵니다.

| 맥락 | 트랙 | 썸 | 이동 거리 |
| :--- | :--- | :--- | :--- |
| `page` | `44 × 24px` | `20px` | `22px` |
| `card` | `36 × 20px` | `16px` | `18px` |
| `table` | `28 × 16px` | `12px` | `14px` |

* **접근명은 타입이 강제합니다(2026-08-21)**: `aria-label`(스위치가 스스로 이름을 갖는 경우)과 `id`(바깥 `<label htmlFor>`가 이름을 주는 경우) 중 **하나는 반드시** 있어야 하며, 없으면 컴파일되지 않습니다. 스위치는 글자를 품지 않으므로 이름이 없으면 스크린리더에 '스위치, 켜짐'까지만 읽힙니다. 실제로 권한 콘솔의 워크스페이스별 읽기·쓰기 스위치가 그 상태였고, 바로 옆 민감정보 패널은 제대로 붙어 있어 **같은 화면 안에서 규칙이 갈려** 있었습니다. 린트가 아니라 타입으로 막는 이유는 빠뜨릴 수 있는 자리를 아예 없애기 위함입니다.
* **설정 한 줄은 `SettingRow`가 소유합니다**: '제목 + 설명 + 오른쪽 스위치' 구조가 근무 기준·자산 등록·근태 상태 폼에 다섯 번 손으로 쓰여 있었고 제목 규격이 둘로 갈렸습니다(`text-body/gray-900` · `text-body font-medium/gray-800`). 이 줄은 값을 보여주는 자리가 아니라 **무엇을 묻는지** 알리는 자리이므로 카드 라벨이 아니라 폼 라벨 규격(`formText`)을 따릅니다. `control`이 `id`를 받아 넘기므로 왼쪽 제목이 곧 컨트롤의 접근명이 됩니다 — 같은 문구를 `aria-label`에 다시 적으면 화면에 보이는 이름과 읽히는 이름이 두 벌이 되어 한쪽만 고쳐집니다.

### 2.5 아바타 (Avatar)

* **크기**: `page` `40px` / `card` `32px` / `table` `24px`. 이니셜 글자도 함께 옮겨 원 안에서 같은 비율로 보이게 합니다.
* **둥글기**: 완전 원형.
* **대체 텍스트**: 이미지가 없으면 이름 첫 글자(영문은 대문자)를 노출합니다.

## 3. 구조 및 데이터 컴포넌트 명세 (Structure & Data Components)

### 3.0 카드섹션 (Card / CardShell / PanelCard)

* **셋 중 하나를 고릅니다**: 상자만 필요하면 `CardShell`, 제목·부제·우측 액션이 필요하면 `Card`, 한 줄 헤더(제목 + 건수 + 액션 하나)면 `PanelCard`입니다. 외형은 `radius-lg` · `border-gray-300` · `bg-white` · `p-5` 한 벌이며 **`Card`는 상자를 `CardShell`에 위임합니다**(2026-08-21) — 이전에는 두 파일이 같은 클래스 문자열을 각자 들고 있어 카드 규격이 두 곳에 존재했습니다.
* **수제 div로 만들지 않습니다**: 클래스 중복보다 중요한 이유는 **밀도 맥락 전달**입니다. 손으로 만든 상자는 `card` 맥락을 내려주지 못해 그 안의 버튼·태그가 페이지 밀도(40px)로 렌더됩니다 — "카드는 작아 보이는데 안의 버튼만 큰" 현상이 여기서 나옵니다.
* **제목 옆 건수는 `CardHeading`이 소유합니다(2026-08-21 신설)**: `[3]` 대괄호 말머리이며 **0건은 강조색을 걷고 회색으로 물러납니다** — '있음'과 '없음'을 색으로 가르는 것이 이 표기의 쓸모입니다. 소유자가 없던 동안 works에 제목+건수가 여섯 곳에 손으로 쓰여 있었고 **간격이 넷**(`ml-2`·`gap-2`·`gap-1.5`·`gap-1`)**, 0건 처리가 셋**으로 갈렸습니다(`PanelCard`만 회색으로 눌렀고, 나머지는 `[0]`을 붉게 세우거나 아예 숨겼습니다 — 붉은 `[0]`은 있지도 않은 것을 강조합니다). 알약 배지가 아니라 대괄호인 근거는 `cardText.count`에 있습니다.
* **소제목은 `CardHeading level="subhead"`입니다**: 카드 제목(16px)과의 구분은 크기가 맡고 색은 `gray-900`을 유지합니다 — 색까지 빼면 소제목이 자기가 이끄는 본문보다 연해져 위계가 뒤집힙니다.
* **셸 없이 섹션을 세우지 않습니다**: 카드 안에 들어갈 내용이 페이지에 맨몸으로 놓이면 제목이 사다리 한 칸 위로 올라가기 쉽고(`text-title-sm`), 그 안의 표는 페이지 직치 표로 판정되어 한 단 큰 규격과 선택 체크박스를 갖게 됩니다.

### 3.1 데이터 테이블 (Data Table)

* **테이블 래퍼**: `border-gray-300` 테두리의 라운드 박스(`radius-md`) 안에 렌더링하며, 가로 스크롤 영역(`overflow-x-auto`)을 확보합니다. 카드·필드·드롭다운 등 모든 컨테이너 외곽은 동일하게 `gray-300`을 쓰고, 내부 divider만 한 단계 연한 `gray-200`을 씁니다.
* **격자는 표가 놓인 자리를 따릅니다(2026-08-20)**: 카드섹션 안에 든 표는 `row`(`36px`), 페이지에 바로 놓인 표는 `row-lg`(`44px`)를 머리글·본문 행에 함께 씁니다. 두 값의 규칙은 하나입니다 — **셀 안 컨트롤 높이 + 위아래 6px씩**(24+6·6 / 32+6·6). 셀 좌우 여백도 같은 원리로 갈립니다(`px-2.5` / `px-3`) — 셀 안 버튼의 좌우 여백과 같은 값이라야 열이 시각적으로 정렬됩니다. 자리는 `DataTable`이 부모 밀도 맥락에서 읽어 스스로 고르며, 화면이 지정하지 않습니다.
* **세로선을 긋지 않습니다(2026-08-20)**: 이전에는 `divide-x`로 모든 셀 사이에 세로선을 그었습니다. 세로선은 가로로 읽는 눈의 진행을 매 열마다 끊어 스캔을 느리게 하고, 열이 많은 표에서는 격자가 데이터보다 먼저 보입니다. 열 구분은 선이 아니라 정렬이 이미 하고 있으므로 — 숫자는 우측 정렬에 `tabular-nums`로 폭이 고정되고 각 열은 머리글 아래로 수직 정렬이 유지됩니다 — 행 구분(가로선 `border-b`)만 남깁니다.
* **머리글에는 램프에서 가장 옅은 회색 면을 깝니다(2026-08-25 확정)**: 2026-08-20에는 면을 완전히 걷어내고 굵기와 색(`semibold` + `gray-600`), 그리고 밑줄 하나로만 머리글을 표시했습니다. 그러나 카드섹션 안에 든 표는 카드 자체가 이미 흰 면이라 머리글 줄과 첫 데이터 행이 같은 바탕 위에 연달아 놓였고, 밑줄 하나로는 띠가 서지 않아 어디까지가 머리글인지 한눈에 잡히지 않았습니다. 되돌린 값은 구 `gray-50`이 아니라 램프에서 가장 옅은 **`gray-25`(`#FAFBFC`)**입니다 — 머리글이 데이터보다 무거워지던 이유는 면을 깐 것 자체가 아니라 그 면이 진했던 것이므로, 띠가 서는 최소한의 톤차만 남깁니다. 글자의 명도 대비는 7.77대 1에서 7.65대 1로만 내려가 KWCAG AA를 그대로 충족합니다. 정렬 가능한 머리글의 Hover는 `gray-50`으로, 이 바탕보다 한 단계 진해 그대로 구분됩니다(`gray-100`은 구 회색 띠가 되돌아온 것처럼 보입니다). 가로 스크롤 시 고정되는 선두 열의 머리글 셀도 같은 `gray-25`를 깔아야 합니다 — 흰색을 남기면 그 열만 머리글 띠에서 빠져 보입니다.
* **마지막 행의 밑줄은 지웁니다(2026-08-20)**: 모든 셀이 `border-b`를 갖는데 래퍼도 테두리를 두르고 있어, 표 아래쪽에 1px 선이 두 줄로 겹쳐 그림자처럼 두껍게 보였습니다. 마지막 행의 경계는 래퍼가 이미 그리므로 행 쪽 밑줄만 걷어냅니다.
* **정렬**: 표를 빨리 읽게 만드는 것은 선이 아니라 **한 표에 기준 모서리가 하나뿐이라는 것**입니다. 그래서 규칙은 셋으로 끝납니다 — **값을 읽는 모든 열은 좌측**(이름·업종·담당자는 물론 날짜·배지도 여기 듭니다), **자릿수를 맞춰 크기를 견주는 숫자만 우측**(금액·건수·No.), **값이 아니라 조작이 놓이는 열만 가운데**(체크박스·관리). 열의 종류(`type`, 아래 참조)가 이를 정하고, 열이 직접 준 `align`이 그것을 덮으며, 둘 다 없으면 왼쪽입니다(2026-08-20 확정, 이전 기본값은 가운데). 종류를 적지 않았다는 것은 그 열을 아직 살피지 않았다는 뜻이므로, 확인 없이 안전한 쪽인 왼쪽으로 떨어져야 합니다. 같은 날 날짜·일시·배지도 가운데에서 좌측으로 옮겼습니다 — 폭이 일정하다는 것은 가운데를 *허용하는* 조건일 뿐 *요구하는* 이유가 아니었고, 그 셋만 가운데로 뜬 표는 좌측 기준선 사이에 다른 기준선이 끼어 눈이 두 번 옮겨 갔습니다. 폭이 일정한 값은 좌측에 세워도 이미 세로로 가지런하므로 가운데로 얻는 것이 없습니다. **머리글은 자기 열의 값과 같은 쪽에 섭니다(2026-08-20)** — 이전에는 모든 머리글이 가운데 고정이라, 왼쪽으로 선 이름 열이나 오른쪽으로 선 금액 열에서 머리글만 홀로 떠 있었습니다. 값과 어긋나면 열을 훑을 기준선이 두 개가 됩니다. 표준 컬럼의 수정일 머리글도 `updatedAtAlign`을 값과 함께 따릅니다.
* **글자 위계**: **한 표 안에서 크기는 하나**로 두고 구분은 **굵기와 색으로만** 만듭니다. 그 하나가 12px인지 14px인지는 위계가 아니라 표가 놓인 자리가 정하며(카드 안 12 / 페이지 직치 14), 셀 안 컨트롤·배지도 함께 한 단 움직입니다 — 값만 키우면 한 행 안에서 값·버튼 라벨·배지가 제각각으로 보입니다. 자리별 규격표와 근거는 [3_typography_rules.md](./3_typography_rules.md) §4.2, 머리글·보조 값의 색이 `gray-600`인 근거(12px 한글의 뭉갬)는 같은 문서 §4.1을 참조합니다. **화면은 셀 안에서 크기를 덧씌우지 않습니다** — 메타 톤이 필요한 열은 컬럼에 `tone: 'meta'`를 적습니다(`tableText.meta`를 셀 안 `<span>`에 붙이면 크기가 함께 딸려 와 그 칸만 자리를 따라오지 못합니다).

| 역할 | 굵기 | 색 | 대상 |
| :--- | :--- | :--- | :--- |
| 머리글 | `600` | `gray-600` | `th` 전체 |
| 식별 값 | `500` | `gray-900` | 그 행이 무엇인지 알려주는 열(이름·기업명) |
| 일반 값 | `400` | `gray-700` | 나머지 도메인 열 전부 |
| 보조 값 | `400` | `gray-600` | `No.`·생성자·수정일 등 메타 |
| 빈 값 | `400` | `gray-400` | 값이 없어 `-`로 대체한 자리 |

* **빈 값은 하이픈(`-`) 하나입니다**: 표기와 색(`gray-400`)은 공용 `EmptyValue` 컴포넌트가 소유하며, 화면에서 글자와 색을 손으로 조합하지 않습니다. em 대시(`—`)는 한글 폰트에서 글자 한 칸을 통째로 차지해, 값이 없는 칸이 값이 있는 칸보다 오히려 길고 진해 보입니다 — 표를 세로로 훑을 때 비어 있는 자리가 먼저 눈에 걸립니다.
* **식별 열은 행마다 하나입니다**: `primary: true`로 지정하며, 미지정 시 첫 번째 도메인 열이 자동으로 식별 열이 됩니다. 도메인 열 전체를 진하게 쓰면 한 행이 통째로 진해져 눈이 걸릴 곳이 없어집니다. 표를 훑을 때 시선이 식별 열을 따라 내려가고 나머지는 배경으로 물러나야 합니다.
* **셀 안에서 색을 다시 지정하지 않습니다**: `render`에서 `text-gray-600` 같은 색을 덧입히면 열마다 톤이 어긋납니다. 위 위계는 셀이 소유합니다.
* **수치 정렬 정합성**: 수량 컬럼은 자릿수가 세로로 맞도록 `tabular-nums`를 적용합니다.
* **인터랙션**: 클릭 가능한 행은 `cursor-pointer hover:bg-gray-25`, 선택된 행은 `bg-brand/5`로 강조합니다.

#### 열 규격은 종류(`ColumnType`)가 정합니다 (2026-08-20)

열 하나를 세우는 데 필요한 폭·정렬·수치서식·줄바꿈 네 가지는 사실 "그 칸에 무엇이 들어가는가"라는 하나의 사실에서 따라 나옵니다. 그래서 넷을 따로 적지 않고 컬럼에 `type` **한 단어**로 선언합니다 — 넷을 손으로 조합하게 두면 화면마다 조합이 조금씩 달라지고, 그것이 곧 들쑥날쑥한 표가 됩니다. 개별 열의 `align`·`numeric`·`className` 명시는 종류가 정한 값을 덮는 예외 통로입니다.

고정폭은 표가 놓인 자리에 따라 두 벌입니다(카드 안 / 페이지 직치) — 폭은 글자에서 따라 나오므로, 글자가 한 단 오르면 폭도 함께 오릅니다.

| 종류 | 폭 (카드 / 페이지) | 정렬 | 비고 |
| :--- | :--- | :--- | :--- |
| `name` | 가변 (가중치 3) | 좌측 | 식별 값(이름·기업명). 남는 폭의 가장 큰 몫 — 잘리면 곤란한 값이라 여유가 가장 쓸모 있는 곳 |
| `long` | 가변 (가중치 2) | 좌측 | 주소·비고 등 긴 텍스트 |
| `tags` | 가변 (가중치 1.6) | 좌측 | 값이 여러 개인 분류 태그(분야·업종). 개수만큼 폭이 널뜁니다 — 표기는 `TagCell`이 소유합니다 |
| `text` | 가변 (가중치 1.2) | 좌측 | 짧은 라벨 중 **길이의 상한을 모르는** 것 |
| `person` | 가변 (가중치 1.3) | 좌측 | 사람 이름. 여럿이면 폭이 허락하는 만큼 적고 `+N`으로 접습니다(`PersonCell`) |
| `code` | 고정 `5rem` (두 자리 공통) | 좌측 | 길이의 상한이 정해진 값 — 코드·구분·단계·재원 |
| `badge` | 고정 `5rem` (두 자리 공통) | 좌측 | 상태 배지 한 개(11px·`px-2`, 네 글자까지) |
| `date` | 고정 `7rem` / `8rem` | 좌측 | `YYYY-MM-DD` |
| `period` | 고정 `12rem` / `13rem` | 좌측 | `YYYY-MM-DD ~ YYYY-MM-DD`(23자). 표기는 `PeriodCell`이 소유합니다 |
| `datetime` | 고정 `9rem` / `11rem` | 좌측 | `YYYY-MM-DD HH:MM:SS` |
| `money` | 고정 `7rem` / `8rem` | 우측 | `tabular-nums`. 값은 열 자리까지 들고, 페이지 자리는 단위 병기 머리글까지 셈합니다 |
| `count` | 고정 `5rem` / `6rem` | 우측 | `tabular-nums` |

* **`text`와 `code`를 가르는 축은 값의 성격이 아니라 '길이의 상한을 아는가'입니다(2026-09-01 신설)**: 상한을 아는 값에 가변폭을 주면 남는 폭이 그 칸의 빈자리로 사라집니다. 둘을 가르지 않던 동안 `text`가 사실상의 기본값이 되어, 두 글자짜리 '구분'이 사업명과 같은 비율로 폭을 받았습니다 — 펀드 목록에서는 다섯 개의 `text` 열(값은 모두 5자 이하)이 남는 폭의 절반을 가져가는 동안 정작 이름과 태그가 잘렸습니다. 고정폭은 자동 레이아웃에서 **하한**이므로, 예외적으로 긴 값이 와도 잘리지 않고 열이 늘어납니다.
* **표의 모든 값은 한 줄에 섭니다(2026-09-02 확정)**: 기간은 한동안 날짜 한 개 폭에 값을 두 줄로 접었습니다. 폭은 아꼈지만 그 열만 행 높이가 두 배가 되어, 한 표 안에 한 줄짜리 열과 두 줄짜리 열이 섞이고 행의 기준선이 하나로 읽히지 않았습니다 — 폭을 아끼려다 표 전체의 리듬을 내주는 거래였습니다. 지금은 값이 한 줄에 서는 것이 먼저이고 폭이 값을 따라갑니다(`period` = 23자). 대신 `period`는 고정폭 중 가장 넓으므로, 열이 많은 표에서는 기간을 **열로 두는 것 자체**를 먼저 의심합니다 — 상세에서만 읽어도 되는 값이면 목록에서 빼는 편이 낫습니다.
* **고정폭은 여유가 아니라 값이 필요로 하는 만큼입니다(2026-09-02 신설)**: 고정폭 열의 남는 여유는 그 칸의 빈자리로 끝나지 않습니다. 가변폭 열이 나눠 가질 몫이 `100% − 고정폭 합`이라, 여유는 곧 식별 열에서 뺀 폭입니다. 고정폭 열이 열 개를 넘는 표에서는 열마다의 작은 여유가 쌓여 식별 열이 굶습니다 — 펀드 목록은 고정폭 합이 96rem까지 불어나 1,652px 컨테이너를 거의 다 먹었고, 남은 116px을 펀드명과 관리인력이 나눠 갖느라 정작 그 행이 무엇인지 알려주는 펀드명이 세 줄로 접혔습니다. 그래서 `code`·`badge`·`period`의 폭을 종류별 최대 길이에 맞춰 조였고(`period` 14→13rem, `code`·`badge` 6→5rem, 카드 안 `money` 8→7rem), 그중 셋은 두 자리(카드/페이지)가 같은 값이 되었습니다 — 담기는 값이 짧아 14px과 13px의 차이가 폭을 가를 만큼 쌓이지 않기 때문입니다. **고정폭을 늘리려는 순간은 그 열이 정말 그만큼 필요한지, 아니면 열을 하나 줄여야 하는지 묻는 자리입니다.**
  * 다만 **조이는 것과 딱 맞추는 것은 다릅니다.** `period`를 값 폭(약 190px)과 같은 12rem에 두었더니 반올림 한 픽셀 차이로 카드 안 표에서 말줄임이 났습니다 — 글자 폭은 글꼴·확대 배율·소수점 반올림에 따라 몇 픽셀씩 흔들리므로, 고정폭은 최대 길이에 **한 칸의 여유를 더한 값**이어야 합니다.
* **단위는 값도 표 위 단서 줄도 아닌 머리글에 병기합니다(2026-09-02 확정, 공용 `ColumnUnit`)**: `약정총액 (백만)`처럼 열 이름 뒤에 12px·보통 굵기로 붙입니다. 값에 붙이는 안이 탈락하는 이유는 그대로입니다(행 수만큼 반복되며 열 폭을 먹고 자릿수 비교가 어긋납니다). 2026-09-01에 골랐던 표 안 단서 줄(`caption`)에서 옮긴 이유는 **읽는 순서**입니다 — 단서 줄은 머리글에서 눈을 한 번 떼야 읽히고, 금액 열이 셋이면 그 단위가 어느 열에 걸리는지도 줄 하나로는 말해 주지 못합니다. 열 이름이 직접 말하면 그 물음이 생기지 않습니다. 크기를 한 단 낮추는 것은 "한 줄 안에서 크기를 갈라 위계를 만들지 않는다"의 예외이며, 근거는 단위가 이름이 아니라 **이름에 붙는 단서**라는 것입니다 — 같은 크기·굵기면 `약정총액`과 `백만`이 두 개의 이름처럼 읽힙니다. `caption`은 표 전체에 걸리는 다른 단서(기준일 등)를 위해 남습니다. 병기한 뒤에는 그 머리글이 열 폭 안에 드는지 확인합니다.
* **인원 열은 폭이 허락하는 만큼 이름을 적고 넘치는 수만 `+N`으로 알립니다(2026-09-02 확정, 공용 `PersonCell`)**: 이전에는 개수와 무관하게 첫 사람만 적고 나머지를 `외 N`으로 접었습니다(구 `memberSummary`). 폭이 남는 표에서도 언제나 한 명만 보여, 담당자가 셋인 사업과 하나인 사업이 목록에서 똑같이 읽혔고 누구에게 물어야 하는지 알려면 매번 상세로 들어가야 했습니다. 접는 기준을 개수가 아니라 자리로 바꾸면 열이 넓어질 때 저절로 더 보입니다. 몇 명이 들어가는지는 글자 폭을 재야 알 수 있으므로 판정은 셀이 하고(숨은 자 + `ResizeObserver`), 라벨 함수는 **누가 먼저 오는가**(대표·리드·PM)만 정합니다. 전원은 `title`에 남습니다.
* **값이 여러 개인 분류 태그는 목록에서 배지가 아니라 한 줄 텍스트입니다(2026-09-01 확정)**: 근거는 셋입니다. ①색은 상태에만 씁니다(§3.4) — 분류까지 색 배지가 되면 한 행에 색 덩어리가 여럿 서고, 표를 훑을 때 지금 확인해야 할 행이 무엇인지 색이 알려주지 못합니다. ②개수가 행마다 달라 배지 줄의 길이가 널뛰고, 세로로 훑는 눈이 그 요철에 걸립니다. ③폭이 모자랄 때 배지 줄은 배지 한 개의 **중간**에서 잘려 반쪽이 남는데, 그것은 압축이 아니라 화면이 깨진 것으로 읽힙니다(글자는 말줄임이 자연스럽습니다). 상한을 넘긴 개수는 `외 N`으로 알리고 전체 값은 `title`에 남깁니다. **상세 화면에서는 배지가 맞습니다** — 거기서는 태그가 훑어야 할 배경이 아니라 읽어야 할 값이고, 한 화면에 한 레코드만 있어 개수가 널뛰는 문제도 없습니다.

* **폭 계산은 표가 합니다**: 데이터 폭이 정해진 열은 rem으로 고정하고, 길이를 예측할 수 없는 열이 나머지(`calc((100% − 고정폭 합) × 가중치 비율)`)를 나눠 갖습니다. 남는 폭을 모든 열에 뿌리면 값들이 흩어지고 한 열이나 빈 칸에 몰아주면 그 자리가 통째로 비어 보이므로, **계산해서 정확히 채우는 것**만 남습니다. 열이 몇 개든 표는 컨테이너를 빈 구간 없이 채우며, 화면은 비율을 손으로 적지 않습니다.
* **가로로 긴 표는 눌러 담지 않고 스크롤합니다(2026-09-02 확정)**: 앞 항목의 계산은 **표가 컨테이너 안에 든다는 전제** 위에 섭니다. 열이 스무 개에 이르러 고정폭 합만으로 컨테이너를 넘으면 그 전제가 깨지고, 브라우저는 각 열이 요구한 폭을 비율대로 깎습니다. 이때 값이 한 줄로 고정된 열은 내용이 폭을 지켜 주지만 **말줄임되는 셀(`TagCell` 등 `truncate`)은 지켜 줄 내용이 없어 한 글자 폭까지 눌립니다** — FUND 포트폴리오 전체보기에서 업종 열이 15px짜리 띠로 짜부라졌습니다. 그래서 **종류가 선언한 폭은 상한이 아니라 하한이기도 합니다.** 고정폭 종류는 자기 `rem`을, 가변폭 종류는 하한(`name` 8·10 / `long` 6·7 / `tags` 5.5 / `person` 4.5 / `text` 4rem)을, 표준 열(선택·`No.`·등록자·수정일·관리)은 자기 폭을 각각 `min-width`로 함께 겁니다. 넘친 폭은 래퍼의 가로 스크롤이 받습니다 — **표는 잘리는 대신 스크롤합니다.**
  * 하한은 선두 열 고정(`stickyLead`)의 **성립 조건**이기도 합니다: 고정 열의 `left` 오프셋은 선택·`No.` 열의 *선언한* 폭을 누적한 값이라, 그 두 열이 깎이면 고정 열 사이에 틈이 생기고 그 틈으로 스크롤되는 열이 비쳐 보입니다. 고정이 깨진 것이 아니라 고정이 믿고 있던 폭이 깨진 것입니다.
  * 대가는 폭이 아주 좁은 카드에서 가로 스크롤이 생길 수 있다는 것이며, 눌러 담아 못 읽는 것보다 낫다고 봅니다. 다만 스크롤은 열이 많다는 신호이므로, 하한을 낮추기 전에 **열을 줄일 수 있는지**(상세에서만 읽어도 되는 값인지)를 먼저 묻습니다.
* **선두 열 고정(`stickyLead`)에는 seam 그림자를 두지 않습니다(2026-09-02)**: 고정 열은 불투명 배경(머리글 `gray-25` / 본문 `white`)만으로 스크롤되는 셀을 덮습니다. 고정 영역 우측에 번지는 그림자(구 `shadow-pinned`)를 두었더니, 스크롤하지 않은 상태에서도 표 한가운데를 세로로 가르는 띠로 읽혀 있지도 않은 경계를 만들었습니다 — 세로선을 긋지 않는다는 위 규칙과 같은 이유로 폐지합니다.
* **`whitespace-nowrap`은 폭 스케일의 성립 조건입니다**: 폭 값 자체는 `densityScale.ts`의 `columnWidth` 스케일이 소유하며, **고정폭 종류의 값에는 `whitespace-nowrap`이 함께** 들어 있습니다. 자동 레이아웃에서 셀 width는 힌트일 뿐이라 다른 열이 공간을 요구하면 브라우저는 그 열을 min-content까지 쥐어짭니다 — `2026-05-14`는 하이픈에서 끊기므로 min-content가 `2026-` 폭이 되어 날짜가 두 줄로 접힙니다. 줄바꿈을 막아야 폭이 실제로 지켜집니다. 예외는 `long` 하나가 아니라 **가변폭 종류 전부**(`name`·`long`·`tags`·`text`·`person`)입니다 — 이들은 애초에 폭 클래스를 받지 않으므로 nowrap도 없습니다. 길이를 예측할 수 없는 값에 nowrap을 걸면 열 하나가 표 전체를 가로로 밀어내기 때문이며, 대신 이 열들은 다른 열처럼 폭이 지켜지지 않을 수 있습니다. 그래도 값을 한 줄에 세워야 하는 가변폭 셀은 셀 안에서 말줄임(`block truncate` + `title`)으로 처리합니다.
* **레이아웃 2모드**: 기본 `auto`는 계산 폭보다 내용이 길면 열이 늘어나 값을 다 보여주고, `fixed`는 폭을 지키고 넘치는 글자를 말줄임(…)합니다. 행 높이와 열 위치가 흔들리면 안 되는 표는 `layout="fixed"`를 씁니다.
* **고정폭 열의 머리글은 접힙니다(2026-08-20 확정)**: 앞 항목의 `whitespace-nowrap`은 **값**을 위한 것입니다. 그것이 머리글에까지 걸리면 머리글의 길이가 곧 열의 최소 폭이 되어, `재고(잔여)` 한 단어가 종류의 5rem을 밀어냅니다 — 규격을 정해 놓고 머리글이 그것을 이기면 규격이 아닙니다. 그래서 고정폭 종류(`badge`·`date`·`datetime`·`money`·`count`)의 머리글 셀만 nowrap을 벗겨 두 줄로 접히게 두고, 열은 자기 폭을 지킵니다. 접힘은 `break-keep`이라 **공백에서만** 일어납니다(한글은 기본값이면 `조합원유`/`형`처럼 음절 아무 데서나 갈라집니다). 따라서 머리글 작성 규칙은 둘입니다.
  * **단위·부연을 머리글에 넣지 않습니다**: 단위는 열마다 반복될 값이 아니라 표 전체에 한 번만 있으면 되는 정보입니다. `투자금액(백만원)` → `투자금액`. 괄호로 두 값을 부연해야 하는 열은 두 값을 그대로 이름 붙입니다(`재고(잔여)` → `잔여/보유`, 셀의 `3 / 10`과 읽는 순서가 같아집니다).
  * **두 어절 이상은 띄어 씁니다**: `조합원유형`이 아니라 `조합원 유형`. 붙여 쓰면 접힐 자리가 없어 열을 밀어냅니다.
  * 그래도 접히지 않고 열이 늘어난다면 그것은 머리글이 길다는 신호이며, 그때 늘릴 것은 폭이 아니라 줄일 것이 머리글입니다.
* **표 안 단서 줄(`caption`)은 표 전체에 걸리는 단서를 위한 자리입니다**: 자리는 표 안, 머리글 줄 **위 오른쪽**입니다. 표 **밖**(카드 부제)에 두지 않는 이유는 캡처입니다 — 표만 잘라 공유해도 단서가 함께 따라와야 합니다. 같은 이유로 이 줄은 가로 스크롤을 함께 타지 않습니다(스크롤은 안쪽 상자가 맡습니다). 2026-09-01에는 금액 단위(`단위: 백만원`)도 여기 두었으나, 2026-09-02에 단위만 머리글로 옮겼습니다(위 `ColumnUnit` 항목) — 단위는 표 전체가 아니라 **특정 열들에 걸리는 단서**이기 때문입니다.
* **`width="content"` 모드는 두지 않습니다(2026-08-20 결정)**: 열이 적은 조밀한 표를 컨테이너 폭이 아니라 데이터 폭으로 붙이는 모드를 검토했으나 도입하지 않습니다. 표가 컨테이너를 정확히 채운다는 성질이 곧 "표끼리 세로가 맞는다"의 근거인데, 이 모드는 표마다 오른쪽 끝을 다르게 만들어 한 화면에 표 둘을 세로로 놓으면 폭이 어긋납니다. 열이 적어 빈 구간이 생길 것이라던 우려는 실제로 관측되지 않았습니다 — `name`·`long`의 가변 몫이 남는 폭을 흡수합니다. 필요해지는 화면이 나오면 그 화면을 근거로 다시 논의합니다.

* **표준 메타 컬럼(필수)**: 레코드성 테이블은 다음을 반드시 포함하며 `DataTable`이 기본 탑재합니다.
  * **좌측 `No.`**: 최상단 행이 가장 큰 번호가 되도록 내림차순으로 매깁니다.
  * **우측 `등록자`**: 최초 등록자(`created_by`). 담당자(관리 주체)는 별개 축이므로 이 컬럼을 재라벨하지 않고 도메인 컬럼으로 따로 둡니다.
  * **우측 `수정일`**: `updated_at`을 `YYYY-MM-DD`로 절삭합니다.
  * **우측 `관리`**: 물리 삭제 금지 원칙에 따라 **소프트 삭제**를 수행합니다. 삭제가 아니라 `deleted_at`을 채우므로 명칭을 '비활성화'로 통일하고 `outline-danger` 버튼을 씁니다. 이미 비활성인 행은 버튼 대신 `비활성` 텍스트로 표기하고 행 전체를 `opacity-50`으로 흐리게 처리합니다.
  * **opt-out 대상**: 감사·다운로드 로그(불변 기록), 매칭 매트릭스(N:N 격자), 랭킹(집계 뷰)처럼 레코드 성격이 아닌 표는 `numbered={false} standardColumns={false}`로 제외합니다.
* **선택 체크박스(`selectable`)의 기본값은 표가 놓인 자리가 정합니다(2026-08-20)**: 페이지에 바로 놓인 표는 그 화면의 작업 대상이므로 켜고, 카드 안에 놓인 표는 상세 화면을 받치는 보조 목록이므로 끕니다 — 관련 목록에서 여러 건을 골라 일괄 처리할 일은 없고, 체크박스만 첫 칸을 차지합니다. 크기를 가르는 축(§1.3)과 같은 축입니다: 중요도가 아니라 놓이는 자리가 답합니다. 명시하면 자리와 무관하게 그 값이 이깁니다 — 카드 안이지만 일괄 처리가 필요한 표는 `selectable`을, 페이지에 있지만 선택 개념이 성립하지 않는 표(집계 매트릭스·순위표)는 `selectable={false}`를 줍니다.

### 3.2 리스트 페이지네이션 (Pagination)

* **버튼 크기**: 아이콘 버튼 격자를 그대로 씁니다(`page` 기준 `36px`). 숫자 버튼은 같은 높이를 유지하되 세 자리 이상에서 넓어지도록 최소 너비로 잡습니다.
* **활성 페이지**: 테두리 없이 브랜드 배경(`bg-brand`) + `text-white`. 비활성 번호는 `text-gray-700` + `hover:bg-gray-100`.
* **퀵 점프**: 이전(◀) 왼쪽에 맨 앞으로(⏮), 다음(▶) 오른쪽에 맨 뒤로(⏭)를 필수 탑재합니다.
* **직접 이동창**: 가장 우측에 '페이지 이동' 라벨과 숫자 입력창을 두어 번호를 직접 입력하고 엔터로 이동할 수 있게 합니다.
* **번호줄 페이저는 한 페이지뿐이어도 노출합니다**: 건수가 적다고 페이저가 사라지면 같은 표가 데이터에 따라 다른 화면처럼 보이고, 표 아래에 무엇이 오는지가 매번 달라집니다. 좌측 건수 표기 또한 같은 이유로 항상 자리를 지킵니다.
* **미니 페이저(`MiniPager`)를 쓰는 자리는 '카드 안'이 아니라 '보조 목록'입니다(2026-09-02 정정)**: 상세 우측 패널의 변동 이력·코멘트처럼 본문을 **받치는** 목록만 화살표 + `현재/전체`로 줄이고, 한 페이지면 숨깁니다. 카드 안에 있더라도 그 탭의 **작업 대상**인 표(FUND 포트폴리오 등)는 목록 화면의 표와 같은 번호줄 페이저를 상시 노출합니다 — 그 표를 다루러 들어온 화면에서 페이저가 다른 화면과 다르게 생기거나 사라지면, 자리를 아껴 얻는 것보다 잃는 것이 큽니다.

### 3.3 탭 메뉴 (Tabs)

* **높이**: 같은 맥락의 컨트롤과 동일합니다(`page` `40px` / `card` `32px` / `table` `24px`). 가변 세로 패딩(`py-*`)을 쓰지 않습니다 — 글꼴에 따라 높이가 흔들립니다.
* **스타일(Underline Tab)**: 카드형이 아닌 하단 라인형을 기본으로 하며, 탭 아래를 가로지르는 `1px` 가이드 라인(`border-b border-gray-200`)을 배치합니다.
* **활성 탭**: 두께 `500`, 브랜드 색, 하단 `2px` 강조 테두리. **비활성 탭**: `text-gray-600`, 호버 시 `text-gray-800`.
* **건수 칩**: 배지와 같은 규격(§3.4)을 공유합니다. 나란히 놓였을 때 어긋나지 않게 하기 위함입니다.

### 3.4 배지 및 태그 (Badge / TagChip)

* **크기 변형(`size` prop)을 두지 않습니다**: 크기는 맥락이 정합니다.

| 맥락 | 높이 | 글자 | 좌우 여백 | 점(dot) |
| :--- | :--- | :--- | :--- | :--- |
| `page` | `22px` | `12px` | `8px` | `6px` |
| `card` | `20px` | `11px` | `6px` | `4px` |
| `table` | `18px` | `10px` | `6px` | `4px` |

* **둥글기 `rounded-full`**(알약), 테두리 `1px`(상태색), 그림자 없음, 글자 두께 `500`. 좌우 여백이 높이 대비 넉넉한 것은 양끝이 둥글게 깎여 각진 모양과 같은 여백으로는 글자가 곡선에 붙어 보이기 때문입니다.
* **`solid` 변형은 표식 전용입니다**: 원색 배경 + 흰 글씨(`NEW` 등 "여기를 보라"는 자리)에만 씁니다. 상태 표시에는 쓰지 않습니다 — 상태끼리 무게가 갈리면 색이 만드는 위계가 깨집니다.
* **크기로 위계를 만들지 않습니다**: 배지가 전달하는 위계는 크기가 아니라 **색(tone)** 입니다. 같은 종류의 정보를 크기로 나누면 "큰 태그 = 더 중요한 상태"라는 잘못된 신호를 줍니다. 강조가 필요하면 톤을 바꾸고 크기는 건드리지 않습니다.
* **세로 크기는 높이로 못 박습니다**: 세로 여백(`py-*`)이 아니라 고정 높이 + `leading-none`으로 정의합니다. 세로 패딩만 주면 배지 높이가 부모의 `line-height` 상속에 끌려다닙니다.
* **색은 상태에만 씁니다**: 값이 하나뿐인 분류(예: '구분')는 배지로 감싸지 않고 텍스트로 둡니다. 분류와 상태가 같은 색 무게로 읽히면 표를 훑을 때 어느 쪽이 지금 확인할 행인지 구분되지 않습니다.
* **직접 만들지 않습니다**: `<span>`에 `rounded + px + py`를 조합해 태그 모양을 새로 만들지 말고 `Badge`(표시용) 또는 `TagChip`(선택 토글용)을 씁니다. 둘은 같은 규격표를 공유해 나란히 놓여도 어긋나지 않습니다.
* **상태 매핑 4종**:
  * **완료/성공(Success)**: 글씨 `#059669` | 배경 `#ECFDF5` | 보더 `#D1FAE5`
  * **대기/주의(Warning)**: 글씨 `#D97706` | 배경 `#FFFBEB` | 보더 `#FEF3C7`
  * **진행/정보(Info)**: 글씨 `#0064FF` | 배경 `#F0F5FF` | 보더 `#E0EBFF`
  * **취소/중단(Danger)**: 글씨 `#E02424` | 배경 `#FFF5F5` | 보더 `#FFE2E2`
  * 위 4종 외에 분류·중립 표기는 `neutral`(회색)을 씁니다.

### 3.5 다이얼로그 모달 (Dialog / Modal)

* **너비**: Tailwind 기본 `max-w-sm/lg/2xl`은 타이포그래피 척도라 다이얼로그 폭으로 쓰면 의미가 어긋납니다. 대화 단계별 전용 토큰을 씁니다.

| 토큰 | 폭 | 용도 |
| :--- | :--- | :--- |
| `modal-sm` | `400px` | 확인·경고 등 한 문장짜리 대화 |
| `modal-md` | `600px` | 단일 폼(기본값) |
| `modal-lg` | `800px` | 2열 폼 · 목록 선택 |
| `modal-xl` | `1000px` | 표를 품는 대화 |
| `modal-2xl` | `1200px` | 전체 화면에 준하는 편집기 |

* **모서리** `radius-lg`, **그림자** `shadow-dialog`.
* **밀도**: 어디서 열든 `page` 맥락으로 재설정합니다(§1.3).
* **구조**: 머리글·바닥글은 고정하고 본문만 스크롤합니다(최대 높이 = 뷰포트 − 여백).
* **푸터 버튼 정렬**: 항상 우측 정렬하며, 보조 버튼(취소·닫기)을 좌측에, 주요 액션(저장·등록)을 가장 우측에 배치합니다.

### 3.6 오버레이·피드백 (Dropdown / Drawer / Toast / Banner / EmptyState)

* **Dropdown**: 팝오버 패널은 `radius-md` · `border-gray-300` · `shadow-popover`. 항목은 카드 규격 높이(32px)로 고정하며 가변 세로 패딩을 쓰지 않습니다.
* **Drawer**: 모달과 같은 이유로 밀도를 `page`로 되돌립니다.
* **Toast**: 앱 어디서 호출하든 같은 크기여야 하므로 밀도를 `card`로 고정합니다. 자동 소멸 `4초`, 우측 하단 배치.
* **Banner**: 화면·폼 상단의 인라인 알림. 배지와 같은 상태 4색을 씁니다.
* **EmptyState**: 제목 + 설명 + 액션 슬롯의 중앙 정렬 블록.

### 3.6.1 도움말 말풍선 (Tooltip)

화면의 **안내 문구가 사는 단 하나의 자리**입니다(2026-09-01 확정). 그 전까지 안내는 라벨 아래 캡션, 카드 제목 아래 부제, 모달 본문 맨 위 문단, 패널 맨 아래 각주로 흩어져 있었고, 같은 성격의 문구가 화면마다 다른 크기·색·자리를 가졌습니다.

* **접는 이유는 자리 절약이 아니라 읽는 순서입니다**: 라벨·컨트롤·값이 서야 할 줄에 규칙 설명이 같은 무게로 끼어들면, 폼을 처음 보는 사람은 무엇을 입력하는 칸인지보다 규칙을 먼저 읽습니다. 규칙은 그 칸을 채우려는 사람만 필요로 하므로 물어볼 때 답합니다.
* **접지 않는 것**: 빈 상태, 오류, **다음 행동을 지시하는 차단 안내**(왜 못 누르는지·무엇을 먼저 해야 하는지), 되돌릴 수 없는 작업의 파급 효과 고지, 입력한 값의 되읽기(금액 포맷 미리보기 등). 호버해야 보이는 안내는 "왜 못 하는가"의 답이 될 수 없습니다.
* **화면이 `Tooltip`을 직접 놓는 일은 드뭅니다**: 폼 한 칸은 `Field`의 `hint`, 설정 한 줄은 `SettingRow`의 `hint`, 제목 줄은 `Card`·`PanelCard`·`Modal`·`PageHeader`·`CardHeading`의 `help`가 대신 놓습니다. 안내가 제목 줄 어디에 어떤 간격으로 서는지를 화면마다 다시 정하지 않기 위해서입니다. 직접 쓰는 자리는 그 어디에도 속하지 않는 곳(차트 범례·표 셀 안 배지·수제 라벨)뿐이며, 그때도 간격은 `tooltipScale.gap`을 씁니다.
* **접지 않을 도움말은 `hintInline`으로 표시합니다**: `Field`·`SettingRow`의 스위치이며, 위의 "접지 않는 것"에만 씁니다. 단순한 규칙 설명에 켜면 접기 기준이 화면마다 갈립니다.
* **규격**(`tooltipScale`, densityScale.ts): 표면 `radius-sm` · `bg-gray-800` · `shadow-popover`, 글자 캡션(12px) 흰색, 최대 폭 `18rem`. 말풍선은 밀도를 타지 않습니다 — 표 셀에서 열든 페이지에서 열든 떠 있는 층은 같은 크기여야 읽힙니다. 밀도를 타는 것은 줄 안에 함께 서는 트리거 아이콘뿐입니다(page·card 14px / table 12px — 자기가 딸린 글자보다 반 단 작게).
* **트리거**: 기본 ⓘ 아이콘. 색 4상태는 `gray-400` → 호버·포커스 `gray-600`. 호버·포커스뿐 아니라 **클릭·Enter·Space로도 열립니다** — 안내가 오직 말풍선 안에만 있으므로 호버가 없는 기기에서 열 방법이 없으면 그 문구는 존재하지 않는 것과 같습니다. `Esc`는 말풍선만 닫고 상위 모달로 전파하지 않습니다(설명을 읽으려다 입력하던 폼을 잃지 않게).
* **띄우는 방식**: body 포털 + fixed 좌표(`z-popover`)라 상위 컨테이너의 overflow/stacking에 잘리지 않습니다. 열려 있는 동안 스크롤·리사이즈를 캡처 단계로 받아 좌표를 다시 계산합니다 — 그러지 않으면 긴 폼에서 스크롤하는 순간 말풍선만 제자리에 남아 엉뚱한 칸을 가리킵니다.

### 3.7 지표 띠 (StatStrip)

대시보드나 목록 상단에서 지표 여러 개를 나란히 세우는 **유일한 규격**입니다(2026-08-20 확정). 지표는 서로 비교하려고 나란히 놓는 것인데, 각자 테두리 상자에 갇히면 비교가 아니라 열거로 읽힙니다. 상자를 걷고 하나의 띠 안에서 아주 옅은 세로선(`divide-gray-200`)으로만 나누면 숫자들이 한 덩어리로 스캔됩니다. 여기서 세로선을 쓰는 것은 표에서 세로선을 지운 판단(§3.1)과 어긋나지 않습니다 — 표는 행이 반복되며 세로선이 수십 줄 누적되지만, 지표 띠는 한 줄이라 선 하나가 누적되지 않습니다.

| 요소 | 규격 | 비고 |
| :--- | :--- | :--- |
| 라벨 | `text-caption` `gray-600` | 12px 한글은 `gray-500`에서 뭉개지므로 표 머리글과 같은 단계로 올립니다 |
| 값 | `text-title-sm`(20px) `font-bold` `tabular-nums` `gray-900` | 사다리가 정한 '지표 값' 단계 |
| 단위 | `text-body`(14px) `gray-500` | 값에 이어 붙이지 않고 별도 자리로 받습니다 |
| 보조 줄 | `text-caption` `gray-600` | 증감(`delta`) 또는 비율 문구(`note`) 중 **하나만** |
| 선택 | `bg-brand-25` + 라벨 `brand-700` | 표의 선택된 행·파이프라인의 켜진 단계와 같은 언어 |

* **총계 칸이라고 값을 키우지 않습니다**: 총계임은 라벨('전체')과 맨 앞이라는 자리가 이미 말합니다. 크기를 한 단 올리면 사다리에 없는 24px 지표가 생겨 다음에 보는 사람이 어느 쪽이 규격인지 알 수 없게 됩니다.
* **아이콘도 진행 막대도 두지 않습니다**: 라벨이 이미 무엇을 재는지 말하고 있고 비율은 보조 줄이 숫자로 말합니다. 같은 말을 형태로 한 번 더 하면 지표보다 장식이 먼저 눈에 듭니다(머리글에서 회색 면을 걷어낸 것과 같은 판단입니다).
* **칸은 곧 필터입니다**: `onClick`을 준 칸은 누를 수 있고, 지금 목록을 좁히고 있는 칸은 `selected`로 켭니다. 건수를 세어 놓고 누를 수 없으면 다음에 할 일이 표를 눈으로 훑는 일밖에 남지 않습니다.
* **카드 제목을 두지 않습니다**: 칸마다 라벨이 무엇을 재는지 이미 말하고 있어 제목이 더할 사실이 없습니다. 상자 안에 제목을 넣으면 테두리 → 제목 → 지표로 층이 셋이 되는데, 지표 띠는 상자를 걷어내 지표를 앞으로 내보내려고 쓰는 규격이라 같은 카드 안에서 층을 다시 쌓으면 취지가 상쇄됩니다. 건수도 목록의 페이저가 같은 모수로 이미 셉니다. 지표 띠는 `CardShell` 안에 그것 하나만 담습니다.
* **경계 — 흐름은 이 규격이 아닙니다**: 사업 워크스페이스의 진행 현황(`ProgramPipeline`)처럼 단계가 **순서를 갖고**(꺾쇠로 잇고) 주 경로 밖 이탈 단계가 따로 있는 카드는 지표 띠가 아니라 별도 패턴입니다. 글자 위계는 지표 띠와 같게 유지하되, 단계 상자·점선 테두리·편중 막대는 그 카드가 소유합니다.

### 3.8 범주형 현황 카드 (SummaryTile)

`SummaryTile`은 AC·M&A·PROJECT처럼 **서로 다른 업무 영역의 규모와 구성**을 나란히 보여주는 요약 패턴입니다. 파스텔 표면, 컬러 아이콘 상자, 28px 강조 수치, 흰색 반투명 보조 지표 필을 한 세트로 유지합니다.

* `StatStrip`은 같은 모수의 지표를 빠르게 비교하거나 필터링할 때 사용합니다.
* `SummaryTile`은 서로 다른 범주에 시각적 정체성이 필요할 때 사용합니다.
* 한 행에는 3개를 기본으로 하고, 좁은 화면에서는 1열로 쌓습니다.
* 범주색은 상태를 의미하지 않습니다. 진행·완료·위험은 별도 `Badge`로 표시합니다.
* 화면 코드에서 색·라운드·수치 크기를 재선언하지 않고 `tone`과 슬롯만 전달합니다.

#### 3.8.1 타일은 곧 필터입니다 (2026-08-26 확정)

목록 위에 선 현황 카드의 타일은 **그 축의 필터**입니다. 건수를 세어 놓고 누를 수 없으면 다음에 할 일이 표를 눈으로 훑는 일밖에 남지 않습니다(지표 띠 §3.7과 같은 판단입니다).

| 요소 | 규격 | 비고 |
| :--- | :--- | :--- |
| 클릭 | `SummaryTile`의 `onClick` | 준 타일만 `<button type="button">`으로 서고, 나머지는 `<section>` 그대로입니다 |
| 선택 | `ring-2 ring-brand ring-offset-2` + `aria-pressed` | 타일이 소유합니다 |
| 총계 타일 | 그 축의 조건을 **푸는** 문(`selected` = 조건 없음) | 총계라고 못 누르게 두면 되돌아올 자리가 필터 팝오버 안으로 숨습니다 |
| 걸 조건이 없는 타일 | `onClick`을 주지 않습니다 | '기타 상태'·'미지정'처럼 원장 값이 없는 묶음, 금액 지표처럼 좁힌 결과인 값 |

* **선택은 링으로 말합니다**: 지표 띠는 상자가 없어 옅은 브랜드 면(`bg-brand-25`)으로 선택을 말하지만, 이 타일은 면이 이미 범주색으로 칠해져 있어 같은 방법을 쓸 수 없습니다. 그래서 면 바깥의 브랜드 링으로 말합니다 — 표현은 다르되 색은 같은 브랜드입니다.
* **화면이 타일을 감싸지 않습니다**: 종전에는 화면마다 `<button>`이나 `role="button"` div로 제각기 감쌌고, 그래서 같은 뜻이 어떤 화면에서는 `ring-2 ring-brand`, 다른 화면에서는 `ring-offset-2`가 붙은 다른 모양이 됐습니다. 키보드 처리도 한쪽에만 있었습니다.
* **집계는 자기 축을 뺍니다**: 타일이 필터가 되려면 "저걸 누르면 몇 건이 되는가"를 답해야 하므로, 지금 걸린 그 축의 조건을 빼고 셉니다. 자기 조건을 자기 집계에 도로 걸면 고르지 않은 타일이 전부 0이 되어 0을 눌러야 결과가 나오는 화면이 됩니다.

### 3.9 규격 확인 페이지

`/styleguide`(WORKS 내부 전용, 메뉴 미노출)에서 같은 코드가 세 맥락에 놓였을 때의 결과를 나란히 확인할 수 있습니다. 각 컴포넌트의 실제 렌더 높이를 px로 함께 표시하므로, 규격 조정 여부는 문서가 아니라 이 화면을 보고 판단합니다.

> [!NOTE]
> `tailwind-preset.mjs`는 Vite의 감시 대상 밖입니다. 토큰 값을 고친 뒤에는 개발 서버를 **재시작**해야 화면에 반영됩니다. 컴포넌트 소스(`.tsx`) 수정은 HMR로 즉시 반영됩니다.

## 4. AC Program 운영 특화 컴포넌트 후보

AC 워크스페이스의 기능 모델은 `matching` 레퍼런스의 운영 감각을 가져오되, 화면 구성은 Works 공통 디자인 시스템을 따른다. 따라서 아래 컴포넌트는 별도 UI 복제가 아니라 기존 AppShell, PageHeader, Tabs, DataTable, Drawer, Modal, StatusBadge, SplitView 패턴을 조합하는 방식으로 정의한다.

### 4.1 ProgramCard / ModuleCard
* **ProgramCard**는 Program 목록과 대시보드에서 사용하며, Program명, 상태, 기간, 담당자, 활성 모듈 수, 미해결 운영 이슈 수를 표시한다.
* **ModuleCard**는 Program 상세의 모듈 보드에서 사용하며, `module_type`, `module_status`, `participation_mode`, 진행률, 마지막 업데이트 시각, 바로가기 액션을 포함한다.

### 4.2 EvaluationSplitView / FileSubmissionPanel
* **EvaluationSplitView**는 서면평가, 대면평가, 데모데이 평가에서 사용한다.
  * 좌측에는 신청서, PDF, 발표자료, 기업 요약 정보를 표시한다.
  * 우측에는 평가표, 점수 입력, 의견 입력, 임시저장/제출 액션을 배치한다.
* **FileSubmissionPanel**은 모집 신청, 발표자료 제출, 세션 자료 제출에서 사용하며, 파일 상태, 제출 마감, 검토 상태, 다운로드 권한을 함께 표시한다.

### 4.3 ScheduleSlotGrid / AssignmentMatrix
* **ScheduleSlotGrid**는 멘토링 회차, 비즈니스 매칭 슬롯, 대면평가 발표 시간표에서 사용한다.
* **AssignmentMatrix**는 심사위원-기업, 멘토-멘티, 전문가-상담 기업의 N:N 또는 1:1 배정 상태를 한 화면에서 확인하도록 구성한다.
* 두 컴포넌트 모두 시간 충돌, 배정 중복, 권한 범위 위반을 StatusBadge와 Inline Alert로 표시한다.

### 4.4 CounselingLogEditor / KpiSummaryPanel / ExportColumnPicker
* **CounselingLogEditor**는 멘토링 및 비즈니스 매칭 상담일지 작성에 사용하며, 요약, 이슈, 조언, 액션아이템, 후속 일정 필드를 기본으로 가진다.
* **KpiSummaryPanel**은 Program KPI와 모듈별 운영 지표를 카드형 요약으로 표시한다.
* **ExportColumnPicker**는 Excel 다운로드 전 컬럼 그룹, 마스킹 정책, 다운로드 사유를 선택하게 하며, Export 권한이 없는 사용자에게는 비활성 상태로 노출한다.

### 4.5 GuestTaskCard / MobileActionBar
* **GuestTaskCard**는 GUEST 포털의 오늘 할 일, 평가 제출, 예약 확인, 출석 체크, 상담일지 작성, 만족도 제출을 표시한다.
* **MobileActionBar**는 모바일 GUEST 화면 하단에 고정되는 주요 액션 영역이며, 한 화면에 하나의 핵심 제출/확정 액션만 강조한다.
