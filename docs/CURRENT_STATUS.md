## 4. 운영 차단 요소

### P0 — 파일럿 또는 운영 전에 해소·결정 필요

* **알림 실발송 부재**: `notifications-dispatch`의 채널별 실제 발송 어댑터가 스텁입니다. 게스트 인증번호·초대 안내·결재 알림이 실제로 발송되지 않으므로 GUEST의 정상 로그인 완료가 성립하지 않습니다.
* **품질 게이트 실패**: 타입 검사와 린트가 실패해 현재 커밋 후보를 안전한 배포 상태로 볼 수 없습니다.
* **운영 CORS 미확정**: 운영 도메인 확정 후 Supabase의 `ALLOWED_ORIGINS` 설정이 필요합니다. 현재 문서상 미설정 유예 모드입니다.
* **운영 DB 정합성 미확인**: 최신 마이그레이션이 운영 Supabase에 모두 반영되었는지, M&A·PROJECT 원장과 RLS 회귀가 통과했는지 확인이 필요합니다.
* **배포 게이트 분리**: CI와 Deploy가 `main` 푸시에 각각 실행되어 CI 실패가 배포를 자동 차단하지 않습니다.
* **작업 트리 혼재**: 제품 수정, 임시 스크립트(`m*.mjs`, `fix.mjs`, `e.mjs`), `hiworks_backup/`이 한 작업 트리에 섞여 있습니다. 삭제·커밋 전 소유자 확인과 민감정보 검토가 필요합니다.

### P1 — 안정화 단계에서 우선 처리

* **E2E 전략 부재**: 권한별 로그인, 사업 생성부터 GUEST 제출, 결재, 첨부파일과 다운로드 권한을 잇는 통합 테스트 기준이 없습니다.
* **관측성 부재**: 운영 오류, Edge Function 실패, 알림 실패, 프론트엔드 예외를 수집·알림하는 체계가 미정입니다.
* **첨부 보안 등급 미완료**: 민감 파일의 `security_grade`와 다운로드 사유 강제 설계가 남아 있습니다.
* **게시판 실연동 미완료**: 게시글·자료 일부가 인메모리 데모 저장소에 의존하고 부서 범위 권한이 미완료입니다.
* **핵심 도메인 후속 기능**: 거래처 상세, M&A 파이프라인·NDA·매칭, PROJECT 태스크·간트, 조직 KPI가 후속 범위입니다.

### P2 — 품질 개선 및 구조 정리

* **GUEST 디자인 시스템 잔여 편입**: 단일 입력과 배지 등 잔여 수제 UI를 공통 규격으로 이동해야 합니다.
* **구조적 부채**: 삭제된 HUB 명칭이 `features/hub` 폴더에 남아 있고, 일부 대형 컴포넌트·훅은 프로젝트의 파일 크기 가이드보다 큽니다.
* **데이터 조회 공통화**: 일부 목록 훅과 기여 로그 조회의 서버 페이지네이션·캐시 규칙 통합이 남아 있습니다.

## 5. 권장 작업 순서

1. **작업 트리 분류**: 사용자 변경, 임시 변환 스크립트, 백업 자료, 신규 마이그레이션을 서로 다른 변경 단위로 구분합니다.
2. **현재 품질 게이트 복구**: 타입 오류 2건, ESLint 규칙 누락, 루트 린트 대상 범위를 먼저 정리합니다.
3. **운영 사실 확인**: 운영 URL·담당자·Supabase 프로젝트·마이그레이션 적용 상태·AWS 자원·복구 이력을 확인합니다.
4. **GUEST 접근 방식 결정**: 알림 공급자를 연결하거나 파일럿 기간의 승인된 대체 인증 경로를 설계합니다.
5. **배포 안전장치 적용**: CI 성공 후에만 배포하고, 운영 승인과 smoke test를 추가합니다.
6. **핵심 E2E 및 RLS 검증**: 사용자 역할과 데이터 경계를 우선 보호합니다.
7. **후속 기능과 리팩터링**: P1 기능은 사업 우선순위로 선정하고, 구조 정리는 변경 빈도와 장애 위험이 높은 파일부터 수행합니다.
