# [3-3] NETWORKS (네트워크 관리) 워크스페이스 상세 기능 요건서

본 문서는 전사 외부 인물·조직 네트워크의 단일 원장인 NETWORKS의 현재 화면과 업무 규칙을 정의합니다. 스타트업 원장은 물리적으로 참조되지만 운영 화면은 STARTUP 워크스페이스로 분리하며, 투자·보육·발굴·기타 구분과 담당자 규칙은 [3_3_1_startup_pool_classification.md](./3_3_1_startup_pool_classification.md)가 소유합니다.

> [!IMPORTANT]
> 2026-07-31 현재 기본 진입은 `?tab=mine`입니다. `전체 네트워크(?tab=dashboard)`는 전면 재설계를 위해 제목만 남긴 골격이며, [3_3_2_networks_dashboard.md](./3_3_2_networks_dashboard.md)는 현재 화면 설명이 아니라 목표 기획입니다.

## 1. 정보 구조와 메뉴

### 1.1 내 네트워크 관리

로그인 사용자가 생성·편집·병합에 관여한 네트워크를 물리 원장 구분 없이 한 목록에 모읍니다.

* **기본 화면**: `/networks` 또는 `/networks?tab=mine`.
* **조회**: 이름·소속 검색, 서버 페이지네이션, 행 클릭 시 실제 원장 상세로 이동.
* **열**: 이름·소속·부서·직책/직급·이메일·연락처·구분의 공용 조직형 열.
* **제외 동작**: 어느 원장에 새로 등록할지 모호하므로 통합 목록에는 등록·비활성화 액션을 두지 않습니다.

기여 이력은 통합 목록을 만드는 조회 축일 뿐 수정 권한 축이 아닙니다.

### 1.2 전체 네트워크

`?tab=dashboard`는 `전체 네트워크` 제목만 렌더링합니다. 기존 규모 타일·분포·평가 랭킹·최근 등록 피드는 재설계 대기 상태이며, 필요한 집계 훅과 차트 부품만 재사용 후보로 보존합니다.

### 1.3 마스터 네트워크 8종

| 탭 | 원장 | 화면 형태 |
| :--- | :--- | :--- |
| `experts` | 전문가 | 인물형 전체 프로필 |
| `investors` | 투자사 | 인물형 전체 프로필 |
| `van` | BAN | 인물형 전체 프로필 |
| `exp` | EXP | 인물형 전체 프로필 |
| `corporates` | 기업 | 조직형 축약 프로필 |
| `institutions` | 기관 | 조직형 축약 프로필 |
| `universities` | 대학 | 조직형 축약 프로필 |
| `etc` | 기타 | 조직형 축약 프로필 |

모든 원장은 공용 목록·페이지형 상세·등록/편집 폼을 공유합니다. 상세 경로는 `/networks/:entity/:id`이며 `:id=new`은 등록 모드입니다.

* **인물형**: 구분·전문분야·활동·매칭 가능 여부·만족도·약력 등 전체 프로필을 사용합니다.
* **조직형**: 매칭·전문분야·약력·만족도를 숨기고 이름·소속·부서·직책·연락처 중심으로 단순화합니다.
* **하위 호환**: `vendors`와 `partners` 정의는 기존 링크/조회 호환을 위해 남기되 현재 사이드바·구분 선택지에는 노출하지 않습니다.

### 1.4 글로벌 네트워크

글로벌은 국내 8종과 테이블을 나누지 않는 독립 단일 원장(`global_networks`)입니다.

* **경로**: 목록 `/networks?tab=global`, 등록 `/networks/global/new`, 상세 `/networks/global/:id`.
* **주요 축**: 이름, 소속, 직책/직급, 이메일, 연락처, 링크드인, 권역, 국가, 구분.
* **구분**: 기업·기관·투자자 3값. 권역과 국가는 ADMIN 태그 원장을 참조합니다.

### 1.5 미분류 데이터베이스

`others`는 네트워크 카테고리가 아니라 분류 전 임시 저장소입니다.

* 목록의 구분 드롭다운에서 실제 8종 원장을 선택하면 해당 원장으로 이관합니다.
* 소속·이메일 도메인을 사용한 추천 구분은 보조값이며 자동 확정하지 않습니다.
* 상세·편집 구조는 조직형 축약 프로필과 같습니다.

### 1.6 대용량 업로드

사이드바의 `대용량 업로드` 한 화면 안에서 국내/글로벌 인페이지 탭을 전환합니다.

* 국내와 글로벌 패널을 동시에 마운트하고 숨김만 전환해, 탭을 오가도 업로드 파일·검증·리뷰 상태가 사라지지 않게 합니다.
* 파일 파싱 후 필수값·형식·중복을 검증하고 오류 행과 사유를 제시합니다.
* 검증이 끝난 행만 일괄 등록·보강하며, 서버 RPC와 각 원장 RLS가 최종 허용 여부를 판정합니다.

## 2. 목록·상세 공통 규칙

* **페이지 컨테이너**: 목록은 검색/필터/등록 액션을 위에 두고 공용 `DataTable`을 사용합니다. 상세가 있는 원장은 행 클릭으로 이동합니다.
* **민감정보**: 외부 인물 이름·이메일·연락처는 ADMIN 콘텐츠별 정책에 따라 목록에서 마스킹하며 상세/폼은 권한 확인 후 원본을 사용합니다.
* **생성자**: `created_by`는 누가 만들었는지를 기록할 뿐 권한을 주지 않습니다. 목록의 공용 표준 열에는 `생성자`로 표기하고, 관리 주체와 혼용하지 않습니다.
* **공동관리**: 국내 8종·글로벌·미분류에는 별도 담당자 원장이 없으며 NETWORKS 쓰기 권한자 공동관리입니다.
* **변동 이력**: 수정·이관·병합·비활성화는 DB 트리거가 기여 이력을 남깁니다. 클라이언트가 이력 테이블에 직접 INSERT하지 않습니다.
* **비활성화**: 물리 삭제 없이 `deleted_at` 소프트 삭제를 사용하고 사유를 기록합니다.

## 3. 등록·수정·병합 흐름

### 3.1 등록·수정

* 구분 선택이 저장 대상 원장을 결정합니다.
* 이름 등 핵심 식별 필드를 검증하고, 태그 필드는 ADMIN 기준정보를 선택합니다.
* 수정 저장 전 사유를 입력하며, 서버는 현재 원장 RLS와 기여 트리거 존재 여부를 검증합니다.

### 3.2 이관·병합

* 미분류 이관, 원장 간 재분류, 중복 병합은 각각의 RPC를 사용해 원본 변경과 이력 기록을 한 트랜잭션으로 처리합니다.
* 병합 후 중복 레코드는 `merged_into_id`와 소프트 삭제 상태를 남기며 정본 링크를 유지합니다.
* ADMIN 중복 병합 검증은 이 흐름의 운영 콘솔이며 프론트 허용 목록이 서버 권한을 대신하지 않습니다.

## 4. 전사 단일 원천(SSOT) 규칙

* AC 프로그램 참가자, FUND 투자기업, M&A/PROJECT 협력 대상은 네트워크 이름을 새 텍스트로 복제하지 않고 NETWORKS 식별자를 참조합니다.
* 스타트업의 투자·보육·발굴·기타 운영은 STARTUP 화면이 담당하지만 동일한 `startups` 원장을 사용합니다.
* 임직원은 NETWORKS가 아니라 MANAGEMENT의 `users`·조직 원장이 정본입니다.

## 5. 권한과 역할 구분

| 축 | 저장 | 역할 |
| :--- | :--- | :--- |
| 생성자 | 각 원장의 `created_by` | 최초 생성 기록. 권한 없음 |
| 공동관리 | 별도 담당자 행 없음 | NETWORKS 쓰기 권한자가 현재 정보를 관리 |
| 기여 이력 | `entity_contributions` | 누가 무엇을 바꿨는지 감사. 권한 판정에 사용하지 않음 |
| 관리자 | `super_admin` | 예외적 전역 우회 및 ADMIN 운영 기능 |

생성자를 교체해야 하는 경우 일반 편집 폼이 아니라 ADMIN `생성자 교체`를 사용하고 사유와 감사 로그를 남깁니다.

## 6. 테스트 기준

* 탭 없이 `/networks`에 들어가면 `내 네트워크 관리`가 열립니다.
* 8종 원장·미분류·글로벌 목록에서 행 클릭 시 올바른 상세 경로로 이동합니다.
* 미분류 이관 후 원본 목록에서 빠지고 대상 원장에서 같은 식별 정보로 조회됩니다.
* 국내/글로벌 업로드 탭을 전환해도 진행 중 파일·리뷰 상태가 유지됩니다.
* `dashboard`는 제목 외 임의의 샘플 KPI를 표시하지 않습니다.
* NETWORKS 쓰기 권한이 없는 사용자는 화면을 숨기는 것과 무관하게 서버에서 쓰기가 거부됩니다.
