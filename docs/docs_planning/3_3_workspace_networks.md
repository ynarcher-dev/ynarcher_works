# [3-3] NETWORKS (네트워크 관리) 워크스페이스 상세 기능 요건서

본 문서는 전사 외부 인물·조직 네트워크의 단일 원장인 NETWORKS의 현재 화면과 업무 규칙을 정의합니다. 스타트업 원장은 물리적으로 참조되지만 운영 화면은 STARTUP 워크스페이스로 분리하며, 투자·보육·발굴·기타 구분과 담당자 규칙은 [3_3_1_startup_pool_classification.md](./3_3_1_startup_pool_classification.md)가 소유합니다.

> [!IMPORTANT]
> 2026-09-04 원장 통합으로 네트워크는 **단일 원장 `public.networks`** 하나이며, 구분(카테고리)과 국가가 직교한 두 축입니다. 사이드바는 **`네트워크 DB` 한 줄**이고(2026-09-05 범위 두 줄 통합) 범위는 목록 상단의 토글(`내 관리`/`전체 관리`)이 정하며 기본은 `내 관리`입니다(2026-09-04 '미분류 데이터베이스' 메뉴 폐지 — 구분 미지정은 목록 필터의 `미지정` 선택지가 답합니다). 구조·이관·다형 키 규칙의 정본은 [3_3_4_networks_unified_ledger.md](./3_3_4_networks_unified_ledger.md)이며, 아래 1절은 그 결과의 화면 요건입니다. [3_3_2_networks_dashboard.md](./3_3_2_networks_dashboard.md)는 현재 화면 설명이 아니라 목표 기획입니다.

## 1. 정보 구조와 메뉴

메뉴는 **`네트워크 DB` 한 줄**이며 탭 키가 없습니다. 범위(내가 관여한 것인가, 볼 수 있는 전부인가)는 메뉴가 아니라 목록 상단의 **범위 토글**이 답하고, 구분·국가와 마찬가지로 목록의 한 축입니다.

| 범위 | 주소 | 화면 | 조회 |
| :--- | :--- | :--- | :--- |
| 내 관리(기본) | `/networks` | 통합 목록 | `my_network_entities()` |
| 전체 관리 | `/networks?scope=all` | 통합 목록 | `all_network_entities()` |

옛 주소(`?tab=mine`·`?tab=all`·`?tab=others` 등)로 들어오면 이 화면으로 바로잡습니다 — `?tab=mine`은 `내 관리`, 나머지는 `전체 관리`입니다.

### 1.1 통합 목록 (범위 토글: 내 관리 · 전체 관리)

원장 하나(`public.networks`)를 한 목록으로 봅니다. 두 범위는 같은 화면을 쓰고 **담기는 범위 하나로만** 갈립니다 — '내 관리'는 로그인 사용자가 생성자(`created_by`)이거나 기여자(`entity_contributions`)인 건, '전체 관리'는 볼 수 있는 전부입니다. NETWORKS는 담당자 축이 없는 공동 관리 모델이므로 기여 이력이 담당자 축을 대신하며, 기여 이력은 조회 축일 뿐 수정 권한 축이 아닙니다.

* **경로**: `/networks`(=내 관리), `/networks?scope=all`.
* **범위 토글**: 액션 줄 왼쪽(`대용량 업로드` 버튼 좌측)의 세그먼트 토글입니다. 배타 선택이라 칩이 아니라 세그먼트를 쓰고, 전환해도 검색어·필터는 유지하며 페이지 번호만 첫 장으로 되돌립니다. 민감정보 정책 키는 범위별로 유지합니다(`networks.mine`/`networks.all`).
* **열**: 이름·소속·직책/직급·이메일·연락처·링크드인·구분·국가·영역·활동·만족도·매칭. 조직형(기업·기관·대학·기타)은 영역·활동·만족도·매칭을 채우지 않으므로 그 칸이 `-`로 남습니다. 열을 구분별로 갈면 통합 목록이 성립하지 않으므로, **열은 세우고 값을 비웁니다.**
* **국가 열**: 한국이면 `한국`, 해외면 그 국가명. 국가를 모르는 옛 행만 `국내`/`해외`로 물러섭니다.
* **필터**: 구분(8종 + `미지정`) · 지역(국내/해외/국가 미확인) · 권역 · 국가 · 영역 · 활동 · 매칭. 권역·국가는 지역이 해외를 포함할 때만 섭니다. 구분과 `미지정`은 서버에서 한 축으로 OR 판정되므로 `투자사 + 미지정`이 두 집합의 합으로 나옵니다.
* **등록**: 목록 상단 `신규 등록` 버튼이 구분을 되묻지 않고 곧장 작성 화면(`/networks/record/new`)으로 갑니다 — 원장이 하나라 고를 것이 없고, 구분은 그 폼의 한 칸이며 기본값은 `미지정`입니다.
* **비활성화**: 사유·영향 확인이 필요하므로 목록이 아니라 상세에서 수행합니다.
* **행 클릭**: `/networks/record/:id`로 이동합니다.

### 1.2 구분 8종의 성격

| 구분 코드 | 라벨 | 화면 형태 |
| :--- | :--- | :--- |
| `experts` | 전문가 | 인물형 전체 프로필 |
| `investors` | 투자사 | 인물형 전체 프로필 |
| `van` | BAN | 인물형 전체 프로필 |
| `exp` | EXP | 인물형 전체 프로필 |
| `corporates` | 기업 | 조직형 축약 프로필 |
| `institutions` | 기관 | 조직형 축약 프로필 |
| `universities` | 대학 | 조직형 축약 프로필 |
| `etc` | 기타 | 조직형 축약 프로필 |

구분은 저장 대상 원장이 아니라 **한 컬럼의 값**입니다. 상세 경로는 `/networks/record/:id`이며 `:id=new`가 등록 모드입니다.

* **인물형**: 구분·전문영역·활동·매칭 가능 여부·만족도 등 전체 프로필을 사용합니다.
* **조직형**: 매칭·전문영역·만족도를 숨기고 이름·소속·부서·직책·연락처 중심으로 단순화합니다.
* **하위 호환**: 은퇴한 `vendors`(외주/거래) 값은 목록에 계속 담기지만 구분 선택지에는 노출하지 않습니다. `partners`는 이번 통합 대상이 아니며 어느 목록에도 서지 않습니다.

### 1.3 국가와 지역

지역을 답하는 것은 **국가 하나**입니다. 담당자는 국가만 고르고, 국내/해외는 그 국가가 자국인지(`country_tags.is_domestic`)에서 서버가 파생합니다.

* **한국도 국가로 명시합니다** — 칸이 비어 있으면 표가 "한국인가, 아직 안 넣었는가"를 답하지 못합니다.
* **드롭다운 순서**: `선택` → `한국` → 구분선 → 나머지 국가(가나다순). 자국을 위로 빼는 이유는 분류가 달라서가 아니라 가장 자주 쓰기 때문입니다.
* **권역**(북미·동남아 등)은 레코드에 저장하지 않습니다 — 국가가 이미 알고 있으므로 조인해 읽으며, 목록에서는 필터 축과 권역별 현황 카드에만 씁니다.
* **국가는 신규 등록에서 필수**입니다. 국가를 모르는 옛 행은 목록의 `국가 미확인` 축에 모여 있으며, 다 채운 뒤 원장에서 잠급니다.

### 1.5 구분 미지정 (분류 대기)

구분이 비어 있는 행(`category is null`)은 별도 원장도 별도 메뉴도 아니라 **값이 비어 있는 상태**이며, 통합 목록의 구분 필터에서 `미지정`을 걸어 찾습니다(2026-09-04 전용 메뉴 폐지).

* 상세에서 구분을 고치면 **행 이동이 아니라 그 칸의 수정**이며 id가 바뀌지 않습니다 — 그 레코드에 붙은 자료·피드백·회의록 링크가 그대로 남습니다.
* 여러 건이 한꺼번에 들어오는 경로에서는 구분이 비지 않습니다 — 회의록 간이 등록은 구분이 필수이고, 대용량 업로드는 빈 구분이 남아 있으면 업로드가 막힙니다. **신규 등록 폼 한 곳만 구분이 선택이며 기본값이 '미지정'입니다**(2026-09-05) — 한 건을 손으로 넣는 자리는 이름만 아는 채로 들어오는 일이 있어, 등록을 막는 대신 미지정으로 받고 목록 구분 필터로 다시 찾아 채웁니다.
* 소속·이메일 도메인을 사용한 추천 구분은 업로드 리뷰의 출발점일 뿐 자동 확정하지 않습니다.
* 상세·편집 구조는 조직형 축약 프로필과 같습니다.

### 1.6 대용량 업로드

목록 상단 `대용량 업로드` 버튼(`/networks/bulk`)으로 진입하는 임포터 한 벌입니다.

* 파일 파싱 후 필수값·형식·중복을 검증하고 오류 행과 사유를 제시합니다.
* 국가는 이름으로 올라와 태그 원장과 대조해 id로 바뀌며, 못 찾은 값은 행을 버리지 않고 '미확인'으로 남습니다.
* 중복이 있으면 합치기(제자리 보강)로 처리하며, 구분·국가가 바뀌었으면 같은 보강에 함께 실립니다.
* 검증이 끝난 행만 일괄 등록·보강하며, 서버 RPC와 원장 RLS가 최종 허용 여부를 판정합니다.

## 2. 목록·상세 공통 규칙

* **페이지 컨테이너**: 목록은 검색/필터/등록 액션을 위에 두고 공용 `DataTable`을 사용합니다. 상세가 있는 원장은 행 클릭으로 이동합니다.
* **민감정보**: 외부 인물 이름·이메일·연락처는 ADMIN 콘텐츠별 정책에 따라 목록에서 마스킹하며 상세/폼은 권한 확인 후 원본을 사용합니다.
* **생성자**: `created_by`는 누가 만들었는지를 기록할 뿐 권한을 주지 않습니다. 목록의 공용 표준 열에는 `생성자`로 표기하고, 관리 주체와 혼용하지 않습니다.
* **공동관리**: 네트워크 원장에는 별도 담당자 원장이 없으며 NETWORKS 쓰기 권한자 공동관리입니다.
* **변동 이력**: 수정·이관·병합·비활성화는 DB 트리거가 기여 이력을 남깁니다. 클라이언트가 이력 테이블에 직접 INSERT하지 않습니다.
* **비활성화**: 물리 삭제 없이 `deleted_at` 소프트 삭제를 사용하고 사유를 기록합니다.

## 3. 등록·수정·병합 흐름

### 3.1 등록·수정

* 구분과 국가를 고릅니다 — 구분은 한 컬럼의 값이고, 국가는 지역(국내/해외)의 유일한 원천입니다.
* 이름 등 핵심 식별 필드를 검증하고, 태그 필드는 ADMIN 기준정보를 선택합니다.
* 수정 저장 전 사유를 입력하며, 서버는 현재 원장 RLS와 기여 트리거 존재 여부를 검증합니다.

### 3.2 이관·병합

* 구분 지정·변경은 한 칸의 수정이며(`update_entity` RPC), 중복 병합은 `merge_entity` RPC가 원본 변경과 이력 기록을 한 트랜잭션으로 처리합니다.
* 병합 후 중복 레코드는 `merged_into_id`와 소프트 삭제 상태를 남기며 정본 링크를 유지합니다.
* ADMIN 중복 병합 검증은 이 흐름의 운영 콘솔이며 프론트 허용 목록이 서버 권한을 대신하지 않습니다.

## 4. 전사 단일 원천(SSOT) 규칙

* AC 프로그램 참가자, FUND 투자기업, M&A/PROJECT 협력 대상은 네트워크 이름을 새 텍스트로 복제하지 않고 NETWORKS 식별자를 참조합니다.
* 스타트업의 투자·보육·발굴·기타 운영은 STARTUP 화면이 담당하지만 동일한 `startups` 원장을 사용합니다.
* 임직원은 NETWORKS가 아니라 MANAGEMENT의 `users`·조직 원장이 정본입니다.

## 5. 권한과 역할 구분

| 축 | 저장 | 역할 |
| :--- | :--- | :--- |
| 생성자 | 각 원장의 `created_by` | 최초 생성 기록. 권한 없음 |
| 공동관리 | 별도 담당자 행 없음 | NETWORKS 쓰기 권한자가 현재 정보를 관리 |
| 기여 이력 | `entity_contributions` | 누가 무엇을 바꿨는지 감사. 권한 판정에 사용하지 않음 |
| 관리자 | `super_admin` | 예외적 전역 우회 및 ADMIN 운영 기능 |

생성자를 교체해야 하는 경우 일반 편집 폼이 아니라 ADMIN `생성자 교체`를 사용하고 사유와 감사 로그를 남깁니다.

## 6. 테스트 기준

* 주소 없이 `/networks`에 들어가면 `내 관리` 범위가 열리고, 토글로 `전체 관리`를 고르면 주소가 `?scope=all`이 되며 걸어 둔 검색어·필터는 그대로 남습니다.
* 목록에서 행 클릭 시 `/networks/record/:id`로 이동하며, 옛 경로(`/networks/experts/:id`·`/networks/global/:id`)도 같은 레코드를 엽니다.
* 구분 필터에서 `미지정`을 걸면 구분이 비어 있는 행만 서고, 상세에서 구분을 지정하면 그 목록에서 빠지며 id는 바뀌지 않습니다.
* 구분이 비어 있는 행이 있는 CSV는 최종 업로드가 잠깁니다.
* 해외 국가 + 구분 `대학` 조합이 등록·조회됩니다(통합 이전에는 불가능했습니다).
* `dashboard`는 제목 외 임의의 샘플 KPI를 표시하지 않습니다.
* NETWORKS 쓰기 권한이 없는 사용자는 화면을 숨기는 것과 무관하게 서버에서 쓰기가 거부됩니다.
