# [3-7-3] MANAGEMENT 근태 관리 기획서

본 문서는 MANAGEMENT 워크스페이스 `근태 관리`(`/management?tab=attendance`) 화면과, 그 원장에 기록을 남기는 OFFICE 대시보드 `근무체크` 위젯의 데이터 모델·기능 요건을 명세합니다. 상위 워크스페이스 기획은 [3_7_workspace_management.md](./3_7_workspace_management.md), 대시보드 구성은 [3_1_workspace_hub.md](./3_1_workspace_hub.md)가 소유합니다.

> [!NOTE]
> **구현 상태(2026-08-03)**: 원장 4종·RLS·상태 시드·RPC 5종 마이그레이션(`20260803190000_attendance.sql`)과 화면 전체(MANAGEMENT `근태 관리` 일간/월간·수정 모달·설정 모달, OFFICE 대시보드 `근무체크` 위젯)가 구현되어 있습니다. 근무일 판정과 정책 해석은 화면이 아니라 조회 RPC(`attendance_board`/`attendance_month`)가 붙여 줍니다. 전자결재 휴가 연동·공휴일 원장·월말 마감·Export는 §12 후속입니다.

---

## 1. 목적

* **찍는 자리와 고치는 자리를 나눕니다**: 임직원은 대시보드 `근무체크`에서 출근·퇴근을 찍기만 하고, 그 기록을 판독·정정하는 권한은 MANAGEMENT `근태 관리` 한 곳이 갖습니다. 같은 원장을 두 화면이 다른 권한으로 다룹니다.
* **판정 기준을 코드가 아니라 원장에 둡니다**: "몇 시까지 찍으면 정상인가", "몇 시간을 채워야 퇴근인가"는 회사가 바꾸는 값이지 개발자가 바꾸는 값이 아닙니다. 기준을 `근태 설정`의 근무 정책 원장에 두고, 사람마다 다른 근무제는 임직원별 예외로 표현합니다.
* **자동 판정과 관리자 판단을 둘 다 남깁니다**: 규칙이 매긴 상태(`지각`)와 관리자가 확정한 상태(`외부근무 승인`, `연차`)는 다른 값입니다. 둘을 같은 칸에 덮어쓰면 "원래 몇 시에 찍혔는가"가 사라지므로 자동 판정값을 따로 보존합니다.
* **정정에는 사유를 남깁니다**: 근태는 급여·평가로 이어지는 기록이라 "누가, 무엇을, 무엇으로, 왜 고쳤는가"가 남아야 합니다.

---

## 2. 이 문서가 다루는 범위

* **포함**:
  * 근무 정책 원장(`attendance_policies`) — 출근 가능 시간대, 소정 근무시간, 근무 요일, 임직원별 예외
  * 근태 상태 원장(`attendance_statuses`) — 시스템 판정 상태 5종 + 관리자가 늘리는 휴가류
  * 일별 근태 원장(`attendance_days`)과 정정 이력(`attendance_edits`)
  * 자동 판정 규칙(지각·조기퇴근·결근)과 관리자 수정 규칙
  * MANAGEMENT `근태 관리` 화면(날짜별 일간 / 인력별 월간)과 `근태 설정` 모달
  * OFFICE 대시보드 `근무체크` 위젯의 동작과 출퇴근 RPC
  * 권한·RLS 및 마이그레이션 설계
* **제외(별도 범위)**:
  * **휴가 신청·승인 흐름** — 연차 신청은 전자결재(OFFICE)의 문서이며, 승인 결과를 근태 상태로 자동 반영하는 연동은 §12 후속입니다. 본 문서는 관리자가 근태 화면에서 상태를 `연차`로 지정하는 것까지를 다룹니다.
  * **연차 잔여일수 산정** — 발생·사용·소멸 계산은 근태 원장이 아니라 별도 휴가 원장의 일입니다.
  * **급여 계산** — 근무시간 합계를 제공할 뿐 급여액을 산출하지 않습니다.
  * **초과근무·야간·휴일 가산** — 소정 근무시간을 넘긴 시간은 집계로만 보여주고 수당 규칙을 두지 않습니다.
  * **GPS·비콘·IP 기반 출근 검증** — 근무지(사내/외부)는 본인이 고르는 값이며 위치를 검증하지 않습니다.

---

## 3. 핵심 사용자

* **임직원 (모든 내부 사용자)**: 대시보드에서 자기 출근·퇴근을 찍고 자기 기록만 봅니다. 남의 근태를 보거나 자기 상태를 고칠 수 없습니다.
* **근태 담당자 (`management` write)**: 날짜별 전 직원 근태를 조회하고 상태·시각을 정정하며, 근무 정책과 상태 원장을 세팅합니다.
* **경영지원 조회자 (`management` read)**: 근태 현황을 조회합니다. 정정하지 않습니다.
* **외부 게스트**: 접근하지 않습니다. 근태는 내부 임직원 전용 원장입니다.

---

## 4. 정보 구조 (Information Architecture)

`근태 관리` 탭은 **날짜별 일간 뷰**를 기본으로 하고, 임직원 이름을 누르면 같은 화면이 **인력별 월간 뷰**로 축을 바꿉니다. 메뉴를 둘로 쪼개지 않는 이유는 두 뷰가 같은 원장을 다른 각도로 자르는 것일 뿐이기 때문입니다.

```
[근태 관리]
 ├── 상단: ◀ 2026-08-03 (월) ▶  [오늘]            [근태 설정]
 ├── 요약 타일: 정상 · 지각 · 외부근무 · 휴가 · 미출근
 └── 일간 표 (그날의 전 임직원 한 줄씩)
      ├── 열: 이름 · 소속 · 근무지 · 출근 · 퇴근 · 근무시간 · 상태(배지) · 비고
      ├── 이름 클릭 → 인력별 월간 뷰
      └── 행 클릭 → 근태 수정 모달

[인력별 월간 뷰]  ◀ 2026년 8월 ▶   [← 일간으로]
 ├── 인물 요약: 사진 · 이름 · 소속 · 근무일수 / 지각 / 휴가 / 총 근무시간
 └── 월간 표 (1일~말일 한 줄씩, 열 구성은 일간 표와 동일 + 요일)
```

> [!NOTE]
> **미출근은 행이 없는 상태입니다.** 아직 찍지 않은 사람은 근태 원장에 행이 없으며, 일간 표는 임직원 명부를 기준으로 줄을 세우고 없는 행을 `미출근`으로 그립니다. 없는 행을 밤마다 만들어 두는 배치를 두지 않는 이유는 §6.3에 적습니다.

## 5. 데이터 모델

### 5.1 근무 정책 (`public.attendance_policies`)

| 화면 항목 | 컬럼 | 타입 | 필수 | 설명 |
| :--- | :--- | :--- | :---: | :--- |
| 적용 대상 | `user_id` | `uuid` → `users(id)` | | `NULL`이면 전사 기본. 값이 있으면 그 임직원 전용 예외 |
| 출근 가능 시작 | `check_in_from` | `time` | O | 이 시각 이전에는 출근을 찍을 수 없습니다. 기본 `07:00` |
| 출근 마감 | `check_in_to` | `time` | O | **지각 판정선**. 이 시각을 넘겨 찍으면 지각입니다. 기본 `09:00` |
| 소정 근무시간 | `work_minutes` | `integer` | O | 출근 시각으로부터 이 시간이 지나야 정상 퇴근입니다(휴게 포함). 기본 `540`(9시간) |
| 근무 요일 | `workdays` | `smallint[]` | O | `0`=일 ~ `6`=토. 기본 `{1,2,3,4,5}` |
| 외부근무 허용 | `allow_external` | `boolean` | O | 끄면 근무체크에 근무지 선택이 뜨지 않습니다. 기본 `true` |
| 적용 시작일 | `effective_from` | `date` | O | 이 날짜부터 적용. 기준을 바꿔도 과거 판정이 흔들리지 않게 합니다 |
| 비고 | `note` | `text` | | |
| 비활성 | `deleted_at` | `timestamptz` | | soft delete |

* **적용 정책을 고르는 규칙은 하나입니다**: 그 날짜에 대해 `user_id`가 일치하고 `effective_from <= 날짜`인 것 중 가장 최근 행, 없으면 `user_id IS NULL`(전사 기본) 중 가장 최근 행입니다.
* **제약**: `check_in_from < check_in_to`, `work_minutes between 60 and 1440`, `workdays`는 0~6 범위이며 비어 있지 않습니다.
* **`퇴근 마감`을 두지 않습니다**: 퇴근 시각은 출근 시각 + 소정 근무시간으로 사람마다 다르게 정해지므로, 고정 퇴근 시각을 따로 두면 두 기준이 서로 어긋납니다.

### 5.2 근태 상태 (`public.attendance_statuses`)

상태 값을 코드에 박지 않고 원장으로 두는 이유는, 회사가 쓰는 휴가 종류가 늘어나는 것이 정상이기 때문입니다.

| 컬럼 | 타입 | 설명 |
| :--- | :--- | :--- |
| `code` | `text` PK | `UPPER_SNAKE_CASE` |
| `label` | `text` | 화면 표기 |
| `tone` | `text` | 배지 톤(`success`/`warning`/`danger`/`info`/`neutral`) |
| `kind` | `text` | `WORK`(근무) / `LEAVE`(휴가) / `ABSENT`(결근) |
| `is_system` | `boolean` | 규칙이 자동으로 매기는 상태. 삭제·코드 변경 불가, 라벨·톤만 수정 가능 |
| `is_paid` | `boolean` | 유급 여부. 집계용 |
| `sort_order` | `integer` | 셀렉트·범례 순서 |
| `is_active` | `boolean` | 끄면 새로 고를 수 없되 기존 기록은 유지 |

**시스템 상태 5종(시드, 자동 판정 결과)**

| 코드 | 라벨 | 톤 | kind | 의미 |
| :--- | :--- | :--- | :--- | :--- |
| `NORMAL` | 정상 | success | WORK | 마감 시각 안에 출근하고 소정 시간을 채운 날 |
| `LATE` | 지각 | warning | WORK | 출근 마감을 넘겨 찍은 날 |
| `EARLY_LEAVE` | 조기퇴근 | warning | WORK | 소정 시간을 채우기 전에 퇴근한 날 |
| `LATE_EARLY` | 지각·조기퇴근 | danger | WORK | 둘 다 해당하는 날 |
| `ABSENT` | 결근 | danger | ABSENT | 근무일인데 출근 기록이 없는 날 |

> [!NOTE]
> **지각과 조기퇴근을 별도 플래그 두 개로 나누지 않고 조합 상태 하나를 더 둡니다.** 관리자가 고치는 단위가 "이 사람의 그날 상태"라는 한 값이기 때문입니다. 플래그로 나누면 수정 화면이 체크박스 두 개가 되어, "지각을 연차로 바꾼다"는 한 동작이 두 필드를 건드리는 일이 됩니다. 조합이 이 하나뿐이라 값이 늘어나지도 않습니다.

**관리자 지정 상태(시드, 그대로 쓰거나 늘립니다)**: `LEAVE_ANNUAL` 연차 · `LEAVE_HALF` 반차 · `LEAVE_SICK` 병가 · `LEAVE_OFFICIAL` 공가(모두 `kind=LEAVE`), `HOLIDAY` 휴일(`kind=WORK`, 무급 아님).

### 5.3 일별 근태 (`public.attendance_days`)

| 화면 항목 | 컬럼 | 타입 | 필수 | 설명 |
| :--- | :--- | :--- | :---: | :--- |
| 임직원 | `user_id` | `uuid` → `users(id)` | O | |
| 날짜 | `work_date` | `date` | O | `(user_id, work_date)` 유니크 |
| 근무지 | `work_place` | `public.attendance_place` | O | `INTERNAL`(사내) / `EXTERNAL`(외부근무). 기본 `INTERNAL` |
| 출근 | `check_in_at` | `timestamptz` | | **서버 시각**으로 기록 |
| 퇴근 | `check_out_at` | `timestamptz` | | |
| 상태 | `status_code` | `text` → `attendance_statuses` | O | 화면에 보이는 확정 상태 |
| 자동 판정 | `auto_status_code` | `text` → `attendance_statuses` | | 규칙이 매긴 원본. `status_code`와 다르면 표에 `수정됨` 표식 |
| 기준 스냅샷 | `policy_check_in_to` | `time` | O | 그날 판정에 쓴 출근 마감 |
| 기준 스냅샷 | `policy_work_minutes` | `integer` | O | 그날 판정에 쓴 소정 근무시간 |
| 비고 | `note` | `text` | | |
| 비활성 | `deleted_at` | `timestamptz` | | soft delete |

* **기준을 행에 복사해 두는 이유**: 정책은 앞으로를 위해 바꾸는 값인데, 기록은 그날의 기준으로 읽혀야 합니다. 스냅샷이 없으면 오늘 출근 마감을 09:30으로 늦추는 순간 작년 지각이 전부 정상으로 바뀝니다.
* **근무시간은 저장하지 않습니다**: `check_out_at - check_in_at`으로 언제든 같은 값이 나오는 파생값이라, 저장하면 두 값이 어긋날 자리만 생깁니다.
* **제약**: `check_out_at >= check_in_at`, 퇴근만 있고 출근이 없는 행은 만들 수 없습니다.

### 5.4 정정 이력 (`public.attendance_edits`)

`attendance_day_id` · `edited_by` · `edited_at` · `field`(`status`/`check_in_at`/`check_out_at`/`work_place`/`note`) · `before_value` · `after_value` · `reason`(**필수**). 추가만 가능하며 UPDATE·DELETE 정책을 두지 않습니다.

> [!NOTE]
> **공용 기여 로그(`entity_contributions`)를 쓰지 않습니다.** 기여 로그는 "누가 이 레코드에 관여했는가"를 남기는 서술이라 이전값·이후값 칸이 없고, SELECT 정책이 워크스페이스 단위여서 개인 근태 정정 사유가 다른 원장의 변동 이력 패널에 섞여 보일 수 있습니다. 근태 정정은 값 이력 자체가 목적이므로 전용 원장을 둡니다.

## 6. 자동 판정 규칙

### 6.1 출근을 찍을 때

1. 오늘이 적용 정책의 `workdays`에 없으면 근무체크 버튼을 비활성화하고 안내합니다(휴일 근무는 관리자가 뒤에 기록합니다).
2. 현재 시각이 `check_in_from` 이전이면 찍을 수 없습니다.
3. `check_in_to`를 넘겼으면 `LATE`, 아니면 `NORMAL`로 `auto_status_code`를 매기고 `status_code`에 같은 값을 넣습니다.
4. 판정에 쓴 `check_in_to`·`work_minutes`를 행에 복사합니다.

### 6.2 퇴근을 찍을 때

* `check_out_at < check_in_at + work_minutes`면 조기퇴근입니다. 이때 이미 `LATE`였다면 `LATE_EARLY`, 아니면 `EARLY_LEAVE`가 됩니다.
* **퇴근 버튼을 막지 않습니다**: 실제로 일찍 나가야 하는 날이 있으므로 차단하지 않고 기록합니다. 대신 위젯이 정상 퇴근까지 남은 시간을 보여주고, 그 전에 누르면 조기퇴근으로 남는다는 확인을 한 번 받습니다.
* **관리자가 이미 상태를 고친 날은 자동 판정이 덮어쓰지 않습니다**: `status_code != auto_status_code`인 행에는 규칙을 다시 적용하지 않습니다.

### 6.3 결근

* **행이 없는 것을 조회 시점에 결근으로 그립니다**. 근무일이고 날짜가 이미 지났는데 행이 없으면 일간 표가 `결근`으로 표시하며, 관리자가 그 칸을 눌러 `연차` 등으로 바꾸는 순간 실제 행이 만들어집니다.
* **밤마다 빈 행을 만드는 배치를 두지 않습니다**: 배치가 하루 걸러 실패하면 그날만 조용히 비고, 그 사실은 아무 데도 남지 않습니다. 조회 시점 파생은 언제 열어도 같은 답을 줍니다. 월말 마감처럼 확정 스냅샷이 필요해지면 그때 배치를 후속으로 도입합니다.

## 7. 화면 사양

### 7.1 일간 표

* **줄의 기준은 임직원 명부입니다**: 활성 임직원 전원이 한 줄씩 서고, 그날 기록이 없으면 상태만 `미출근`(오늘) 또는 `결근`(지난 날)으로 그립니다.
* **열**: `이름`(식별 열) · `소속` · `근무지`(사내/외부 배지) · `출근` · `퇴근` · `근무시간` · `상태`(배지) · `비고`. 표준 메타 열 중 생성자는 끄고 수정일도 두지 않습니다 — 이 표에서 알아야 하는 시각은 출근·퇴근이며, 정정 시각은 수정 모달의 이력이 답합니다.
* **수정된 행 표식**: `status_code != auto_status_code`인 행은 상태 배지 옆에 `수정됨` 말머리를 붙이고, 툴팁에 자동 판정값을 적습니다.
* **정렬**: 소속·이름 오름차순. 미출근을 위로 올리지 않습니다 — 명부 순서가 흔들리면 사람을 눈으로 찾을 수 없습니다.
* **요약 타일**: 정상 · 지각 · 외부근무 · 휴가 · 미출근 건수. 타일을 누르면 표가 그 상태로 걸러집니다.

### 7.2 월간 뷰

* 인물 요약(사진·이름·소속)과 그달 집계(근무일수 / 지각 / 휴가 / 총 근무시간)를 먼저 세우고, 1일부터 말일까지 한 줄씩 그립니다.
* 근무일이 아닌 날은 회색 줄로 두고 상태 칸을 비웁니다.
* 일간 뷰와 같은 수정 모달을 씁니다.

### 7.3 근태 수정 모달

```
[근태 수정 — 홍길동 / 2026-08-03 (월)]
 ├── 근무지 (사내 / 외부근무)
 ├── 출근 시각 | 퇴근 시각
 ├── 상태 (셀렉트 — 상태 원장 활성값)      자동 판정: 지각
 ├── 사유 (필수)
 ├── 비고
 ├── ── 정정 이력 ──
 │     2026-08-03 14:20  김담당  상태  지각 → 연차  "오전 반차 결재 승인"
 └── 푸터: [취소] [저장]
```

* **사유 없이 저장할 수 없습니다**: 빈 값이면 저장 버튼이 비활성입니다. DB의 `not null`이 최종 판정입니다.
* **자동 판정값은 읽기 전용으로 옆에 둡니다**: 무엇을 무엇으로 바꾸는지 보이지 않으면 정정이 아니라 입력이 됩니다.
* **여러 필드를 한 번에 고쳐도 이력은 필드별로 남깁니다**: 사유는 같은 문장을 공유합니다.

### 7.4 근태 설정 모달

```
[근태 설정]
 ├── [근무 기준] 탭
 │     ── 전사 기본 ──
 │     출근 가능 시간   [07:00] ~ [09:00]   ← 뒤 값을 넘기면 지각
 │     소정 근무시간    [9] 시간            → 퇴근 가능 시각 = 출근 + 9시간
 │     근무 요일        [월][화][수][목][금][토][일]
 │     외부근무 허용    [토글]
 │     적용 시작일      [2026-08-01]
 │     ── 임직원별 예외 ──  [예외 추가]
 │     홍길동  10:00~11:00 · 8시간 · 월~금            [수정] [삭제]
 └── [근태 상태] 탭
       정상 · 지각 · 조기퇴근 · 지각·조기퇴근 · 결근   (시스템 — 라벨/톤만 수정)
       연차 · 반차 · 병가 · 공가 · 휴일               [상태 추가]
```

* **설정을 별도 사이드바 메뉴로 만들지 않습니다**: 목록이 주인공이고 기준은 가끔 여는 값이라, 자산 관리와 같은 구조로 화면 상단 액션에 둡니다.
* **기준을 바꿔도 과거는 그대로입니다**: 저장 시 `effective_from`을 새로 잡아 행을 추가하며, 기존 행을 고치지 않습니다.

### 7.5 OFFICE 대시보드 `근무체크` 위젯

```
[근무체크]
 8월 3일 (월)
 13:48:26   [외부 근무중]                    ∧
 ──────────────────────────────────────────
   ⤵ 출근하기          ⤴ 퇴근하기
     09:45:54             00:00:00
```

* **초 단위 시계**를 돌리고, 오늘 행이 있으면 찍힌 시각을 버튼 아래에 적습니다.
* **버튼은 둘뿐입니다**: 출근하기 · 퇴근하기. 참고 화면에 있던 `업무`·`외출`·`회의`·`외근`·`조퇴`는 두지 않습니다 — 이 값들은 근태 상태가 아니라 일과의 분류이고, 근태 원장이 답해야 하는 질문(제때 왔는가, 얼마나 일했는가)에 기여하지 않습니다.
* **근무지는 출근할 때 고릅니다**: 사내/외부근무 선택은 출근 버튼에 붙은 선택이며, 외부근무로 찍은 날은 상단에 `외부 근무중` 배지가 뜹니다. 정책의 `allow_external`이 꺼져 있으면 선택 자체가 없습니다.
* **찍은 뒤에는 되돌릴 수 없습니다**: 잘못 찍은 기록은 본인이 지우는 것이 아니라 근태 담당자가 사유와 함께 정정합니다.
* **시각은 서버가 정합니다**: 클라이언트 시계를 신뢰하지 않으며 RPC 안에서 `now()`로 기록합니다.

## 8. 서버 액션 (RPC)

| RPC | 보안 | 하는 일 |
| :--- | :--- | :--- |
| `public.attendance_check_in(p_place)` | `SECURITY DEFINER` | 본인 오늘 행을 만들고 `check_in_at`을 서버 시각으로 채운 뒤 자동 판정·기준 스냅샷을 씁니다. 이미 찍었으면 오류 |
| `public.attendance_check_out()` | `SECURITY DEFINER` | 본인 오늘 행의 `check_out_at`을 채우고 상태를 다시 판정합니다. 출근 기록이 없으면 오류 |
| `public.set_attendance_record(p_day_id, ...)` | `SECURITY INVOKER` | 관리자 정정. 원장 UPDATE와 `attendance_edits` INSERT를 한 트랜잭션에 묶고, 사유가 비면 거부합니다 |

* **출퇴근 RPC를 `SECURITY DEFINER`로 두는 이유**: 본인에게 `attendance_days` UPDATE 정책을 주면 자기 `status_code`도 고칠 수 있습니다. 컬럼 단위 권한 대신 **본인 쓰기 정책을 아예 만들지 않고** 좁은 RPC 두 개로만 길을 냅니다. 함수 안에서 `app.current_app_user_id()`로 대상을 고정하므로 남의 행에는 닿지 않습니다.
* **정정 RPC는 `SECURITY INVOKER`입니다**: 여기서는 우회할 이유가 없습니다 — `management` 쓰기 정책이 그대로 판정하고, 함수는 이력과 원장을 원자적으로 묶는 일만 합니다. 프로젝트 규약(정책을 함수 안에 복제하지 않는다)을 그대로 따릅니다.
* **모두 `set search_path = app, public`으로 고정하고 `GRANT EXECUTE`는 `authenticated`로 한정합니다.**

## 9. 권한·RLS

| 테이블 | SELECT | INSERT / UPDATE |
| :--- | :--- | :--- |
| `attendance_days` | `app.can_read_workspace('management')` **또는** `user_id = app.current_app_user_id()`(본인) | `app.can_write_workspace('management')`만. 본인 쓰기는 RPC 경유 |
| `attendance_policies` | `management` read **또는** `user_id IS NULL` **또는** 본인 | `app.can_write_workspace('management')` |
| `attendance_statuses` | `app.is_internal_user()` — 라벨·톤은 위젯도 읽습니다 | `app.can_write_workspace('management')` |
| `attendance_edits` | `management` read | INSERT만 `management` write. UPDATE·DELETE 정책 없음(append-only) |

* **DELETE 정책은 만들지 않습니다**. 근태 행은 `deleted_at`으로만 걷어냅니다.
* **외부 게스트는 어느 테이블에도 닿지 않습니다** — 모든 정책이 내부 사용자 헬퍼를 경유합니다.
* **데이터 등급은 `Personal`입니다**: 목록에 이름·소속 외의 개인 식별 정보를 덧붙이지 않으며, 개인 근태를 파일로 내려받는 Export 기능은 이번 범위에 두지 않습니다(도입 시 `access_logs` 적재 경로를 함께 설계합니다).

## 10. 마이그레이션 설계

파일 한 건(`supabase/migrations/<타임스탬프>_attendance.sql`)으로 처리합니다.

1. **enum 신설**: `public.attendance_place`(`INTERNAL`/`EXTERNAL`) — 멱등 생성.
2. **테이블 4종 생성** 후 즉시 `enable row level security`.
3. **정책 생성**: 위 §9 표대로 SELECT·INSERT·UPDATE를 분리해 만들고 DELETE는 만들지 않습니다.
4. **시드**: 전사 기본 정책 1행(`07:00`~`09:00`, 540분, 월~금)과 상태 10종(시스템 5 + 휴가류 5). 개인정보·secret을 포함하지 않습니다.
5. **인덱스**: `attendance_days(work_date, user_id)`(일간 뷰) · `attendance_days(user_id, work_date desc)`(월간 뷰) · `attendance_edits(attendance_day_id, edited_at)`.
6. **트리거**: `app.set_updated_at`을 `attendance_days`·`attendance_policies`에 겁니다. 기여 로그 트리거는 걸지 않습니다(§5.4).
7. **RPC 3종**: §8대로 생성하고 `GRANT EXECUTE ... TO authenticated`.

**보안 게이트 점검**([11_migration_security_gate.md](../docs_dev/11_migration_security_gate.md)): 소유 워크스페이스 `management` / 데이터 등급 `Personal` / 접근 주체 내부 임직원 / Scope `self` + `global` / 감사 로그는 Export 도입 시점까지 미대상. 새 테이블 4종과 `SECURITY DEFINER` 함수 2종이 생기므로 RLS 즉시 활성화, 정책 분리, DELETE 미생성, 헬퍼 경유, `search_path` 고정, 함수 내부 권한 확인, `GRANT` 최소화를 모두 충족시키고 `supabase/tests/rls_regression_test.sql`에 본인/타인/게스트 3케이스를 추가합니다.

## 11. 검증 규칙 (DB 제약 ↔ 화면 안내)

| 규칙 | DB | 화면 |

## 12. 후속 과제

* **전자결재 휴가 문서 연동** — 연차·반차 결재가 승인되면 해당 날짜의 근태 상태를 자동으로 채우고, 정정 이력에 `결재 승인` 출처를 남깁니다.
* **공휴일 원장** — 현재 공휴일은 프론트 상수(`apps/works/src/lib/koreanHolidays.ts`)라 DB 판정에 쓸 수 없습니다. 근무일 판정에 반영하려면 원장으로 올려야 합니다.
* **월말 마감 스냅샷** — 확정된 달의 집계를 얼려 두는 배치와 잠금.
* **근태 현황 Export** — CSV 내려받기와 `access_logs` 적재.
* **지사·부서별 기준 시각** — 지금은 전사 기본 + 임직원별 예외 2단입니다. 지사 단위 기준이 필요해지면 축을 하나 더 둡니다.
* **초과근무 집계** — 소정 시간을 넘긴 시간의 누적과 경고.

## 13. 테스트 기준

* 출근 마감(`09:00`) 이후에 출근을 찍으면 상태가 `지각`으로 기록되고, 이전에 찍으면 `정상`으로 기록된다.
* 출근 가능 시작(`07:00`) 이전에는 출근을 찍을 수 없다.
* 소정 근무시간을 채우기 전에 퇴근을 찍으면 `조기퇴근`으로, 지각한 날이면 `지각·조기퇴근`으로 바뀐다.
* 근무 요일에서 뺀 요일에는 근무체크 버튼이 비활성화된다.
* 관리자가 `지각`을 `연차`로 바꾸면 표에 `수정됨` 표식이 뜨고, 자동 판정값(`지각`)은 그대로 남는다.
* 사유를 비우고 정정을 저장하면 거부된다.
* 정정 이력에 이전값·이후값·사유·정정자·정정 시각이 남고, 이력 행은 수정·삭제되지 않는다.
* 출근 마감 시각을 `09:30`으로 바꿔 저장해도 이전 날짜의 지각 판정은 바뀌지 않는다(기준 스냅샷).
* 임직원별 예외를 등록한 사람은 그 기준으로, 나머지는 전사 기본으로 판정된다.
* 일반 임직원이 남의 근태를 조회하면 결과가 비어 있고, 자기 행의 `status_code`를 직접 UPDATE하려는 요청은 거부된다.
* 외부 게스트 계정은 근태 테이블 어느 것도 조회하지 못한다.
* 근무일인데 기록이 없는 지난 날짜는 일간 표에 `결근`으로 표시되고, 상태를 지정하면 그때 행이 생성된다.
* 마이그레이션 재실행 시 오류 없이 통과한다(멱등).
