# [3-3-3] STARTUP 메뉴별 통계 카드 섹션 기획서

> [!NOTE]
> 본 문서는 [3_3_1_startup_pool_classification.md](./3_3_1_startup_pool_classification.md)가 규정한 STARTUP 4개 구분 목록 뷰와 '내 기업 관리' 뷰를 대상으로, **메뉴명(PageHeader) 아래 · 목록 위에 놓이는 통계 카드 섹션**의 항목을 확정하기 위한 기획서입니다. 카드 항목이 확정되기 전의 **후보안 단계**이며, 확정 시 본 문서의 표가 구현 계약이 됩니다. 워크스페이스 전체를 한 화면에 담는 '전체 기업(`?tab=dashboard`)' 대시보드는 별도 재설계 대상이므로 본 문서 범위에서 제외합니다.

---

## 1. 목적

* 목록 화면에 들어온 사용자가 **그 목록의 전체 규모와 상태**를 표를 스크롤하지 않고 먼저 파악하도록 합니다.
* 숫자를 보여주는 데 그치지 않고, **다음 조치가 있는 지표**(담당자 미지정, 정보 결측, 장기 무활동)를 카드로 올려 클릭 한 번으로 해당 목록에 도달하게 합니다.
* 메뉴마다 카드 구성을 다르게 두어, 같은 원장이라도 **구분별로 관심사가 다르다**는 사실을 화면 구조에 반영합니다(투자기업은 담당자·집행액, 발굴기업은 유입 경로·정보 완성도).

---

## 2. 이 문서가 다루는 범위

* STARTUP 5개 메뉴(내 기업 관리 / 투자기업 / 보육기업 / 발굴기업 / 기타기업)의 카드 섹션 항목 정의.
* 각 카드의 집계 정의와 데이터 원천, 현행 스키마 기준 실현 가능성 판정.
* 카드 섹션의 공통 배치·상호작용 규칙.
* **제외**: 전체 기업 대시보드(`?tab=dashboard`) 재설계, 카드의 시각 규격(치수·글자 위계는 `densityScale.ts`·`cardText`가 소유), NETWORKS·AC·M&A·PROJECT·FUND의 동일 성격 카드 섹션(같은 틀로 후속 기획).

---

## 3. 배경 (현재 상태)

* 데이터베이스(STARTUP·NETWORKS)·워크스페이스(AC·M&A/PE·PROJECT·FUND) 구획과 OFFICE의 **대시보드 콘텐츠는 전면 재설계를 위해 비워 둔 상태**입니다(2026-07-31). 화면은 메뉴명과 구분선만 남아 있습니다.
* 본 카드 섹션은 그 재설계의 첫 단계로, **대시보드 한 곳에 지표를 몰아넣는 대신 각 목록 메뉴가 자기 지표를 이고 가는 방향**을 택한 것입니다.
* 목록 데이터 테이블에는 소재지(`startups.location`) 열이 추가되어 있어, 소재지 분포 카드와 목록이 같은 축을 공유합니다.

---

## 4. 공통 규칙

* **위치**: `PageHeader`(메뉴명 + 구분선) 바로 아래, 목록 컨트롤 행 위에 한 줄로 배치합니다.
* **개수**: 메뉴당 **4장 고정**을 원칙으로 합니다(3~5장 범위에서 하나로 통일). 메뉴를 옮겨도 카드 줄의 높이와 열 정렬이 흔들리지 않아야 합니다.
* **구성**: 카드 한 장은 **대표 숫자 1개 + 보조 분해 1줄**로 제한합니다. 차트는 카드에 넣지 않고 전체 기업 대시보드가 담당합니다.
* **상호작용**: 카드 클릭 시 그 조건이 적용된 **같은 목록**으로 이동합니다(예: `정보 갱신 필요` → 해당 필터가 걸린 상태의 목록).
* **규격**: 화면에서 규격 클래스를 직접 쓰지 않고 `cardText`·`densityScale.ts`의 매핑을 따릅니다. 숫자는 `tabular-nums`로 자릿수를 고정합니다.
* **권한**: 타 워크스페이스 원장을 조인하는 카드는 권한이 없는 사용자에게 **0이 아니라 조회 불가로 표기**합니다. 0으로 보이면 데이터가 없는 것으로 오독됩니다.

---

## 5. 실현 가능성 표기

| 표기 | 의미 |
| :--- | :--- |
| `즉시` | `public.startups` 원장과 기존 임베드(`startup_managers`·`users`)만으로 계산 가능합니다. |
| `조인` | 타 워크스페이스 원장 조인이 필요하며, 해당 워크스페이스 RLS 권한이 없으면 값이 비어 옵니다. |
| `신규` | 현행 스키마로 계산할 수 없어 컬럼·테이블 추가가 선행되어야 합니다. |

---

## 6. 메뉴별 카드 후보안

### 6.1 내 기업 관리 (`?tab=mine`)

담당자(`startup_managers`) 또는 생성자(`created_by`)가 나인 기업을 구분 무관하게 모은 뷰이므로, **내 담당 범위의 규모와 방치 여부**가 관심사입니다.

| 카드 | 집계 정의 | 원천 | 판정 |
| :--- | :--- | :--- | :--- |
| 내 관리기업 | 총 개사 수 + 투자·보육·발굴·기타 4분해 | `management_status` | `즉시` |
| 이번 달 내 신규 등록 | 이번 달 내가 등록한 개사 수 + 전월 대비 증감 | `created_by`, `created_at` | `즉시` |
| 정보 갱신 필요 | 최종 수정 후 90일이 지난 개사 수 | `updated_at` | `즉시` |
| 내 투자기업 관리현황 | 내 담당 투자기업의 관리현황 분포(정상·주의·폐업 등) | `pool_status` | `즉시` |

### 6.2 투자기업 (`?tab=invested`)

투자기업만 담당자 지정과 관리현황을 갖는 구분이므로, **자본 집행과 관리 책임**이 관심사입니다.

| 카드 | 집계 정의 | 원천 | 판정 |
| :--- | :--- | :--- | :--- |
| 투자기업 수 | 총 개사 수 + 이번 달 증감(신규 − 비활성화) | `management_status`, `created_at`, `deleted_at` | `즉시` |
| 자사 투자 집행 | 자사 집행 건수 + 집행액 합계(억 원) | `investments`(`is_own_investment`) | `조인` (FUND 권한 필요) |
| 관리현황 분포 | 관리현황 태그별 개사 수 | `pool_status` | `즉시` |
| 담당자 미지정 | 지정 담당자가 없는 투자기업 개사 수 | `startup_managers` | `즉시` |

> [!NOTE]
> 담당자 미지정 카드는 단순 통계가 아니라 **규칙 위반 경고**입니다. 투자기업은 담당자 원장에 행이 있어야 정상이며, 비어 있으면 일반 사용자가 수정할 수 없어 관리 책임이 사라집니다. 생성자·담당자·기여 이력은 서로 다른 축이며, 생성자나 과거 기여자로 담당자를 대체하지 않습니다.

### 6.3 보육기업 (`?tab=incubated`)

보육은 사업(프로그램)을 통해 접점이 유지되는 구분이므로, **참여 상태와 접점 단절**이 관심사입니다.

| 카드 | 집계 정의 | 원천 | 판정 |
| :--- | :--- | :--- | :--- |
| 보육기업 수 | 총 개사 수 + 이번 달 신규 | `management_status`, `created_at` | `즉시` |
| 사업 참여 현황 | 진행 중 사업에 참여 중인 개사 수 / 미참여 개사 수 | `program_participants` | `조인` (AC 권한 필요) |
| 분야 분포 Top 5 | 분야 태그별 개사 수(다중 태그 중복 집계) | `industries` | `즉시` |
| 90일 무활동 | 최근 90일간 기여 로그가 없는 개사 수 | `entity_contributions` | `즉시` |

> [!NOTE]
> "보육 → 투자 전환 건수"는 보육 단계의 성과를 가장 잘 드러내는 지표이지만 `신규`입니다. `management_status`는 현재값만 보관하고 기여 로그에도 변경 전/후 값이 없어, 전환 시점 컬럼 또는 구분 이력 테이블을 신설해야 계산할 수 있습니다.

### 6.4 발굴기업 (`?tab=discovered`)

발굴은 유입 직후 단계라 데이터가 얇은 구분이므로, **유입 경로와 정보 보강**이 관심사입니다.

| 카드 | 집계 정의 | 원천 | 판정 |
| :--- | :--- | :--- | :--- |
| 발굴기업 수 | 총 개사 수 + 이번 달 신규 | `management_status`, `created_at` | `즉시` |
| 발굴 경로 Top 5 | 발굴 경로별 개사 수 | `discovery_source` | `즉시` |
| 정보 보강 대상 | 설립일·분야·소재지·대표자 중 하나라도 비어 있는 개사 수 | `founded_on`, `industries`, `location`, `representative` | `즉시` |
| 소재지 분포 Top 5 | 시·도별 개사 수(미기재 별도) | `location` | `즉시` |

> [!NOTE]
> 발굴 경로(`discovery_source`)는 자유 텍스트 컬럼이라 같은 경로가 다른 표기로 쌓입니다. 카드를 도입하려면 단계·관리현황·소재지처럼 **태그 원장으로 정규화**하는 편이 집계 신뢰도에 유리합니다.

### 6.5 기타기업 (`?tab=etc`)

기타는 다른 세 구분에 들어가지 않는 잔여 구분이므로, **무엇이 담겼는지와 재분류**가 관심사입니다.

| 카드 | 집계 정의 | 원천 | 판정 |
| :--- | :--- | :--- | :--- |
| 기타기업 수 | 총 개사 수 + 이번 달 신규 | `management_status`, `created_at` | `즉시` |
| 자유 분류 분포 | 기타 자유 분류 라벨별 개사 수 | `management_status_etc` | `즉시` |
| 재분류 대상 | 등록 후 90일이 지나도록 기타로 남은 개사 수 | `created_at` | `즉시` (근사) |
| 정보 완성도 | 필수 항목이 비어 있는 개사 수 | 발굴기업과 동일 기준 | `즉시` |

## 7. 후속 작업

* **카드 항목 확정**: 6절 후보안 중 채택·교체 항목을 사용자와 확정한 뒤 본 문서를 확정본으로 갱신합니다.
* **공용 카드 셸 구현**: 메뉴별 카드 섹션을 그리는 공용 컴포넌트를 하나 만들고 5개 메뉴에 주입합니다(카드 정의는 데이터, 렌더링은 공용).
* **집계 훅 정리**: 카드 집계는 목록 조회와 분리된 head 카운트 질의로 구성하여, 목록 페이지네이션 결과에 좌우되지 않게 합니다.
* **타 워크스페이스 확장**: NETWORKS·AC·M&A/PE·PROJECT·FUND에 같은 틀(메뉴당 4장, 대표 숫자 + 보조 분해, 클릭 시 프리필터 목록)을 적용합니다.
* **선행 과제**: 구분 전환 이력(6.3), 발굴 경로 태그 정규화(6.4)는 카드 도입 전 스키마 결정이 필요합니다.

---

## 8. 테스트 기준

* 5개 메뉴 각각에서 카드 4장이 같은 높이·같은 열 정렬로 렌더링됩니다.
* 카드의 숫자가 검색어·필터·페이지 이동에 영향받지 않고, 해당 메뉴 전체 모집단을 기준으로 집계됩니다.
* 카드 클릭 시 그 조건이 적용된 목록으로 이동하며, 뒤로가기로 카드 섹션이 있는 원래 상태로 복귀합니다.
* FUND·AC 권한이 없는 계정에서 `조인` 카드가 0이 아니라 조회 불가로 표기됩니다.
* 집계 대상에서 비활성화(`deleted_at`)·병합(`merged_into_id`) 레코드가 제외됩니다.
