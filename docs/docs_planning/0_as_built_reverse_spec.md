# 현재 구현 화면 역기획 기준서 (As-built Baseline)

> 기준일: 2026-07-31  
> 기준 소스: `apps/works/src/router.tsx`, `apps/guest/src/router.tsx`, `apps/works/src/config/workspaces.ts`, `apps/works/src/config/navigation.ts` 및 각 페이지 컨테이너

이 문서는 기존 기획서가 설명하는 **목표 상태**와 현재 앱이 실제로 렌더링하는 **구현 상태**를 분리하기 위한 역기획 기준서입니다. 세부 업무 규칙은 각 `3_x` 문서가 소유하고, 현재 메뉴·라우트·진입 기본값·준비 중 화면 여부는 이 문서를 우선 확인합니다.

## 1. 상태 표기

| 상태 | 의미 |
| :--- | :--- |
| **사용 가능** | 라우트와 주요 조회·입력 흐름이 화면에 연결되어 있음 |
| **부분 구현** | 핵심 화면은 있으나 일부 탭·외부 연동·보고 기능이 후속임 |
| **골격** | 메뉴와 제목 또는 안내만 있고 업무 콘텐츠는 아직 없음 |
| **목표 기획** | 기존 기획서에 정의되어 있으나 현재 화면에는 연결되지 않음 |

`구현 반영`은 문서가 구현을 참고했다는 뜻이지, 문서에 적힌 모든 목표 기능이 완료되었다는 뜻으로 사용하지 않습니다.

## 2. 전역 정보 구조

### 2.1 워크스페이스 스위처

스위처는 다음 네 구획과 순서를 사용합니다.

| 구획 | 워크스페이스 |
| :--- | :--- |
| 업무 허브 | OFFICE |
| 데이터베이스 | STARTUP, NETWORKS |
| 워크스페이스 | AC, M&A/PE, PROJECT, FUND |
| 경영·시스템 | MANAGEMENT, ADMIN |

인증 후 `/` 진입은 `/office`로 이동합니다. `GUEST`는 WORKS 스위처에 넣지 않고 별도 앱으로 운영합니다.

### 2.2 전역·호환 라우트

| 경로 | 현재 동작 |
| :--- | :--- |
| `/login` | WORKS 임직원 로그인 |
| `/me` | 모든 인증 사용자의 내 계정 관리. 사진·약력·노트·자료는 직접 편집하고 계정/조직 정보는 조회만 함 |
| `/styleguide` | 메뉴에 노출하지 않는 내부 디자인 시스템 확인 페이지 |
| `/approval` | 하위 호환을 위해 `/office?tab=approval`로 리다이렉트 |
| 알 수 없는 워크스페이스 탭 | 해당 페이지의 기본 제목 또는 준비 중 안내로 폴백 |

AI 에이전트와 전사 캘린더는 사이드바 탭이 아니라 **상단바 전역 액션의 우측 패널**로 엽니다. 통합 검색과 알림도 상단바가 소유합니다.

### 3.2 STARTUP

기본 진입은 `?tab=mine`입니다.

| 탭 | 상태 | 현재 화면 |
| :--- | :---: | :--- |
| `mine` | 사용 가능 | 구분과 무관하게 생성자 또는 지정 담당자가 나인 기업 |

| `invested` / `incubated` / `discovered` / `etc` | 사용 가능 | 구분별 상호 배타 목록, 검색·복수 필터·페이지네이션·등록·상세 이동 |
| `archerscan` / `bulk` | 골격 | 메뉴와 준비 중 안내 |

목록은 현재 관리 주체를 답하도록 구성합니다. 투자기업은 리드 1명과 지원 N명의 지정 담당자를, 나머지 구분은 `공동관리`를 표시하며 생성자는 목록에서 숨기고 상세의 기록 정보에만 둡니다. 메뉴별 통계 카드 후보는 [3_3_3_startup_menu_stat_cards.md](./3_3_3_startup_menu_stat_cards.md)에 있으며 아직 목표 기획입니다.

### 3.4 AC · M&A/PE · PROJECT

세 워크스페이스는 `features/program`의 목록·상세·모듈 보드를 공유하고 원장·라벨·카테고리만 분리합니다. 모두 기본 진입은 `?tab=mine`입니다.

| 워크스페이스 | 내 목록 | 전체 목록 | 사업구분 |
| :--- | :--- | :--- | :--- |
| AC | `내 사업 관리` | `전체 사업` | 공공·민간·매출·기타 (목록 필터) |
| M&A/PE | `내 딜 관리` | `전체 딜` | Sell·Buy·PE Fund·기타 (목록 필터) |
| PROJECT | `내 프로젝트 관리` | `전체 프로젝트` | 글로벌·신사업·기타 (목록 필터) |

사이드바는 두 항목뿐입니다. 2026-08-03에 사업구분별 세분화 항목을 내리고 사업구분을 목록 필터의 축으로 옮겼으며, 미분류(`category is null`) 건은 그 필터의 `미지정` 선택지가 답합니다. 옛 링크(카테고리 탭, 구 `?tab=dashboard`)로 들어오면 전체 목록으로 주소까지 바로잡습니다.

목록은 검색(사업명·생성자), 상태·사업구분·담당 부서·시작일 필터, 서버 페이지네이션, 다중 선택을 제공하며 생성자는 목록에서 숨깁니다. 관리 주체는 담당 부서와 담당자 열이 답하고, 생성자는 상세 기본 정보에만 표시합니다. AC는 정형 운영 모듈 8종과 기본 템플릿 3종(글쓰기·URL첨부·파일첨부)을 사용하고, M&A/PE·PROJECT는 기본 템플릿 3종만 운용합니다.

## 4. 공용 화면 규칙

### 4.1 생성자·담당자·기여 이력

| 축 | 답하는 질문 | 화면 원칙 |
| :--- | :--- | :--- |
| 생성자 (`created_by`) | 누가 레코드를 만들었나 | 권한을 주지 않음. 관리 주체가 따로 있는 원장은 목록에서 숨기고 상세에 기록 정보로 표시 |
| 담당자/배정 인력 | 지금 누가 관리하나 | 목록의 관리 주체 열에 표시. 지정 인력이 없고 공동관리인 원장은 `공동관리`로 표시 |
| 기여 이력 | 누가 무엇을 바꿨나 | 상세 변동 이력에서 조회. 접근 권한 판정에 사용하지 않음 |

`내 … 관리`의 조회 범위는 사용 편의를 위해 생성자와 담당자를 함께 볼 수 있으나, 이것이 생성자에게 수정 권한을 부여한다는 뜻은 아닙니다.

### 4.2 인원 요약

목록의 복수 인원은 **대표 1명 + `외 N`**으로 접습니다. 대표는 도메인이 결정합니다(투자기업 리드, 사업 PM, 펀드 대표펀드매니저). 상세 화면은 전원을 나열하며, 목록에서 생성자를 담당자 대체값으로 사용하지 않습니다.

### 4.3 목록 상태 보존

* 탭·검색·필터·스코프가 바뀌면 페이지와 선택 행을 초기화합니다.
* 서버 페이지네이션을 사용하는 목록은 전체 건수를 기준으로 역순 `No.`를 계산합니다.
* 비활성화는 물리 삭제가 아니라 `deleted_at` 소프트 삭제를 기본으로 합니다.
* 상세 페이지가 있는 원장은 목록의 관리 열을 비우지 않고 아예 숨기며, 편집·비활성화는 상세에서 수행합니다.
* 화면의 빈 값은 공용 빈 값 표기를 사용하고, 임의의 샘플 숫자로 채우지 않습니다.

## 5. 기존 기획서 해석 규칙

1. OFFICE·STARTUP·NETWORKS·AC/M&A/PROJECT·FUND의 대시보드 상세 문구는 현재 구현 설명이 아니라 **재설계 목표**로 읽습니다.
2. `3_4_1_ac_dashboard.md`와 `3_3_2_networks_dashboard.md`는 목표 기획이며, 현재 `dashboard` 탭은 빈 골격입니다.
3. M&A 딜 파이프라인·매칭 매트릭스, PROJECT 태스크 칸반·의존 간트, FUND 조합 재무·자동 보고서는 후속 범위입니다.
4. 준비 중 메뉴를 `구현 완료`로 표기하지 않습니다. 메뉴 노출, UI 골격, 업무 기능, 외부 연동을 각각 분리해 상태를 기록합니다.

## 6. 역기획 완료 기준

* 라우터의 공개 경로와 문서의 경로 목록이 일치합니다.
* 사이드바 메뉴 순서·기본 탭·동적 플라이아웃이 문서와 일치합니다.
* 빈 대시보드와 준비 중 메뉴가 목표 기능과 구분됩니다.
* 목록/상세/등록의 생성자·담당자 표기가 실제 화면 규칙과 일치합니다.
* 한 기능의 상세 규칙은 한 문서가 소유하고, 다른 문서는 링크와 요약만 둡니다.
