# 현재 구현 화면 역기획 기준서 (As-built Baseline)

> 기준일: 2026-09-12 · 기준 `846dfb83` + 현재 작업 트리(미커밋)
> 기준 소스: `apps/works/src/router.tsx`, `apps/works/src/config/workspaces.ts`, `apps/works/src/config/navigation.ts`, `apps/guest/src/router.tsx`, `apps/guest/src/config/navigation.ts` 및 각 페이지 컨테이너

> [!IMPORTANT]
> 이 문서의 상태 표기는 **기준 커밋의 소스를 읽어 판정한 정적 결과**입니다. 브라우저 실행, 데이터베이스 응답, 외부 연동의 실제 동작은 확인하지 않았으므로, "화면이 연결되어 있다"가 "그 화면이 운영 데이터로 정상 동작한다"를 뜻하지는 않습니다.

기존 기획서가 설명하는 **목표 상태**와 앱이 실제로 렌더링하는 **구현 상태**를 분리하기 위한 문서입니다. 세부 업무 규칙은 각 `3_x` 문서가 소유하고, **현재 메뉴·라우트·기본 진입·준비 중 여부는 이 문서를 우선 확인**합니다.

## 1. 상태 표기

| 상태 | 의미 (모두 **소스 기준 정적 판정**) |
| :--- | :--- |
| **구현 연결** | 라우트와 주요 조회·입력 흐름이 소스에서 화면에 연결되어 있음. 런타임 동작은 미검증 |
| **부분 구현** | 핵심 화면은 있으나 일부 탭·연동·보고가 후속 |
| **골격** | 메뉴와 제목 또는 안내만 있고 업무 콘텐츠는 없음 |
| **목표 기획** | 기획서에는 있으나 현재 화면에 연결되지 않음 |

`구현 반영`은 문서가 구현을 참고했다는 뜻이지, 문서의 모든 목표 기능이 완료되었다는 뜻이 아닙니다.

| 2 | 공용 오피스 (`office`) | `office` / `/office` |

**항목(자리)과 권한 키(축)는 분리되어 있습니다.** 한 항목이 구획 여럿을 덮을 수 있고, 그때도 사이드바 노출·라우트 게이트·RLS는 구획마다 자기 키로 판정합니다. 구획의 신원은 키가 아니라 **경로**입니다(`resolveWorkspace`가 경로 세그먼트로 판정).

* 인증 후 `/` 진입은 `/my-office`로 이동합니다.
* `project`는 **구 AC**입니다(2026-09-09 개명). 구 PROJECT 워크스페이스는 2026-09-07에 폐지되었고, DB enum에는 과거 기록을 위해 `project_retired`라는 이름으로 남아 있습니다(`apps/works/src/auth/types.ts`, `supabase/migrations/20260909150000_rename_ac_workspace_to_project.sql`).
* `GUEST`는 WORKS 스위처에 넣지 않고 별도 앱으로 운영합니다.

* AI 에이전트·통합 검색·알림은 사이드바가 아니라 **상단바 전역 액션**이 소유합니다.

### 3.3 데이터베이스 — STARTUP / NETWORKS

두 원장은 스위처 항목 하나 아래 각각 한 줄로 섭니다. **합친 것은 자리뿐**이며 원장·권한 키·목록 화면은 갈린 채입니다.

| 경로 | 상태 | 현재 화면 |
| :--- | :---: | :--- |
| `/startup` | 구현 연결 | 스타트업 단일 목록. 범위는 `?scope=`(기본 `all`), 구분·소재지·단계는 목록 필터 축 |
| `/startup/new`, `/startup/:id` | 구현 연결 | 페이지형 등록, 카드 섹션형 상세·편집·자료·변동 이력 |
| `/startup/bulk` | 구현 연결 | 대량 업로드(목록 상단 버튼으로 진입, 메뉴 아님) |
| `/networks` | 구현 연결 | 네트워크 단일 목록. 구분(`category`)과 국가가 직교한 두 축 |
| `/networks/:id` | 구현 연결 | 페이지형 상세·등록(`id='new'`이면 등록 모드, `?category=`로 초기 구분) |
| `/networks/bulk` | 구현 연결 | 국내/글로벌 인페이지 탭 업로드·검증·리뷰 |

* 범위 토글은 메뉴가 아니라 목록 상단입니다(`lib/listScope.ts`). 기본 범위는 주소에 적지 않습니다.
* `?tab=archerscan`은 라우팅만 살아 있는 준비 중 화면이며 사이드바에서는 내렸습니다.
* NETWORKS 구분에는 2026-09-12에 `startup`(스타트업 대표·임직원 등 사람)이 다시 열렸습니다. 이 값은 분류일 뿐 `public.startups` 행과의 연결을 뜻하지 않습니다.

**게스트 계정 화면은 하나입니다.** `/guest-accounts`는 사업부·M&A팀·투자실 사이드바 하단에서 가깝게 열지만 URL·목록 범위·생성 창구는 전사 한 벌입니다. 일반 내부 사용자는 생성·마스킹 조회만, ADMIN은 같은 화면에서 원본 조회·연락처 수정·비밀번호 초기화·체크박스 일괄 정지/해제·영구 삭제를 합니다. 옛 OFFICE·ADMIN·워크스페이스 `?tab=guest-accounts` 주소는 모두 이 URL로 보냅니다. 생성자 교체는 권한 이관이 아니라 `created_by` 표기 정리용 관리자 오버라이드이며 `CREATOR_CHANGE` 감사 로그에 남습니다.

## 5. 공용 화면 규칙

아래는 **여러 화면에 반복 적용해 온 UI 규약과 의도된 정책**입니다. 소스에서 그 규약이 쓰이는 자리를 확인했다는 뜻이며, 모든 화면이 예외 없이 이대로 동작한다고 검증한 결과는 아닙니다. 개별 화면의 실제 동작은 해당 기능 문서와 코드가 답합니다.

### 5.1 생성자 · 담당자 · 기여 이력

| 축 | 답하는 질문 | 화면 원칙 |
| :--- | :--- | :--- |
| 생성자 (`created_by`) | 누가 만들었나 | 권한을 주지 않음. 관리 주체가 따로 있는 원장은 목록에서 **숨기고** 상세의 기록 정보에만 표시 |
| 담당자/배정 인력 | 지금 누가 관리하나 | 목록의 관리 주체 열. 지정 인력 없이 공동관리인 원장은 `공동관리` |
| 기여 이력 | 누가 무엇을 바꿨나 | 상세 변동 이력. **접근 권한 판정에 쓰지 않음** |

`내 …` 범위가 생성자와 담당자를 함께 보여 주는 것은 사용 편의이며, 생성자에게 수정 권한을 준다는 뜻이 아닙니다.

### 5.2 인원 요약

목록의 복수 인원은 **대표 1명 + `외 N`**으로 접습니다. 대표는 도메인이 정합니다(투자기업 리드, 사업 PM, 펀드 대표펀드매니저). 상세는 전원을 나열하며, 목록에서 생성자를 담당자 대체값으로 쓰지 않습니다.

### 5.3 목록 상태

* 탭·검색·필터·범위가 바뀌면 페이지와 선택 행을 초기화합니다.
* 서버 페이지네이션 목록은 전체 건수 기준 역순 `No.`를 계산합니다.
* 비활성화는 물리 삭제가 아니라 `deleted_at` 소프트 삭제가 기본입니다.
* 상세 페이지가 있는 원장은 목록의 관리 열을 비우지 않고 **아예 숨기며**, 편집·비활성화는 상세에서 합니다.
* 빈 값은 공용 빈 값 표기를 쓰고 임의의 샘플 숫자로 채우지 않습니다.

### 5.4 메뉴 설계 원칙(반복 적용된 판단)

분류·범위를 사이드바 항목으로 두면 그것이 '어디에 있는가'가 되어 다른 축과 함께 걸 수 없습니다. 그래서 사업구분(2026-08-03), 펀드 종류·스타트업 구분(2026-08-20), 지역(2026-09-04), 범위(2026-09-05)가 차례로 메뉴에서 **목록 필터·토글 축**으로 내려왔습니다. 새 분류를 추가할 때 메뉴 한 줄을 늘리는 설계는 이 선례와 충돌합니다.

## 7. 역기획 완료 기준

* 라우터의 공개 경로와 이 문서의 경로 목록이 일치한다.
* 사이드바 항목 순서·기본 탭·동적 플라이아웃이 `config/` 소스와 일치한다.
* 빈 대시보드와 준비 중 메뉴가 목표 기능과 구분되어 있다.
* 목록/상세/등록의 생성자·담당자 표기가 실제 화면 규칙과 일치한다.
* 한 기능의 상세 규칙은 한 문서가 소유하고, 다른 문서는 링크와 요약만 둔다.
