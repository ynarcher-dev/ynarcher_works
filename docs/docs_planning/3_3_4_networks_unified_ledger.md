# [3-3-4] NETWORKS 통합 원장 — 구분과 국가를 직교한 두 축으로

본 문서는 NETWORKS 원장 11종(국내 10 + 글로벌 1)을 단일 원장 `public.networks` 하나로 합치고, **구분(카테고리)** 과 **국가** 를 서로 독립한 두 축으로 세우는 결정의 정본입니다. 상위 화면 요건은 [3_3_workspace_networks.md](./3_3_workspace_networks.md)가, 스타트업 원장 규칙은 [3_3_1_startup_pool_classification.md](./3_3_1_startup_pool_classification.md)가 소유합니다.

> [!IMPORTANT]
> 2026-09-04 사용자 확정. 종전 구조(구분=물리 테이블, 해외=별도 원장)는 이 문서 이후 정본이 아니며, 옛 구조를 근거로 삼지 않습니다.

---

## 1. 무엇이 갈려 있었는가

분리가 한 겹이 아니라 **두 겹**이었습니다.

| 축 | 종전 국내 | 종전 해외 |
| :--- | :--- | :--- |
| 구분 | 물리 테이블 10개(`experts`·`van`·`exp`·`investors`·`corporates`·`institutions`·`universities`·`etc`·`vendors`·`others`)로 가름 | `category` 스칼라 3값(기업·기관·투자자)으로 가름 |
| 지역 | — (원장 자체가 국내) | 원장 자체가 해외(`global_networks`) |

* **같은 사실을 두 문법으로 적었습니다**: 구분이 한쪽에서는 테이블 이름이고 다른 쪽에서는 컬럼 값입니다. 국내 원장은 그마저 `profile.category`에 라벨을 한 번 더 적어, 한 레코드의 구분이 두 곳에 살았습니다.
* **표현할 수 없는 것이 생겼습니다**: 해외 구분이 3값뿐이라 **해외 대학·해외 전문가·해외 BAN이 성립하지 않았습니다.** 반대로 국내 원장에는 권역·국가·링크드인 칸이 없어 해외로 옮겨 간 사람을 그대로 둘 수 없었습니다.
* **사람에게 판단을 먼저 시켰습니다**: 등록·업로드가 갈려 있어, 정보를 넣기 전에 "이건 어느 원장인가"를 먼저 정해야 했습니다. 그 판단이 틀리면 이관이 곧 행 이동입니다.
* **읽는 쪽은 이미 하나였습니다**: `app.network_entities_union`이 11종을 한 컬럼 규약으로 정규화해 목록 RPC가 그 위에서 돌고 있었습니다. 실제로 갈려 있던 것은 **메뉴·등록·업로드·상세** 네 곳입니다.

## 2. 통합이 이 프로젝트에서 값싼 이유

* **바깥에서 이 원장들을 FK로 가리키는 표가 없습니다**: 전수 조사 결과 `references public.experts(id)` 류는 전부 자기 자신의 `merged_into_id`뿐입니다. 바깥 연결(기여 로그·피드백·자료·회의록 링크·코드 레지스트리·사업 참가자)은 모두 **다형 키(문자열 + uuid)** 입니다.
* **식별자가 uuid라 표를 옮겨도 값이 그대로입니다**: 이관은 참조 재배선 없이 "행을 옮기고 다형 키 문자열만 갱신"으로 끝납니다. 원장 통합에서 가장 비싼 부분이 여기에는 없습니다.
* **화면이 이미 두 벌 중복입니다**: 폼(362/343줄)·상세(275/214)·업로드(411/384, 패널 400/365)·훅(611/247)이 국내와 글로벌로 같은 일을 두 번 합니다. 통합은 기능 추가가 아니라 **중복 제거**입니다.

## 3. 확정 구조 — 원장 하나, 축 둘

`public.networks` 한 원장에 다음 두 컬럼이 서로 독립해 섭니다.

* **구분(`category`)**: 전문가·BAN·EXP·투자사·기업·기관·대학·기타. 값은 **코드**(`experts`·`van`·`exp`·`investors`·`corporates`·`institutions`·`universities`·`etc`)이며 라벨은 코드가 아니라 화면 상수(`CATEGORY_LABEL`)가 소유합니다. 값이 `null`이면 **구분 미지정**이며, 그 상태를 찾는 자리는 목록 구분 필터의 `미지정` 선택지 하나입니다(§3.1).
* **국가(`country_tag_id`)**: 기준정보 태그(`country_tags`)를 참조합니다. **한국도 다른 나라와 같은 국가 한 줄**이며, 담당자가 지역에 대해 고르는 칸은 이것 하나뿐입니다.

두 축이 직교하므로 **해외 대학·국내 기업이 같은 문법으로** 섭니다. 구분이 늘어도 테이블이 늘지 않고, 국가가 바뀌어도 행이 이동하지 않습니다.

### 3.1 미지정은 카테고리가 아니라 빈 값입니다

종전 `others`는 "분류 전 임시 저장소"라는 성격을 **표 하나**로 표현했습니다. 통합 후에는 `category is null`이 그 성격입니다.

* 구분 지정이 **행 이동에서 `UPDATE` 한 줄로** 바뀝니다. 종전에는 soft delete + insert였고, 그 과정에서 id가 바뀌어 그 레코드에 붙어 있던 자료·피드백·회의록 링크가 원본을 잃었습니다.
* **전용 메뉴('미분류 데이터베이스')는 2026-09-04에 걷고 목록 구분 필터의 `미지정` 선택지 하나로 옮겼습니다.** 통합 직후에는 "분류 대기는 조회 조건이 아니라 매일 처리할 일감"이라는 이유로 메뉴 한 줄을 남겼으나, 분류를 메뉴로 두면 그것이 '어디에 있는가'가 되어 지역·영역 같은 다른 축과 함께 걸 수 없습니다(*해외의 미지정*, 같은 질문에 답할 수 없습니다). AC 사업구분(2026-08-03)·STARTUP/FUND 구분(2026-08-20)이 먼저 밟은 길과 같습니다.
* 대신 **구분이 정해지는 자리를 앞으로 당겼습니다** — 대용량 업로드는 구분이 빈 행이 하나라도 있으면 업로드가 막히고(추천 구분이 미리 채워지되 확정은 사람이 합니다), 회의록 간이 등록과 신규 등록 폼도 구분을 필수로 받습니다. 뒤에서 비우는 대기열이 없어지는 대신 앞에서 채우게 하는 것이며, 남는 `null`은 새로 들어오는 것이 아니라 **옛 데이터의 잔여**입니다(국가 미확인 축과 같은 성격).
* 서버에서 구분 배열(`p_categories`)과 미지정(`p_uncategorized`)은 **한 축으로 OR 판정**합니다(마이그레이션 20260904140000). 두 인자를 AND로 묶으면 '투자사 또는 미지정'이 늘 0건이 되어, 고를 수 있다고 말하면서 아무것도 답하지 않는 조합이 생깁니다.
* 미지정 건수는 목록의 구성 현황 타일과 NETWORKS 대시보드 현황 슬롯이 함께 답합니다 — 메뉴를 접어도 일감의 크기는 보여야 합니다.

### 3.2 지역은 국가가 답합니다 (2026-09-04 사용자 확정)

종전에는 '국내'가 원장 자체였고 국가는 해외 행에만 붙었습니다. 그래서 국내 행의 국가 칸이 비어 있었고, 표는 **"한국인가, 아직 안 넣었는가"를 답하지 못했습니다.**

* **한국도 국가로 명시합니다.** `country_tags`에 `is_domestic` 플래그를 두고 한국 행을 심습니다(권역도 `국내` 하나 신설 — 권역 목록이 북미·유럽 같은 해외 대륙권뿐이라 한국이 설 자리가 없고, `기타`에 넣으면 브라질·남아공과 한 칸에 묶여 집계가 뒤섞입니다).
* **`region_scope`(국내/해외)는 사람이 고르는 칸이 아닙니다.** 국가에서 파생되어 저장되는 열이며 트리거(`app.sync_network_region_scope`)가 채웁니다. 화면이 무엇을 보내든 서버가 다시 계산하므로 "해외로 저장했는데 국가는 한국"이 만들어지지 않습니다. 필터·인덱스가 쓸 빠른 축으로만 둡니다.
* **권역은 행에 저장하지 않습니다.** 국가가 이미 알고 있으므로(`country_tags.region_tag_id`) 조인해 읽습니다 — 따로 적으면 국가를 고쳤을 때 권역만 옛 값으로 남습니다.
* **국가는 필수입니다.** 다만 지금 `NOT NULL`을 걸지 않습니다 — 국가를 모르는 옛 해외 행이 있을 수 있고, 지금 잠그면 그 행은 저장 자체가 막혀 국가를 채워 넣을 수도 없습니다. **신규 등록은 화면이 즉시 필수로 막고**, 목록의 `국가 미확인` 축으로 남은 행을 채운 뒤 별도 마이그레이션에서 잠급니다.

**국가 드롭다운**은 자국(한국)을 맨 위에 두고 구분선 아래로 나머지를 **가나다순**으로 세웁니다. ADMIN 노출순위를 쓰지 않는 이유는 국가에 업무상 우열이 없어 순위를 매길 근거가 없기 때문입니다 — 자국이 먼저인가만 순위이고 나머지는 이름이 답합니다.

## 4. 스키마

```
public.networks
  id             uuid pk
  name           text not null
  affiliation    text                      -- 소속
  email          text
  phone          text
  linkedin_url   text                      -- 종전 글로벌 전용 → 전체 공통
  category       text                      -- 구분 코드. null = 미지정(목록 구분 필터가 답한다)
  country_tag_id uuid → country_tags(id)   -- 지역 축의 유일한 입력값(한국 포함)
  region_scope   text not null default 'DOMESTIC'   -- 국가에서 파생(트리거). DOMESTIC | OVERSEAS
  expertise      jsonb not null default '[]'
  profile        jsonb not null default '{}'
  is_provisional boolean not null default false
  merged_into_id uuid → networks(id)
  created_by     uuid → users(id)
  created_at / updated_at / deleted_at
```

* **CHECK**: `category`는 코드 8종 또는 `null`. `region_scope`는 2값(값 자체는 트리거가 채웁니다).
* **기준정보**: `country_tags.is_domestic`(자국 여부) 신설. 국내/해외 판정의 단일 원천이며, 네트워크 행이 아니라 국가가 갖습니다.
* **RLS**: 종전과 동일하게 `app.can_read_workspace('networks')` / `can_write_workspace('networks')`. 원장이 하나로 줄어 정책도 11벌에서 1벌이 됩니다.
* **트리거**: `set_updated_at` · `sync_network_region_scope`(국가 → 국내/해외 파생) · `guard_network_destructive`(비활성·병합 가드) · `log_entity_contribution('networks')` · `track_affiliation_history` · `audit_networks_merge` · 생성자 기본값. 종전 11벌 루프가 1벌이 됩니다.
* **인덱스**: 이름 정렬·부분일치, `category`, `region_scope`, `country_tag_id`, `merged_into_id`. 종전 원장별 인덱스 11벌을 대체합니다.

## 5. 이관 규칙

| 원본 | `category` | 국가 |
| :--- | :--- | :--- |
| `experts`·`van`·`exp`·`investors`·`corporates`·`institutions`·`universities`·`etc`·`vendors` | 원장 이름 그대로 코드 | **한국** |
| `others` | `null` | **한국** |
| `global_networks` (기업/기관/투자자) | `corporates`/`institutions`/`investors` | 갖고 있던 국가 그대로 |
| `global_networks` (구분 없음) | `null` | 갖고 있던 국가 그대로 |

> [!WARNING]
> 국내 원장 행은 **전부 한국**으로 채웁니다. 국내 원장에 실제로는 외국 소속인 사람이 섞여 있었다면 그 행도 한국이 되므로, 이관 후 목록에서 국가로 훑어 바로잡아야 합니다.
> 국가를 모르는 옛 글로벌 행은 국가가 비어 있고 지역만 해외로 남습니다. 그 건수는 이관 로그에 찍히며, 목록의 `국가 미확인` 축이 그 대기열입니다. 권역만 알던 행은 그 권역명을 `profile.legacy.region`에 남겨 나중에 국가를 채울 단서로 씁니다.

* **id를 보존합니다.** 다형 키가 가리키는 대상이 그대로여야 자료·피드백·회의록 링크·코드가 살아 있습니다.
* **`profile.category`(중복 라벨)는 더 이상 쓰지 않습니다.** 값은 `category` 컬럼이 승계하고 jsonb의 키는 걷습니다 — 같은 사실을 두 곳에 적으면 어긋나고, 어긋났을 때 어느 쪽이 정답인지 정할 근거가 없습니다.
* **쓰이지 않는 옛 스칼라**(`investor_type`·`representative`·`focus`·`biz_reg_no`·`industry`·`institution_type`·`university_type`·`department`·`region`·`memo`·`contact`·원장별 `category`)는 값이 있을 때만 `profile.legacy` 아래로 접어 넣습니다. 화면이 읽지 않는 항목이지만 원장에서 조용히 사라지게 두지 않습니다.
* **`vendors`(외주/거래)·`partners`는 은퇴 상태를 유지합니다.** 행은 통합 원장에 담겨 목록에 보이되, 구분 선택지·등록 선택지에는 서지 않습니다(모듈 카탈로그가 `is_active`로 하는 것과 같은 자세 — 새로 만들 수 없을 뿐 있는 것은 계속 보입니다).

## 6. 다형 키 정규화

원장 이름을 값으로 들고 있던 다형 키를 `networks` 계열 한 값으로 모읍니다.

| 대상 | 종전 값 | 통합 후 |
| :--- | :--- | :--- |
| `entity_contributions.entity_table` | `experts`·…·`global_networks` | `networks` |
| `entity_feedback.target_type` | `expert`·`investor`·`global_network`·… | `network` |
| `attachments.target_type`(자료) | 위와 동일 | `network` |
| `meeting_minute_links.target_type` | `expert`·…·`global_network` | `network` |
| `entity_codes.entity_table` | 원장명 | `networks` |
| `program_participants.master_table` | `experts` | `networks` + `category='experts'` 판정 |

* **옛 값을 남기고 매핑 함수로 우회하지 않습니다.** 매핑을 두면 조인마다 그 함수를 태워야 하고, 한 곳이라도 빠지면 목록에서 조용히 사라지는 행이 생깁니다.
* **`access_logs.resource_type`은 고치지 않습니다.** 감사 로그는 그때 무엇에 접근했는지의 기록이라 사후에 이름을 바꾸면 사실이 아닌 기록이 됩니다. 새 로그부터 새 값을 씁니다.
* **`meeting_minute_links`의 CHECK 목록과 `app.can_link_minute_target()`의 CASE**는 옛 값을 계속 받아들이되(이미 남아 있는 행이 있습니다) 새 값 `network`을 더합니다.

## 7. 구 원장 처리

* 옛 표 11종은 **드롭하지 않고 `_retired_*`로 개명**합니다. 이 환경은 `pg_dump`가 Docker를 요구해 백업을 뜰 수 없으므로, 되돌릴 수단 없이 지우지 않습니다(2026-09-03 구 모듈 원장과 같은 자세).
* 개명 후 PostgREST에 노출되더라도 RLS 정책은 종전 그대로라 접근 범위가 넓어지지 않습니다.
* **표 이름을 바꾸거나 지우는 마이그레이션은 그 이름으로 함수 본문을 전수 조사하는 것까지가 한 벌입니다.** `drop`·`alter ... rename`은 함수 본문(문자열 본문)을 의존성으로 추적하지 않아, 조회하던 함수가 살아남아 호출 순간 42P01로 죽습니다(2026-09-03 수습의 교훈).
* 통합 원장이 한 사이클 운영된 뒤 별도 마이그레이션으로 삭제하며, 그 항목은 PROGRESS 백로그가 답합니다.

## 8. 화면 재편

### 8.1 메뉴

다섯 줄이 세 줄이 됩니다. 지역은 메뉴가 아니라 **목록 필터 축**입니다.

| 메뉴 | 탭 | 범위 |
| :--- | :--- | :--- |
| 내 업로드 DB | `mine` | 생성자이거나 기여자인 건 |
| 전체 네트워크 | `all` | 볼 수 있는 전부(구분 미지정 포함) |

구분이 비어 있는 행은 메뉴가 아니라 **구분 필터의 `미지정`** 이 답합니다(§3.1). 옛 주소 `?tab=others`는 `전체 네트워크`로 바로잡습니다.

지역을 메뉴로 두면 그것이 '어디에 있는가'가 되어 구분·영역 같은 다른 축과 함께 걸 수 없습니다. 사이드바 재편(2026-08-20)이 구분에 대해 이미 밟은 길과 같습니다.

### 8.2 목록

* **열**: 이름·소속·직책/직급·이메일·연락처·링크드인·구분·**국가**·영역·활동·만족도·매칭.
* **국가 열 한 칸**이 지역을 답합니다 — 한국이면 `한국`, 해외면 그 국가명. 국가를 모르는 옛 행만 `국내`/`해외`로 물러섭니다. 권역까지 열로 세우면 국가와 같은 사실을 두 번 말하므로 권역은 필터 축으로만 둡니다.
* **필터**: 구분 · 지역(국내/해외/**국가 미확인**) · 권역 · 국가 · 영역 · 활동 · 매칭. 권역·국가 선택지는 지역이 해외를 포함할 때만 섭니다. `국가 미확인`은 별도 축이 아니라 같은 물음의 세 번째 답이라 지역 축 안에 둡니다.
* **권역 요약 카드**는 지역 필터가 해외일 때만 렌더합니다(국내 행에는 권역이 없어 비율이 뜻을 갖지 않습니다).

### 8.3 등록·상세·업로드

* **폼 한 벌**: 고르는 칸은 **구분과 국가 둘**입니다(국내/해외 라디오는 없습니다 — 국가가 답합니다). 구분 선택은 저장 대상 원장이 아니라 **한 컬럼의 값**이라, 구분을 바꿔도 행이 이동하지 않고 종전의 "구분 변경 = soft delete + insert"가 사라집니다.
* **상세 경로**: `/networks/record/:id`(등록은 `/networks/record/new?category=…`). 옛 경로 `/networks/:entity/:id`·`/networks/global/:id`는 id를 그대로 물려 새 경로로 리다이렉트합니다 — 이관이 id를 보존하므로 옛 링크가 죽지 않습니다.
* **업로드 한 벌**: 국내/글로벌 인페이지 탭을 걷고 CSV 양식에 `국가`·`링크드인` 열을 더합니다. 국가는 이름으로 올라와 태그 원장과 대조(대소문자·공백 무시)해 id로 바뀌며, **못 찾은 값은 행을 버리지 않고 '미확인'으로 남겨** 목록에서 채우게 합니다. 리뷰 표의 국가 열은 읽기 전용입니다 — 드롭다운을 하나 더 세우면 행마다 두 번 고르게 됩니다.

### 8.4 민감정보 정책

콘텐츠 키 12개(`networks.experts`·`networks.global` 등)를 실제 목록 셋(`networks.mine`·`networks.all`·`networks.others`)으로 줄입니다. **합칠 때는 가장 엄격한 값을 승계합니다** — 정책을 합치면서 느슨한 쪽을 택하면 그 축소가 곧 노출 확대입니다.

## 9. 하지 않는 것

* **구분 목록을 ADMIN 원장으로 옮기지 않습니다.** 구분은 아이콘·진입 경로·조직형/인물형 화면 분기를 함께 갖는 값이라, 화면 구현이 있어야만 성립합니다. 코드가 갖는 쪽이 맞습니다(모듈 템플릿에서 코드와 원장을 가른 기준과 같습니다).
* **스타트업(`startups`)을 합치지 않습니다.** 별도 워크스페이스가 소유하는 업무 원장이며 권한 판정 키부터 다릅니다.
* **익명 접근 정책을 만들지 않습니다.** 통합 원장에도 `anon` 정책은 없습니다.

## 10. 위험과 회귀 지점

* **사업 참가자 판정**: `program_participants.master_table='experts'`가 "전문가 원장"이라는 뜻이었는데, 통합 후에는 `networks` + `category='experts'` 조건이 됩니다. 문자열 하나가 두 조건이 되는 자리라 회귀가 실제로 날 지점입니다.
* **민감정보 정책 축소**: 위 8.4. 엄격한 쪽 승계를 지키지 않으면 조용히 열립니다.
* **기여 로그 갱신**: `entity_contributions`는 append-only 규약을 가진 표인데 이번 정규화는 그 표의 키 컬럼을 UPDATE합니다. 값의 뜻을 바꾸지 않고 이름만 옮기는 변경이며, 이 한 번 외에는 여전히 append-only입니다.
* **표 이름으로 함수 본문 전수 조사**: 위 7절.
* **되돌리기**: 옛 표가 `_retired_*`로 남아 있으므로 롤백은 "개명 되돌리기 + RPC·뷰를 옛 원장으로 되돌리기"입니다. 통합 이후 새로 들어온 행은 되돌아가지 않습니다.

## 11. 테스트 기준

* 사이드바 NETWORKS는 세 줄이며, 지역은 목록 필터로만 존재합니다.
* 해외 지역 + 구분 '대학'으로 등록·조회가 성립합니다(종전 구조에서 불가능했던 조합).
* 한국을 고른 레코드는 지역이 국내로, 다른 나라를 고른 레코드는 해외로 자동 판정됩니다(트리거).
* 등록 화면에서 국가를 비운 채로는 저장되지 않습니다.
* 국가 드롭다운은 `선택 → 한국 → 구분선 → 가나다순 국가`로 섭니다.
* 구분이 비어 있는 레코드에 구분을 지정해도 id가 바뀌지 않고, 그 레코드의 자료·피드백·회의록 링크가 그대로 남습니다.
* 구분 필터에서 `미지정`만 고르면 구분이 빈 행만, `투자사`와 함께 고르면 두 집합의 합이 나옵니다(AND가 아니라 OR).
* 구분이 비어 있는 행이 있는 CSV는 최종 업로드 버튼이 잠기고, 그 이유와 건수가 화면에 적힙니다.
* 옛 상세 링크(`/networks/experts/:id`·`/networks/global/:id`)가 같은 레코드로 열립니다.
* 통합 업로드 CSV의 `국가` 열이 태그 원장과 매칭되고, 못 찾은 값은 `null`(국가 미확인)로 남되 행이 버려지지 않습니다.
* NETWORKS 쓰기 권한이 없는 사용자는 화면과 무관하게 서버에서 쓰기가 거부됩니다.
