# 워크스페이스 예산·지출 구현 기준

* **사용자 확정(2026-09-13)**: PROJECT·M&A·FUND 상세에 공통 `예산/지출` 탭을 둡니다. 승인된 연결 품의가 없으면 빈 상태입니다. 여러 품의는 내부 품의별 탭으로 표시합니다.
* **연결**: 품의 하나는 워크스페이스 하나에 배정합니다. 워크스페이스에는 여러 품의를 연결할 수 있습니다. 지출결의 하나는 품의 하나를 참조하고 각 지출 항목은 품의의 예산 항목을 참조합니다.
* **승인 기준**: 배정·실제 지출·예산 변경은 최종 승인 시에만 반영합니다. 지출 상신은 항목 금액을 예약하고 회수·반려는 예약을 해제합니다. 최종 승인은 예약을 사용액으로 전환하며 승인 취소는 해당 사용액을 복원합니다. 재시도·동시 상신으로 이중 반영되면 안 됩니다.
* **초과**: 사용 가능액 = 현재 승인 예산 - 승인 지출액 - 진행 중 예약액입니다. 신규 지출결의 상신 시 항목별 초과를 차단합니다.
* **변경**: 현재 유효한 품의 예산과 지출·예약 현황을 기준으로 변경안을 작성합니다. 예상 잔액이 음수여도 상신과 최종 승인을 허용합니다. 예상 부족액을 결재자에게 표시합니다. 기존 진행 중 지출결의는 유지하며 결재자가 판단합니다. 이미 지출·예약에 사용된 항목의 참조와 이력을 유지합니다.
* **품의 취소**: 진행 중 또는 유효한 승인 지출결의가 있으면 차단합니다. 진행 중 문서를 먼저 회수·취소하고 승인 지출도 전부 취소되면 품의 승인 취소가 가능합니다. 최초 금액이 아닌 현재 유효한 배정 전체를 회수하며 변경·취소 이력은 보존합니다.
* **VAT 확정**: 항목마다 공급가액·VAT·합계액을 저장하며 모든 예산·예약·차감은 VAT 포함 합계액 기준입니다. VAT 없는 항목은 0원이며 과세·면세·영세율·과세대상 아님을 구분합니다. 자동 계산과 증빙에 따른 세액 수정을 지원하고 합계 일치 및 유효 금액을 서버에서도 검증합니다. 기존 금액을 임의로 10% 증액하거나 과세 유형을 추정하지 않습니다. 승인 취소는 당시 반영액을 그대로 복원합니다.
* **디자인 완료 조건**: 기존 공통 UI·색상·간격·타이포·밀도 규칙을 따릅니다. 많은 품의 탭, 긴 제목·항목 경로, 큰 금액·음수, 좁은 화면·모달에서 겹침·잘림·페이지 가로 넘침을 검사합니다. 필요한 가로 스크롤은 탭·표 영역 안에 제한하고 버튼과 선택 메뉴 접근을 보장합니다. 실제 브라우저 검증 여부를 구분합니다.

## 실행·검토

* **역할**: Claude CLI가 구현·테스트·문서를 작성하고 Codex가 diff와 직접 실행한 검증을 리뷰합니다. 기존 사용자 변경을 보존하며 커밋·푸시·배포·운영 DB 변경은 수행하지 않습니다.
* **토큰 절약**: 이 문서를 재사용해 구현 단위별 짧은 지시로 이어갑니다. 보고는 변경 파일·검증 결과·남은 문제만 간결히 작성합니다. 문맥이 차면 자동 압축을 사용하며 재개 지점·파일·미해결 사항을 남깁니다.
* **순서**: 기존 구조 조사 → 예산/VAT·상태 처리 → 공통 탭·결재 UI → 권한·동시성·오버플로우 검증 및 리뷰 수정입니다. 기존 구조를 우선 재사용합니다.
* **현재 상태**: 구현 및 Codex의 로컬 검증 완료(하단 최종 검증 참조). 운영 DB 적용·커밋·배포는 하지 않았습니다. 아래 중간 체크포인트의 미검증 표기는 당시 기록입니다.

## Codex 중간 리뷰 — 서버 초안 확인 사항

* **취소 기준**: `assert_no_active_budget_children`가 승인된 예산 변경까지 세어 품의 취소를 영구 차단하면 확정 정책과 다릅니다. 완료된 변경 이력은 유지하고, 유효 지출이 모두 정리되면 현재 배정을 취소할 수 있어야 합니다.
* **동시성**: 품의 취소와 지출 상신이 같은 품의 잠금을 공유해야 합니다. 문서 자체 저장·상신의 동시 호출도 기존 상태 확인부터 잠가야 합니다. 최신 함수 정의를 기준으로 수정하여 회차 처리 회귀를 막습니다.
* **검증 우회**: VAT 역할 열이 있는 새 양식에서 net/vat/kind를 모두 생략해도 옛 양식으로 오인하여 통과하지 않아야 합니다. 금액이 있는 지출 행의 예산 참조 누락도 집계에서 버리지 말고 거절해야 합니다.
* **전체 경로**: 신규 기안은 문서 INSERT → 상태 UPDATE 경로도 존재합니다. `save_approval_draft`와 재상신 RPC만 검사하면 최초 상신 및 직접 UPDATE가 우회할 수 있으므로 실제 생성·상신 경로를 모두 확인합니다.
* **순서**: CLI 생성 마이그레이션이 당일 미래 시각의 기존 마이그레이션보다 앞섭니다. 전체 재생에서 후속 정의에 덮이지 않는지 확인하고 필요한 경우 생성된 파일을 미적용 신규 파일에 한해 마지막 순서로 정렬합니다.
