# GUEST 계정·원장 식별 정책 확정안

> 확정일: 2026-09-12  
> 이 문서는 기존 `3_9_1`, `3_9_2` 문서 중 계정 생성 위치와 원장 중복 정책에 관한 내용을 대체한다.

## 1. 핵심 원칙

- `users`의 GUEST 계정은 사람의 로그인 신원이며, `guest_identities`는 그 사람이 어떤 원장 레코드와 연결되는지를 표현한다.
- 사업 참여는 계속 기업·당사자 단위로 관리하고, 로그인하는 사람은 별도 계정으로 여러 기업·원장·사업에 재사용할 수 있다.
- 스타트업 대표자를 GUEST로 만들기 위해 NETWORKS 원장에 같은 사람을 다시 만들지 않는다.
- GUEST 계정 정지와 개별 사업 접근 차단은 별개의 상태다. 계정 정지는 전체 로그인을 막고, 사업 차단은 해당 사업만 닫는다.

## 2. 통합 GUEST 화면과 M&A 보안

- 내부 관리 화면은 워크스페이스별 복제 페이지 대신 URL `/guest-accounts`의 통합 원장 하나를
  사용한다. 메인 워크스페이스 스위처에는 두지 않고 외부 참여자를 운영하는 **사업부·M&A팀·
  투자실** 사이드바 하단에서 같은 URL을 연다.
- 일반 내부 사용자는 계정을 생성·조회한다. ADMIN 쓰기 권한이 있는 사용자만 목록 체크박스로
  여러 계정을 선택해 일괄 정지·해제·영구 삭제할 수 있으며, 행별 관리 버튼은 두지 않는다.
- 일괄 변경은 서버의 한 트랜잭션에서 실행한다. 영구 삭제 중 한 계정이라도 필수 업무 참조로
  막히면 선택 전체를 롤백하며, 업무 기록의 nullable 사용자 참조는 익명화한다.
- M&A 읽기 권한이 없는 사용자는 M&A에만 연결된 계정 자체를 볼 수 없다.
- 일반 사업과 M&A에 함께 연결된 계정은 볼 수 있지만, 그 사용자가 읽을 수 없는 M&A 연결·사업 정보는 응답에서 제외한다.
- 이 필터는 화면 숨김이 아니라 `guest_accounts_list`와 원장 RLS에서 강제한다.

## 3. 계정 우선 생성

1. GUEST 계정 생성은 **직접 생성**이 기본이다. 이름·이메일·전화번호만 입력하며 원장은 만들거나
   연결하지 않는다.
2. 원장 연결이 필요할 때만 **원장에서 찾기**로 바꾼다. `원장 연결`과 선택한 `스타트업/전문가/
   SELLER/BUYER 원장`을 두 열로 보여 주며, 대상은 드롭다운이 아니라 입력 검색 + 돋보기가 여는
   공용 원장 검색 모달에서 고른다.
3. 같은 이메일의 기존 GUEST 계정이 있으면 이름이 같을 때 그 계정을 재사용하고, 없으면 새로
   만든다. 이름이 다르면 다른 사람이 같은 계정으로 합쳐지지 않도록 거부한다.
4. 원장에서 고른 경우에만 원장 레코드와 사람 계정을 `guest_identities`로 연결한다.
5. 각 워크스페이스의 참가자 생성도 직접 `users`를 만들지 않고 같은 중앙
   `create_guest_account` 경로를 호출한 뒤 반환된 계정을 사업 참여 줄에 연결한다.

원장의 대표자·연락처는 `원장값 불러오기`를 선택했을 때만 입력 편의를 위해 복사한다. 원장 연락처가 바뀌어도 이미 생성된 로그인 계정의 이메일·초기 비밀번호는 바뀌지 않는다. 초기 비밀번호는 계정 생성 시 확정한 전화번호의 숫자값이다.

## 4. 원장별 중복 규칙

### 스타트업·매도자 명단·매수자 명단

같은 원장 안의 활성·미병합 레코드끼리는 다음 값 중 하나라도 같으면 생성과 수정을 모두 차단한다.

- 사업자등록번호: 숫자만 비교
- 이메일: 앞뒤 공백 제거 후 소문자로 비교
- 전화번호: 숫자만 비교

빈 값은 중복으로 보지 않는다. 화면 사전검사와 DB 유니크 인덱스를 함께 사용하며, 대용량 업로드에도 같은 판정을 적용한다.

### NETWORKS DB

- 이메일이나 전화번호 한 항목만 같다는 이유로 자동 차단하거나 자동 병합하지 않는다.
- 이름·이메일·전화번호 중 두 항목 이상이 일치할 때만 기존 인물 후보로 본다.
- 연락처 변경 시 이전 이메일·전화번호를 `profile.contact_history`에 남긴다.
- 대용량 업로드는 `합치기(빈칸 보강)`, `합치기(연락처 갱신)`, `미업로드`를 명시적으로 고른다.
- 한 업로드 행이 여러 기존 인물과 동시에 충돌하면 자동 병합하지 않고 미업로드 처리한다.

## 5. 배포 전 데이터 감사

유니크 인덱스 적용 전에 활성·미병합 데이터의 정규화 중복을 조회한다. 충돌이 있으면 이름만 보고 합치지 않고 담당자가 정본을 확정한 뒤 병합한다. 2026-09-12 로컬 데이터 감사에서는 새 제약 대상 8개 기준 모두 중복 그룹이 0건이었다.

## 6. 검증 기준

- M&A 권한 없는 내부 사용자는 M&A 전용 계정을 조회할 수 없다.
- M&A와 일반 사업을 함께 가진 계정에서는 허용된 일반 연결만 보인다.
- 같은 이메일은 동일한 GUEST 계정으로 재사용되며, 다른 전화번호의 새 계정은 만들 수 없다.
- 스타트업·매도자·매수자는 사업자등록번호·이메일·전화번호 단일 중복을 각각 차단한다.
- NETWORKS 연락처 교체는 이력을 남기고 GUEST 로그인값을 바꾸지 않는다.
- 대용량 업로드의 연락처 보강과 명시적 교체가 구분되며 다중 후보 충돌은 자동 병합되지 않는다.
