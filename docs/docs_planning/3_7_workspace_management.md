# [3-7] MANAGEMENT (경영지원) 워크스페이스 상세 기능 요건서

본 문서는 조직·임직원·지사·자산·예산·KPI 등 전사 내부 자원의 원장을 관리하는 MANAGEMENT 워크스페이스의 현재 화면과 후속 범위를 정의합니다.

> [!IMPORTANT]
> 전자결재의 사용 화면은 OFFICE로 이관되었습니다. MANAGEMENT는 승인 완료 문서의 금액을 재무 집계에서 읽을 뿐, 사이드바에 전자결재 메뉴를 두지 않습니다.

## 1. 현재 메뉴와 구현 상태

| 메뉴 | 탭/경로 | 상태 |
| :--- | :--- | :---: |
| 경영 현황 | `dashboard` | 준비 중 골격 |
| 조직 관리 | `departments` | 사용 가능 |
| 조직 개편 | `/management/org-reform` | 사용 가능 |
| 지사 관리 | `branches` | 사용 가능 |
| 인사 관리 | `hr` | 사용 가능 |
| 계정 생성/임직원 상세 | `/management/hr/new`, `/management/hr/:id` | 사용 가능 |
| 자산 관리 | `assets` | 사용 가능 |
| 재무 관리 | `finance` | 부분 구현 |
| KPI 관리 | `kpi` | 부분 구현 |

탭이 없으면 `경영 현황`을 열며 현재는 `대시보드는 준비 중입니다` 안내만 표시합니다.

> [!NOTE]
> 직책·직급·호봉 태그 관리는 2026-08-03부터 ADMIN `태그 관리` 그룹이 소유합니다([3_2_workspace_admin.md](./3_2_workspace_admin.md) §1.4). 세 원장 모두 쓰기 정책이 `app.is_admin()`이라 MANAGEMENT에서는 열람만 가능했습니다. 임직원 등록·수정 화면의 직책·직급·호봉 선택은 그대로이며, 선택지 원장을 고치는 자리만 옮겼습니다.

## 2. 조직 관리

### 2.1 조직 버전 조회

* 조직 버전을 선택해 해당 시점의 조직 트리와 소속 임직원을 조회합니다.
* 이름·직급/직책·소속으로 검색하며 임직원 카드를 누르면 MANAGEMENT 상세로 이동합니다.
* 현재 발효 버전과 과거 버전을 구분하고, 설계 중인 개편 초안이 있으면 이어서 설계할 수 있는 배너를 노출합니다.

### 2.2 직접 편집

현재 선택한 조직 버전을 그대로 고칠 때 사용합니다.

* 조직 추가·이름/상위 관계 변경·삭제, 임직원 배치를 한 편집 세션에서 수행합니다.
* 조직 레벨 정의와 삭제된 조직 복원은 별도 모달로 엽니다.
* 저장 전까지 로컬 초안으로 유지하며 취소 시 변경을 폐기합니다.

### 2.3 조직 개편

조직 구조 변경 이력을 새 버전으로 남겨야 할 때 `/management/org-reform`을 사용합니다.

* 초안(`DRAFT`)은 서버에 보존되어 페이지를 나갔다 돌아와도 이어서 편집합니다.
* 기준 버전 복제, 발효일, 조직 구조와 인력 배치를 함께 설계합니다.
* 직접 편집과 조직 개편은 목적이 다릅니다. 현 버전 정정은 직접 편집, 새 시점의 구조 전환은 조직 개편을 사용합니다.

## 3. 지사와 인사 기준정보

### 3.1 지사 관리

지사명·주소·전화번호·상주 인력을 등록·수정합니다. 이 원장은 OFFICE 지사 정보와 회의실 예약의 지사 선택에서 읽기 전용으로 재사용합니다.

### 3.2 직책·직급·호봉

세 기준정보는 MANAGEMENT 소유 태그 원장입니다.

* 사이드바의 각 메뉴에서 공용 태그 관리 패널을 사용합니다.
* 임직원 폼과 상세는 코드에 고정 목록을 두지 않고 이 태그 원장의 활성값을 선택·표시합니다.
* 직급과 직책은 화면의 호칭 조합 규칙에 사용하고, 호봉은 인사 관리에서만 노출합니다.

## 4. 인사 관리

### 4.1 임직원 목록

* 페이지 헤더에서 이름을 검색하고 `크게보기`로 전체화면 조직/임직원 목록을 엽니다.
* `계정 생성`은 `/management/hr/new`의 페이지형 폼으로 이동합니다.
* 행 클릭은 `/management/hr/:id` 상세로 이동합니다.

### 4.2 계정 생성·상세

* 이름·이메일·연락처·역할·회사·부서·직급·직책·호봉·입사일 등 계정/인사 정보를 관리합니다.
* 부서 선택지는 현재 조직도에서 만들며 상위·하위 경로 라벨을 동일 규칙으로 표시합니다.
* 사진·약력·관심 산업·철학·관심사·한 줄 소개와 자료 패널을 공용 프로필 부품으로 관리합니다.
* OFFICE `/office/managers/:id`는 같은 상세를 읽기 전용으로 재사용하고 호봉을 숨깁니다.

### 4.3 내 계정 관리

`/me`는 워크스페이스 권한과 무관하게 모든 인증 사용자가 접근합니다.

* 본인은 사진·약력·철학·관심사·한 줄 소개·자료만 편집할 수 있습니다.
* 이름·역할·부서·이메일·연락처·입사일 등 계정 필드는 조회만 하며 변경은 인사 관리에 요청합니다.
* 허용 범위는 UI 숨김이 아니라 전용 RPC/RLS로 강제합니다.

## 5. 자산 관리

자산 세부 요건의 정본은 [3_7_2_management_assets.md](./3_7_2_management_assets.md)입니다.

* 지사 귀속 자산을 등록·수정하고 품목·시리얼 번호·상태·수량·할당 대상·자산 관리자·비용/결제 주기·구독 기간·사진을 관리합니다.
* 자산명·품목·시리얼 번호 검색, 복수 필터, 페이지네이션, 다중 선택, 대량 업로드를 제공합니다.
* `반출 가능` 설정은 OFFICE 반출대장 노출 여부를 결정합니다.
* 자산에는 `created_by`가 없으므로 생성자 열을 표시하지 않습니다. 관리 축은 할당 대상과 자산 관리자이며 둘은 별개입니다.

## 6. 재무 관리

현재 화면은 2026년 부서/전사 예산과 승인 완료 전자결재의 금액을 비교한 표입니다.

* 열: 부서, 예산, 실지출, 상태.
* 실지출이 예산을 넘으면 `예산 초과`, 그 외는 `정상` 배지로 표시합니다.
* 승인 문서의 부서별 귀속 정밀 집계, 예산 등록/수정, 연도 선택, 회계 원장은 후속입니다.

## 7. KPI 관리

현재 화면은 KPI 원장의 지표명·기간·실적/목표·달성률을 조회합니다.

* 달성률 100% 이상은 성공, 70~99%는 경고, 그 미만은 중립 배지로 표시합니다.
* 템플릿·할당·검증·평가·등급·인센티브를 포함한 전체 성과 사이클은 [3_7_1_management_performance_kpi.md](./3_7_1_management_performance_kpi.md)의 목표 기획입니다.

## 8. 원장 소유와 연동

| 원장/기능 | MANAGEMENT 역할 | 소비 화면 |
| :--- | :--- | :--- |
| 임직원·조직 버전 | 생성·수정 정본 | OFFICE 임직원 조회, 전 워크스페이스 사람/부서 피커 |
| 지사 | 생성·수정 정본 | OFFICE 지사 정보·회의실 예약 |
| 직책·직급·호봉 | 기준정보 정본 | 인사 폼·상세·마이페이지 호칭 |
| 자산 | 생성·수정 정본 | OFFICE 반출대장 |
| 예산 | 집계 정본 | MANAGEMENT 재무 |
| 승인 결재 | 읽기/집계 | OFFICE가 업무 화면 소유 |
| KPI | 실적/목표 조회 | MANAGEMENT KPI |

## 9. 권한·보안 원칙

* MANAGEMENT 라우트는 `RequireWorkspace workspace="management"`를 통과해야 합니다.
* 조직·계정·급여성 기준정보·자산 비용은 MANAGEMENT 쓰기 권한과 각 RPC/RLS를 통과해야 변경됩니다.
* OFFICE 재사용 화면은 조회 전용이며 수정 버튼을 숨기는 것과 별개로 서버 쓰기 정책을 부여하지 않습니다.
* 비활성화는 물리 삭제가 아니라 소프트 삭제를 사용하고 조직 개편/자산 변경 이력을 보존합니다.

## 10. 테스트 기준

* 조직 버전을 바꾸면 해당 버전의 조직·임직원만 표시되고 검색 결과도 같은 버전에 한정됩니다.
* 직접 편집 취소 시 서버 원장이 바뀌지 않으며, 조직 개편 초안은 다시 진입해 이어서 편집됩니다.
* MANAGEMENT에서 수정한 지사·임직원 정보가 OFFICE 읽기 화면에 반영됩니다.
* 자산의 반출 가능 설정에 따라 OFFICE 반출대장 후보가 달라집니다.
* `/me`에서 계정/조직 필드를 직접 바꾸려는 요청은 서버에서 거부됩니다.
* 경영 현황 골격과 KPI 목표 기획을 구현 완료로 표시하지 않습니다.
